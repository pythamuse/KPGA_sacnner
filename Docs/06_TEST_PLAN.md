# TEST_PLAN — 테스트 계획

## 1. 테스트 범위

테스트는 다음 5개 영역으로 나눈다.

1. 데이터 정규화 테스트
2. 데이터 검증 테스트
3. 엑셀 쓰기 테스트
4. 이미지 인식 결과 처리 테스트
5. 통합 다운로드 테스트

## 4. 엑셀 쓰기 테스트

### 4.1 단일 학생 저장

입력:

```json
{
  "basic": { "age": 14, "gender": "여", "schoolType": "중학교", "grade": "2학년" },
  "cagi": { "q01": 0, "q02": 0, "q03": 0, "q04": 0, "q05": 0, "q06": 0, "q07": 0, "q08": 0, "q09": 0 },
  "satisfaction": { "q01": 4, "q02": 1, "q03": 1, "q04": 1, "q05": 1, "q06": 1, "q07": 4, "q08": 4, "q09": 4, "q10": 4 }
}
```

기대 결과:

CAGI:

```text
A3=14, B3=여, C3=중학교, D3=2학년, E3:M3=0
```

만족도:

```text
A3=14, B3=여, C3=중학교, D3=2학년, E3:N3=4,1,1,1,1,1,4,4,4,4
```

### 4.2 다중 학생 저장

학생 10명을 저장하면 다음을 검증한다.

| 검증 | 기대 결과 |
|---|---|
| CAGI 입력 행 | 3~12행 |
| 만족도 입력 행 | 3~12행 |
| 두 파일 행 수 | 동일 |
| 13행 | 비어 있음 |

### 4.3 실패 트랜잭션

케이스:

- CAGI는 정상
- 만족도 q02=4로 오류

기대 결과:

- CAGI 파일에도 저장하지 않음
- 만족도 파일에도 저장하지 않음
- 사용자에게 오류 메시지 표시

## 6. 이미지 인식 테스트

### 6.1 예시 이미지 고정 테스트

입력 이미지:

1. 선별검사지 예시 이미지
2. 만족도 예시 이미지

기대값:

```json
{
  "basic": { "age": 14, "gender": "여", "schoolType": "중학교", "grade": "2학년" },
  "cagi": [0,0,0,0,0,0,0,0,0],
  "satisfaction": [4,1,1,1,1,1,4,4,4,4]
}
```

### 6.2 이미지 뒤바뀜 테스트

| 업로드 위치 | 이미지 | 기대 결과 |
|---|---|---|
| CAGI 칸 | 만족도 이미지 | 양식 불일치 오류 |
| 만족도 칸 | CAGI 이미지 | 양식 불일치 오류 |

### 6.2.1 CAGI 조기개입 서비스 표기 테스트

| 케이스 | 기대 결과 |
|---|---|
| 선별검사지 하단 조기개입 서비스에 표기 흔적이 있음 | 오류 없이 검수 화면으로 진행 |
| 조기개입 서비스에 표기 후 삭제 흔적이 있음 | 오류 없이 검수 화면으로 진행 |
| 조기개입 서비스 표기 흔적이 있는 선별검사지가 만족도조사로 오판될 수 있는 이미지 | `FORM_TYPE_MISMATCH`로 막지 않고 선별검사지로 유지 |
| 위 케이스에서 인식 완료 | `선별검사지 N페이지` 조기개입 노티스 표시 |
| 위 케이스에서 저장 | 조기개입 서비스 값은 저장하지 않고 CAGI 문항 1~9만 저장 |
| 실제 만족도조사를 CAGI 칸에 업로드 | 기존처럼 `FORM_TYPE_MISMATCH` 반환 |

### 6.3 품질 저하 테스트

| 상황 | 기대 결과 |
|---|---|
| 흐림 | 낮은 신뢰도 또는 재촬영 요청 |
| 종이 일부 잘림 | 재촬영 요청 |
| 심한 그림자 | 재촬영 요청 |
| 기울어짐 | 보정 시도, 실패 시 재촬영 요청 |

### 6.3.1 경계 검출 불확실성 및 OCR 보조 경로

| 케이스 | 기대 결과 |
|---|---|
| 외곽 프레임이 충분히 검출되지 않는 CAGI 이미지 | 후보 점수만 표시하고 CAGI 자동값은 확정하지 않음 |
| 외곽 프레임이 충분히 검출되지 않는 만족도 이미지 | 후보 점수만 표시하고 만족도 자동값은 확정하지 않음 |
| 위 입력에서 인식 완료 | 검수 화면에 원본 대조 안내가 표시됨 |
| 픽셀 기반 문항 행 매칭 성공 | OCR을 호출하지 않고 픽셀 결과 사용 |
| 픽셀 기반 문항 행 매칭 실패 | OCR을 최대 2.5초 보조 경로로 시도하고 실패 시 기존 ROI로 폴백 |
| 조기개입 ROI를 포함하지만 경계가 불확실함 | 조기개입 노티스를 임의로 생성하지 않음 |

## 7. 사용자 수정 테스트

| 케이스 | 기대 결과 |
|---|---|
| OCR이 성별을 남으로 인식했으나 사용자가 여로 수정 | 엑셀에는 여 저장 |

| 사용자가 허용값 밖의 값 입력 시도 | 입력 차단 |

## 10. Vercel 배포본 업로드 안정성 테스트

로컬 서버에서는 재현되지 않고 Vercel 배포본에서만 발생할 수 있는 항목을 별도로 확인한다.

### 10.1 작업 세션 복구

| 케이스 | 기대 결과 |
|---|---|
| 새 작업 생성 직후 선별검사지 PDF 업로드 | `/api/upload`가 404/500 세션 오류 없이 성공 |
| Vercel 콜드 스타트처럼 메모리 세션이 없는 상태에서 유효한 `job_숫자` 업로드 | `/api/upload`가 작업공간과 `session.json`을 복구하고 성공 |
| 선별검사지 업로드 후 만족도조사 PDF 업로드 | 같은 jobId의 uploads 폴더에 누적 |
| 업로드 완료 후 인식 실행 | `/api/recognize`가 같은 jobId를 인식 |
| 검수 저장 후 다운로드 | `/api/download`가 같은 jobId의 엑셀 파일 반환 |

주의:

- Vercel Serverless에서는 인메모리 `Map`만으로 세션을 유지하면 안 된다.
- 세션 관련 API는 `getJobSession()` 또는 `hasJobSession()`의 파일 기반 복구 경로를 사용해야 한다.

### 10.2 PDF 업로드 용량

| 케이스 | 기대 결과 |
|---|---|
| 선별검사지 다페이지 PDF 업로드 | 모든 페이지가 JPEG로 변환되어 끝까지 업로드 |
| 만족도조사 다페이지 PDF 업로드 | 모든 페이지가 JPEG로 변환되어 끝까지 업로드 |
| 업로드 중 실패 | alert 메시지와 Network의 `/api/upload` status code를 기록 |

실패 분석 기준:

- `413`: 변환 이미지 용량 문제. PDF 변환 scale/quality를 더 낮춘다.
- `404`: job session 복구 문제. `session.json` 생성/복구 경로를 확인한다.
- `500`: 서버 로그에서 `req.formData()`, 임시파일 쓰기, Vercel 함수 제한 여부를 확인한다.
