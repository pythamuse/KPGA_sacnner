# PRD — 도박예방교육 선별검사지·만족도조사 엑셀 자동작성 웹앱

## 1. 제품 개요

본 웹앱은 도박예방교육 강사가 교육 후 수집하는 종이 응답지 2종을 사진으로 업로드하면, 이미지에서 필요한 응답값을 추출하고 중앙 시스템 업로드용 엑셀 템플릿 2개에 학생별 행 단위로 자동 입력하는 도구이다.

대상 응답지는 다음 2종이다.

1. 도박문제 선별검사지 CAGI 아동·청소년
2. 예방교육 후 만족 및 평가 설문 아동·청소년

최종 산출물은 다음 2개 엑셀 파일이다.

1. `양식_청소년도박문제선별검사_CAGI_3.xlsx`
2. `청소년예방교육만족도.xlsx`

앱 내부에서는 학생 1명을 하나의 데이터 세트로 관리한다. 학생 1명 데이터는 선별검사지 이미지 1장과 만족도 설문 이미지 1장으로 구성된다.

---

## 2. 문제 정의

현재 강사는 학생별 응답지를 확인한 뒤 중앙 시스템 업로드용 엑셀에 값을 직접 입력해야 한다. 이 과정에서 다음 문제가 발생한다.

| 문제 | 설명 |
|---|---|
| 반복 입력 부담 | 학생 수만큼 응답값을 수작업으로 입력해야 함 |
| 단순 오타 발생 | 성별, 학년, 문항 점수 등에서 잘못된 값 입력 가능 |
| 업로드 실패 | 중앙 시스템이 엑셀 데이터 규칙을 엄격하게 검사할 경우 업로드 불가 |
| 오류 탐색 비용 | 어느 셀의 값이 문제인지 찾는 데 시간이 오래 걸림 |
| 양식별 중복 입력 | 만족도 파일의 기본정보 A~D열은 선별검사지와 동일하지만 다시 입력해야 함 |

## 3. 목표

### 3.1 1차 목표

- 학생별 응답지 사진 2장을 업로드해 CAGI 파일과 만족도 파일을 자동 작성한다.
- 엑셀 입력 전 앱 내부에서 허용값 검증을 수행한다.
- 검증 실패 시 엑셀에 저장하지 않고 사용자에게 수정 또는 재업로드를 요구한다.
- 최종 다운로드 시 중앙 시스템 업로드용 원본 템플릿 구조와 데이터 유효성 규칙을 최대한 보존한다.

### 3.2 비목표

1차 MVP에서는 다음 기능을 제외한다.

| 제외 기능 | 제외 사유 |
|---|---|
| 중앙 시스템 자동 로그인 및 자동 업로드 | 보안·인증·정책 리스크가 큼 |
| 여러 학생 응답지 일괄 자동 매칭 | 앞면·뒷면 매칭 오류 가능성이 높음 |
| 개인정보 동의서 영역 자동 입력 | 현재 엑셀 템플릿에 입력 대상 컬럼 없음 |
| 이름·전화번호 저장 | 현재 중앙 시스템 업로드용 템플릿에 해당 컬럼 없음 |
| 모바일 네이티브 앱 | 웹앱으로 우선 구현 가능 |

## 4. 핵심 사용자 흐름

### 4.1 새 작업 생성

1. 사용자가 `[새로 작성]` 버튼을 누른다.
2. 서버에 저장된 원본 템플릿 2개를 작업 세션용 파일로 복사한다.
3. 작업 세션은 아직 학생 데이터가 없는 상태로 시작한다.

### 4.2 학생 1명 추가

1. 사용자가 선별검사지 이미지를 업로드한다.
2. 사용자가 만족 및 평가설문 이미지를 업로드한다.
3. 시스템이 이미지에서 값을 추출한다.
4. 시스템이 추출값을 내부 학생 데이터로 정규화한다.
5. 시스템이 앱 내부 검증을 수행한다.
6. 사용자가 인식 결과 확인 화면에서 값을 검수한다.
7. 사용자가 `[저장]`을 누르면 CAGI 파일과 만족도 파일의 같은 행 번호에 동시에 값이 입력된다.

### 4.3 완료 및 다운로드

1. 사용자가 `[완료 및 다운로드]` 버튼을 누른다.
2. 시스템이 전체 학생 데이터에 대해 최종 검증을 수행한다.
3. 검증 통과 시 CAGI 파일과 만족도 파일을 다운로드할 수 있게 한다.
4. 검증 실패 시 오류가 있는 학생·항목을 표시하고 다운로드를 제한한다.

## 5. 입력 이미지별 추출 대상

### 5.1 선별검사지 이미지에서 추출할 값

선별검사지 이미지에서는 다음 값을 추출한다.

| 구분 | 항목 | 엑셀 반영 |
|---|---|---|
| 기본정보 | 연령대 | CAGI A열, 만족도 A열 |
| 기본정보 | 성별 | CAGI B열, 만족도 B열 |
| 기본정보 | 학교유형 | CAGI C열, 만족도 C열 |
| 기본정보 | 학년 | CAGI D열, 만족도 D열 |
| CAGI 응답 | CAGI 01~09 | CAGI E~M열 |

선별검사지 이미지에는 실시일자, 정보수집일, 이름, 연락처, 개인정보 동의, 상담서비스 신청 항목 등이 있지만 현재 엑셀 템플릿에는 해당 입력 컬럼이 없다. 따라서 MVP에서는 추출 대상에서 제외한다.

### 5.2 만족 및 평가설문 이미지에서 추출할 값

만족도 이미지에서는 다음 값만 추출한다.

| 구분 | 항목 | 엑셀 반영 |
|---|---|---|
| 만족도 응답 | 문항1~문항10 | 만족도 E~N열 |

중요: 만족도 엑셀의 A~D열은 만족도 이미지에서 추출하지 않는다. 반드시 선별검사지 이미지에서 추출한 연령대, 성별, 학교유형, 학년을 복사한다.

## 8. 사용자 확인 화면 요구사항

OCR 및 체크마크 인식 결과는 반드시 사용자 확인 화면을 거쳐야 한다.

### 8.1 화면 구성

학생 1명 데이터 확인 화면은 다음 섹션으로 구성한다.

1. 기본정보
2. CAGI 01~09 응답
3. 만족도 문항1~10 응답
4. 오류·경고 목록
5. 저장 버튼
6. 재업로드 버튼

### 8.2 필드별 표시 요소

각 필드는 다음 정보를 표시한다.

| 표시 요소 | 설명 |
|---|---|
| 항목명 | 예: 성별, CAGI 01, 만족도 문항7 |
| 인식값 | 시스템이 추출한 값 |
| 신뢰도 | high, medium, low |
| 원본 이미지 영역 | 가능하면 해당 체크 영역 크롭 이미지 |
| 수정 입력 | 드롭다운 또는 라디오 버튼 |
| 검증 상태 | 정상, 확인 필요, 오류 |

### 8.3 저장 조건

다음 조건을 모두 만족해야 저장 가능하다.

1. 필수값이 모두 존재한다.
2. 모든 값이 앱 내부 허용값을 통과한다.
3. CAGI 이미지와 만족도 이미지가 모두 업로드되어 있다.
4. 사용자가 인식 결과를 확인했다.

## 9. 오류 처리 요구사항

| 오류 유형 | 예시 | 처리 |
|---|---|---|
| 이미지 누락 | 선별검사지 없이 만족도만 업로드 | 저장 불가, 누락 이미지 요청 |
| 양식 오인식 | 만족도 칸에 선별검사지 업로드 | 업로드 거부 또는 사용자 확인 요청 |
| 필수값 누락 | 성별 미인식 | 저장 불가, 수정 또는 재업로드 요청 |
| 다중 체크 | 한 문항에 2개 이상 체크 | 저장 불가, 사용자 선택 요구 |
| 응답값 범위 오류 | 만족도 문항2에 4 인식 | 저장 불가, 수정 요구 |
| 기본정보 불일치 | 동일 학생 세트 내 내부값 충돌 | 선별검사지 기본정보 우선 사용 |
| 엑셀 저장 실패 | 템플릿 손상 또는 파일 잠김 | 저장 중단, 원본 템플릿으로 복구 |

## 10. 개인정보·보안 요구사항

| 요구사항 | 설명 |
|---|---|
| 이미지 임시 저장 | 업로드 이미지는 처리 후 일정 시간 내 삭제 |
| 개인정보 로그 금지 | 이름, 연락처, 검사 결과를 서버 로그에 남기지 않음 |
| HTTPS 필수 | 이미지 업로드 및 다운로드 구간 암호화 |
| 세션 격리 | 사용자별 작업 파일이 섞이지 않도록 처리 |
| 파일 만료 | 작업 세션 파일은 일정 시간 후 자동 삭제 |
| 원본 이미지 다운로드 제한 | 처리 후 원본 이미지 노출 최소화 |

MVP에서는 회원가입 없이 단일 사용자용으로 구현할 수 있으나, 배포 환경에서는 최소한 세션 단위 격리가 필요하다.

## 10-1. 자동 입력률 요구사항 (제품 성립 조건)

**검수자가 대부분의 칸을 직접 입력해야 한다면 이 도구는 존재 이유가 없다.** 강사가 엑셀에 손으로 넣는 것과 다를 바가 없기 때문이다. 따라서 자동 입력률은 "있으면 좋은 지표"가 아니라 **제품이 실무에 투입될 수 있는지를 가르는 조건**이다.

### 10-1.1 기준

| # | 기준 | 값 |
|---|---|---|
| **A1** | 학생 1명당 자동 입력되는 항목 비율 | **23개 중 20개 이상 (87%)** |
| **A2** | 자동 입력된 값 중 오답 | **0건. 예외 없음** |
| **A3** | 검수자가 손대야 하는 항목 | 학생 1명당 **평균 3개 이하** |

A2는 A1보다 우선한다. 빈칸은 검수자의 키 입력 한 번이지만, 오답은 사람이 확인한 것처럼 중앙 시스템에 저장된다. **자동 입력률을 올리기 위해 오답을 감수하는 교환은 금지한다.**

### 10-1.2 판정 방법

`tests/real-scan-measure.test.ts`가 배포본과 동일한 래스터로 실제 스캔을 측정한 `CORRECT / WRONG / BLANK`로만 판정한다. 검수 화면에서 사용자가 수정한 값은 자동 인식의 근거가 아니다.

- **A1 환산**: 6페이지 표본 기준 `CORRECT ≥ 118/135`
- **A2 환산**: `WRONG = 0`

### 10-1.3 현재 상태와 남은 거리

| 시점 | CORRECT | 자동 입력률 | WRONG (A2) | 검수자 몫/학생 (A3) | A1까지 |

| 2026-08-19 계측기 기준선 (6쪽) | 92/135 | 68% | — | — | −26칸 |
| 2026-08-28 노드, 스캔 세트 1 (19명) | 355/432 | 82% | **7** | 3.9 | −21칸 |
| 2026-08-24 브라우저, 같은 세트 | 302/437 | 69% | **10** | 7.1 | −78칸 |

## 10-2. 작업 연속성 요구사항

강사는 한 번에 19명 안팎을 검수한다. 중간에 검수를 취소하거나 브라우저가 새로고침되면 그때까지의 검수 결과가 사라져 처음부터 다시 업로드·인식해야 한다. **잘못 누르거나 작업이 끊겨도 원래 작업으로 돌아올 수 있어야 한다.**

### 10-2.1 요구사항

| # | 요구사항 | 이유 |
|---|---|---|
| C1 | `검수 취소`를 눌러도 직전 검수 상태로 **되돌릴 수 있어야** 한다 | 오조작이 19명분 작업을 날리면 안 된다 |
| C2 | 새로고침·네트워크 끊김·탭 종료 뒤에도 **저장 완료된 학생 목록과 검수 중이던 값**이 남아 있어야 한다 | 인식은 몇 분이 걸리고, 수기 수정한 값은 재현할 수 없다 |
| C3 | 복구는 **사용자가 명시적으로 선택**해야 한다. 자동으로 이전 작업을 이어받지 않는다 | 다른 학급을 새로 시작하려는 경우와 구분해야 한다 |
| C4 | `새로 작성`을 시작하면 이전 복구 지점을 **삭제**한다 | 이전 학급 데이터가 새 작업에 섞이면 안 된다 |
| C5 | 복구 데이터에 **원본 이미지를 저장하지 않는다** | 개인정보 보관 최소화(§10) 및 용량 |

### 10-2.2 저장 범위 — 실측 근거

학생 1명 기준 측정값이다.

| 대상 | 용량 | 판정 |
|---|---:|---|
| 인식 결과 전체(썸네일·crop 이미지 포함) | 1,602KB | 19명이면 30MB — 브라우저 저장 한도 초과 |
| **값 + 신뢰도 + 진단만(이미지 제외)** | **3KB** | 19명이면 61KB — 저장 가능 |

따라서 **이미지는 저장하지 않고 값만 저장한다.** 이는 C5와도 일치한다.

### 10-2.3 두 층으로 나눈 복구

두 실패 방식은 성격이 다르므로 대응도 나눈다.

| 실패 | 복구 층 | 보존 범위 |
|---|---|---|
| `검수 취소` 오조작 (페이지 유지) | **메모리 스냅샷** | 이미지 포함 **완전 복구** |
| 새로고침·끊김·탭 종료 | **브라우저 로컬 저장소** | 값·신뢰도·진행 위치 (이미지는 복구되지 않음) |

새로고침 복구에서 이미지가 없는 것은 의도된 제약이다. 검수자는 값과 진단으로 이어서 작업하고, 원본 대조가 필요하면 해당 학생만 다시 올린다.

### 10-2.4 수용 기준

- 검수 도중 `검수 취소`를 누른 뒤 되돌리면 취소 직전 상태(현재 학생 위치 포함)로 복귀한다.
- 검수 도중 새로고침하면 이어서 할지 묻고, 선택 시 저장 완료 학생 목록과 검수 중이던 값이 복원된다.
- 이어서 하기를 선택하지 않고 `새로 작성`을 하면 이전 복구 지점이 남지 않는다.
- 브라우저 저장소에 원본 이미지·crop 이미지가 저장되지 않는다.

## 11. 수용 기준

### 11.1 기능 수용 기준

- 사용자는 새 작업을 만들 수 있다.
- 사용자는 학생 1명당 선별검사지 이미지와 만족도 이미지를 업로드할 수 있다.
- 시스템은 선별검사지에서 기본정보와 CAGI 응답을 추출한다.
- 시스템은 만족도 이미지에서 문항1~10만 추출한다.
- 만족도 엑셀 A~D열은 선별검사지 기본정보를 복사한다.
- 검증 통과한 학생 데이터만 두 엑셀 파일의 같은 행 번호에 저장된다.
- 10명의 학생을 저장하면 두 엑셀 파일 모두 3~12행에 값이 입력된다.
- 완료 및 다운로드 시 두 개의 엑셀 파일을 받을 수 있다.

### 11.2 데이터 수용 기준

- 성별은 `남` 또는 `여`만 저장된다.
- 만족도 파일에 `남자`, `여자`가 저장되면 실패로 본다.
- CAGI 문항은 0~3만 저장된다.
- 만족도 문항1은 1~4만 저장된다.
- 만족도 문항2~6은 0 또는 1만 저장된다.
- 만족도 문항7~10은 0~4만 저장된다.

### 11.3 엑셀 수용 기준

- 원본 템플릿의 시트명, 스타일, 병합셀, 코드 시트가 유지된다.
- 기존 드롭다운 데이터 유효성 검사 규칙이 저장 후에도 유지된다.
- 데이터는 3행부터 입력된다.
- 행 삽입으로 인해 양식 구조가 밀리면 실패로 본다.
- CAGI 파일과 만족도 파일의 학생 순번 행 번호가 어긋나면 실패로 본다.

## 12. 기술적 주의사항

- 이 프로젝트는 단순 OCR이 아니라 정해진 양식의 체크 위치를 읽는 Form Recognition 문제이다.
- 텍스트 OCR은 보조 수단이며, 문항 응답값은 좌표 기반 체크마크 인식이 더 안정적일 수 있다.
- 엑셀 템플릿의 유효성 검사는 `x14:dataValidations` 확장 영역에 존재한다. 라이브러리 저장 과정에서 이 영역이 손상되지 않아야 한다.
- 일부 엑셀 라이브러리는 파일을 저장하면서 확장 유효성 검사 정보를 제거할 수 있으므로, 반드시 저장 후 검증 테스트를 수행해야 한다.
