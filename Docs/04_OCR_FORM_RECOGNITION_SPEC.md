# OCR_FORM_RECOGNITION_SPEC — 이미지 인식 명세

## 1. 핵심 원칙

이 프로젝트는 단순 OCR이 아니다. 문항 텍스트를 읽는 것보다 정해진 양식에서 어떤 체크박스 또는 선택지에 표시가 되었는지 판정하는 것이 핵심이다.

따라서 인식 엔진은 다음 두 기능을 결합해야 한다.

1. OCR: 나이 등 숫자·텍스트 인식
2. Form Recognition: 체크 위치·동그라미 위치 인식

---

## 2. 이미지 처리 단계

권장 파이프라인은 다음과 같다.

```text
이미지 업로드
→ 이미지 방향 보정
→ 문서 외곽선 검출
→ 원근 보정
→ 양식 종류 분류
→ 관심 영역 ROI 분할
→ 체크마크/동그라미 감지
→ OCR 보조 인식
→ 내부값 변환
→ 신뢰도 산출
→ 사용자 확인 화면 전달
```

---

## 3. 양식 종류 분류

업로드된 이미지가 어떤 양식인지 먼저 분류해야 한다.

| 양식 | 판별 기준 |
|---|---|
| CAGI 선별검사지 | 제목에 `도박문제 선별검사지`, `CAGI`, `아동·청소년` 등이 있음 |
| 만족 및 평가설문 | 제목에 `예방교육 후 만족 및 평가 설문` 등이 있음 |

사용자가 CAGI 칸에 만족도 이미지를 넣거나 반대로 넣는 경우 오류 또는 확인 요청을 표시한다.

### 3.1 현재 구현 상태

2026-07-13 기준 구현은 제목 OCR이 아니라 선택지 배치 기반 MVP이다.

구현 파일:

- `src/lib/recognition/classifyForm.ts`
- `src/app/api/recognize/route.ts`

현재 방식:

1. 이미지가 존재하지 않으면 `unknown`으로 분류한다.
2. 일반 이미지(`png`, `jpg`, `jpeg`, `webp`)는 먼저 이미지 내용 기반 판별을 시도한다.
3. CAGI는 선별검사지 문항 선택지 ROI 배치와 마킹 밀도 패턴을 점수화하고, 상단 기본정보 영역을 양식 고유 signature로 함께 확인한다.
4. 만족도는 문항 1~10의 선택지 배치와 마킹 밀도 패턴을 점수화하고, 하단 문항 7~10의 5점 척도를 양식 고유 signature로 함께 확인한다.
5. 신뢰 가능한 외곽 프레임이 없으면 내용 판정을 건너뛴다.
6. 외곽 프레임이 있어도 전체 배치 점수·고유 signature·최소 점수 차이를 모두 만족하지 못하면 `unknown`으로 둔다.
7. 내용 판별이 실패한 경우 파일명 힌트(`cagi`, `satisfaction`, `선별`, `만족`, `설문` 등)를 보조로 사용한다.
8. 기존 통합 테스트용 `example` fixture는 작은 이미지이므로 파일명 힌트를 유지한다.

업로드 칸 불일치 처리:

- 업로드 API는 선택한 칸에 따라 파일명을 `cagi_...` 또는 `satisfaction_...`로 저장한다.
- 인식 API는 파일명 prefix로 사용자가 업로드한 칸을 확인한다.
- 이미지 내용 판별 결과와 prefix가 다르면 `FORM_TYPE_MISMATCH`를 반환한다.
- 이 오류는 장수 불일치(`COUNT_MISMATCH`)보다 먼저 반환한다.

자동 검증:

- `tests/form-classifier.test.ts`
- `tests/recognize-form-mismatch.test.ts`

## 4. 선별검사지 인식 대상

### 4.1 기본정보

| 항목 | 인식 방식 |
|---|---|
| 연령대 | `만 __ 세` 영역의 숫자 OCR |
| 성별 | 남자/여자 체크 위치 |
| 학교유형 | 초등학교/중학교/고등학교/학교외기관 체크 위치 |
| 학년 | 1~6학년 체크 위치 |

### 4.2 CAGI 문항

CAGI 문항 1~9는 표 형태의 선택지를 가진다.

문항 1~7 선택지:

1. 없다
2. 가끔 있다
3. 자주 있다
4. 거의 항상 있다

문항 8~9 선택지:

1. 없다
2. 1~3회 있다
3. 4~6회 있다
4. 7회 이상 있다

응답값은 왼쪽부터 0, 1, 2, 3으로 변환한다.

### 4.3 조기개입 서비스 영역

선별검사지 하단의 조기개입 서비스 영역은 엑셀 추출 대상이 아니다.

운영 정책:

- 조기개입 서비스 표기 흔적은 CAGI 문항값으로 저장하지 않는다.
- 조기개입 서비스에 표기했다가 삭제한 흔적이 있어도 선별검사지 인식은 계속 진행한다.
- 해당 흔적이 감지되면 오류가 아니라 노티스로만 표시한다.
- 노티스에는 몇 번째 선별검사지 페이지에서 감지되었는지 표시한다.

현재 구현:

- `src/lib/recognition/cagiEarlyIntervention.ts`에서 하단 조기개입 서비스 영역의 표기 흔적을 별도 ROI로 감지한다.
- `src/app/api/recognize/route.ts`는 조기개입 표기 흔적 때문에 선별검사지가 만족도조사처럼 보이는 경우에도 해당 파일을 선별검사지로 유지한다.
- `src/app/page.tsx`는 API의 `warnings`를 확인 안내로 표시한다.

주의:

- 실제 만족도조사를 선별검사지 칸에 업로드한 경우에는 여전히 `FORM_TYPE_MISMATCH`로 차단해야 한다.
- 조기개입 감지는 안내 목적이며, 엑셀 입력 데이터에는 반영하지 않는다.

## 5. 만족도 설문 인식 대상

만족도 설문에서는 문항 1~10만 인식한다.

| 문항 | 선택지 수 | 변환값 |
|---|---:|---|
| 문항1 | 4개 | 왼쪽부터 1, 2, 3, 4 |
| 문항2~6 | 2개 | 아니오=0, 예=1 |
| 문항7~10 | 5개 | 왼쪽부터 0, 1, 2, 3, 4 |

만족도 이미지에서 연령대, 성별, 학교유형, 학년을 찾으려고 하지 않는다. 해당 값은 선별검사지에서 복사한다.

### 5.1 현재 구현 상태

2026-07-23 기준 만족도 문항 1~10 ROI 인식 MVP가 구현되어 있다.

구현 파일:

- `src/lib/recognition/roiTemplates.ts`
- `src/lib/recognition/detectCheckmarks.ts`

현재 방식:

1. `satisfactionTemplate.choiceGroups`에 문항 1~10 선택지 좌표를 정의한다.
2. `recognizeStudentForms()`가 만족도 이미지를 grayscale 분석 데이터로 로드한다.
3. 각 ROI 후보의 어두운 픽셀 밀도를 계산한다.
4. 최고 점수와 차점 차이로 값을 채우고 confidence를 산출한다.
5. 불명확한 항목은 값을 비워 검수 화면에서 직접 선택하게 한다.

자동 검증:

- `tests/satisfaction-recognition.test.ts`

## 6. 체크마크 판정 방식

권장 방식:

1. 양식 좌표를 기준으로 각 선택지의 후보 영역을 정의한다.
2. 원근 보정 후 각 후보 영역의 마킹 밀도를 계산한다.
3. 가장 높은 마킹 점수를 가진 선택지를 후보값으로 선정한다.
4. 최고 점수와 차점 점수의 차이가 작으면 `확인 필요`로 표시한다.
5. 선택지 2개 이상이 임계값을 넘으면 `다중 체크` 오류로 표시한다.

## 7. 신뢰도 산출

각 필드는 다음 신뢰도를 가진다.

| 신뢰도 | 조건 | 처리 |
|---|---|---|
| high | 선택지 1개가 명확함 | 기본값으로 채움 |
| medium | 선택지가 보이나 경계가 애매함 | 사용자 확인 권장 |
| low | 마크 위치가 불명확함 | 사용자 확인 필수 |
| error | 값 추출 불가 또는 다중 체크 | 저장 불가 |

## 10. 이미지 인식 MVP 전략

1차 MVP에서는 완전 자동화를 목표로 하지 않는다.

권장 MVP 수준:

1. 이미지 업로드
2. 자동 인식 시도
3. 인식 결과를 사용자가 확인·수정
4. 검증 통과 후 엑셀 저장

초기 버전에서 신뢰도가 낮은 항목은 자동 저장하지 않고 사용자가 직접 선택하도록 한다.

## 2026-07-29 현재 구현 메모

기본정보 인식은 완전 OCR이 아니라 ROI 기반 MVP로 단계적으로 구현한다.

현재 구현:

- `basic.gender`: CAGI 양식의 성별 체크 ROI를 분석한다.
- `basic.schoolType`: CAGI 양식의 학교유형 체크 ROI를 분석하고 `초등학교`, `중학교`, `고등학교`, `학교외기관` 값으로 변환한다.
- `basic.grade`: CAGI 양식의 학년 체크 ROI를 분석하고 `1학년`~`6학년` 값으로 변환한다.
- `basic.age`: 나이 숫자 OCR은 아직 수행하지 않고, 검수 화면에서 원본 영역 crop을 보여주는 field region으로 정의한다.

검수 화면 전달 데이터:

- 선택형 ROI 필드는 `draft.confidence[field]`와 `draft.candidates[field]`를 함께 전달한다.
- `basic.age`처럼 후보 점수가 없는 입력형 ROI도 crop API에서 영역 이미지를 생성할 수 있다.

로컬 서버 테스트 포인트:

- CAGI 실제 샘플에서 학교유형/학년 체크 위치가 정확히 선택되는지 확인한다.
- confidence가 낮거나 중간인 경우 검수 화면 강조와 crop preview가 함께 표시되는지 확인한다.
- 나이 crop이 실제 나이 입력칸을 포함하고, 너무 넓거나 좁지 않은지 확인한다.
- 저장 시 `validateStudent()`가 기본정보 값을 정상 통과시키는지 확인한다.

## 2026-07-30 운영 이슈 메모

### PDF 업로드와 Vercel Serverless 세션

Vercel 배포본에서는 로컬 서버와 다르게 API 요청이 여러 함수 인스턴스에 분산될 수 있다.

따라서 다음 원칙을 따른다.

- 작업 세션은 인메모리 `Map`만으로 판단하지 않는다.
- `src/lib/storage/jobStore.ts`의 `getJobSession()`/`hasJobSession()`을 통해 `session.json` 복구 경로를 사용한다.
- 새로 추가하는 API도 jobId 검증 시 위 함수를 사용한다.
- 업로드 파일과 엑셀 작업 파일은 현재 임시 저장소 기반이므로 장기 보관 요구가 생기면 영구 저장소로 전환한다.

PDF 업로드는 다음 원칙을 따른다.

- 클라이언트에서 PDF 페이지를 큰 PNG로 업로드하지 않는다.
- JPEG 변환과 scale/quality 축소를 우선 적용한다.
- 배포본에서 업로드 실패가 발생하면 `/api/upload` status code를 기준으로 원인을 분류한다.

## 2026-08-05 인식 안전장치 및 실행 순서

실제 ROI 오정렬과 Vercel OCR 지연을 반영해 이미지 인식은 다음 순서로 실행한다.

- 신뢰 가능한 외곽 프레임이 검출된 경우에만 ROI 채점 결과를 자동값으로 확정한다.
- 프레임 크기·여백·종횡비가 양식 전체와 맞지 않으면 `contentBoundsConfident`를 false로 취급한다.
- 문항 행 위치는 서버의 픽셀 기반 가로선 검출을 먼저 사용한다.
- 픽셀 기반 행 매칭이 실패할 때만 OCR 텍스트 위치 앵커를 최대 2.5초 동안 보조적으로 시도한다.
- OCR 또는 행 검출이 실패해도 이미지 인식 요청은 중단하지 않고 기존 ROI 또는 빈 결과로 폴백한다.
- 경계가 불확실한 입력은 후보 점수와 low confidence만 검수 화면에 표시하고, 사용자가 확인·수정한 값만 저장한다.

이 원칙은 OCR이 체크마크 자체를 판독하지 않는다는 기존 정책과도 일치한다. OCR은 영역 위치 파악에만 사용하고, 실제 응답 판정은 픽셀 밀도와 사용자 검수로 제한한다.
