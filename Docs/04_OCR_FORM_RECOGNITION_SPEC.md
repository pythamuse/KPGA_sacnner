# OCR_FORM_RECOGNITION_SPEC — 이미지 인식 명세

## 1. 핵심 원칙

이 프로젝트는 단순 OCR이 아니다. 문항 텍스트를 읽는 것보다 정해진 양식에서 어떤 체크박스 또는 선택지에 표시가 되었는지 판정하는 것이 핵심이다.

따라서 인식 엔진은 다음 두 기능을 결합해야 한다.

1. OCR: 나이 등 숫자·텍스트 인식
2. Form Recognition: 체크 위치·동그라미 위치 인식

---

## 2. 이미지 처리 단계

권장 파이프라인은 다음과 같다.

```text
이미지 업로드
→ 이미지 방향 보정
→ 문서 외곽선 검출
→ 원근 보정
→ 양식 종류 분류
→ 관심 영역 ROI 분할
→ 체크마크/동그라미 감지
→ OCR 보조 인식
→ 내부값 변환
→ 신뢰도 산출
→ 사용자 확인 화면 전달
```

---

## 3. 양식 종류 분류

업로드된 이미지가 어떤 양식인지 먼저 분류해야 한다.

| 양식 | 판별 기준 |
|---|---|
| CAGI 선별검사지 | 제목에 `도박문제 선별검사지`, `CAGI`, `아동·청소년` 등이 있음 |
| 만족 및 평가설문 | 제목에 `예방교육 후 만족 및 평가 설문` 등이 있음 |

사용자가 CAGI 칸에 만족도 이미지를 넣거나 반대로 넣는 경우 오류 또는 확인 요청을 표시한다.

### 3.1 현재 구현 상태

2026-07-13 기준 구현은 제목 OCR이 아니라 선택지 배치 기반 MVP이다.

구현 파일:

- `src/lib/recognition/classifyForm.ts`
- `src/app/api/recognize/route.ts`

현재 방식:

1. 이미지가 존재하지 않으면 `unknown`으로 분류한다.
2. 일반 이미지(`png`, `jpg`, `jpeg`, `webp`)는 먼저 이미지 내용 기반 판별을 시도한다.
3. CAGI는 선별검사지 문항 선택지 ROI 배치와 마킹 밀도 패턴을 점수화한다.
4. 만족도는 문항1, 문항2~6, 문항7~10의 선택지 배치와 마킹 밀도 패턴을 점수화한다.
5. 두 점수 차이가 작거나 임계값에 못 미치면 `unknown`으로 둔다.
6. 내용 판별이 실패한 경우 파일명 힌트(`cagi`, `satisfaction`, `선별`, `만족`, `설문` 등)를 보조로 사용한다.
7. 기존 통합 테스트용 `example` fixture는 작은 이미지이므로 파일명 힌트를 유지한다.

업로드 칸 불일치 처리:

- 업로드 API는 선택한 칸에 따라 파일명을 `cagi_...` 또는 `satisfaction_...`로 저장한다.
- 인식 API는 파일명 prefix로 사용자가 업로드한 칸을 확인한다.
- 이미지 내용 판별 결과와 prefix가 다르면 `FORM_TYPE_MISMATCH`를 반환한다.
- 이 오류는 장수 불일치(`COUNT_MISMATCH`)보다 먼저 반환한다.

자동 검증:

- `tests/form-classifier.test.ts`
- `tests/recognize-form-mismatch.test.ts`

## 4. 선별검사지 인식 대상

### 4.1 기본정보

| 항목 | 인식 방식 |
|---|---|
| 연령대 | `만 __ 세` 영역의 숫자 OCR |
| 성별 | 남자/여자 체크 위치 |
| 학교유형 | 초등학교/중학교/고등학교/학교외기관 체크 위치 |
| 학년 | 1~6학년 체크 위치 |

### 4.2 CAGI 문항

CAGI 문항 1~9는 표 형태의 선택지를 가진다.

문항 1~7 선택지:

1. 없다
2. 가끔 있다
3. 자주 있다
4. 거의 항상 있다

문항 8~9 선택지:

1. 없다
2. 1~3회 있다
3. 4~6회 있다
4. 7회 이상 있다

응답값은 왼쪽부터 0, 1, 2, 3으로 변환한다.

## 5. 만족도 설문 인식 대상

만족도 설문에서는 문항 1~10만 인식한다.

| 문항 | 선택지 수 | 변환값 |
|---|---:|---|
| 문항1 | 4개 | 왼쪽부터 1, 2, 3, 4 |
| 문항2~6 | 2개 | 아니오=0, 예=1 |
| 문항7~10 | 5개 | 왼쪽부터 0, 1, 2, 3, 4 |

만족도 이미지에서 연령대, 성별, 학교유형, 학년을 찾으려고 하지 않는다. 해당 값은 선별검사지에서 복사한다.

### 5.1 현재 구현 상태

2026-07-23 기준 만족도 문항 1~10 ROI 인식 MVP가 구현되어 있다.

구현 파일:

- `src/lib/recognition/roiTemplates.ts`
- `src/lib/recognition/detectCheckmarks.ts`

현재 방식:

1. `satisfactionTemplate.choiceGroups`에 문항 1~10 선택지 좌표를 정의한다.
2. `recognizeStudentForms()`가 만족도 이미지를 grayscale 분석 데이터로 로드한다.
3. 각 ROI 후보의 어두운 픽셀 밀도를 계산한다.
4. 최고 점수와 차점 차이로 값을 채우고 confidence를 산출한다.
5. 불명확한 항목은 값을 비워 검수 화면에서 직접 선택하게 한다.

자동 검증:

- `tests/satisfaction-recognition.test.ts`

## 6. 체크마크 판정 방식

권장 방식:

1. 양식 좌표를 기준으로 각 선택지의 후보 영역을 정의한다.
2. 원근 보정 후 각 후보 영역의 마킹 밀도를 계산한다.
3. 가장 높은 마킹 점수를 가진 선택지를 후보값으로 선정한다.
4. 최고 점수와 차점 점수의 차이가 작으면 `확인 필요`로 표시한다.
5. 선택지 2개 이상이 임계값을 넘으면 `다중 체크` 오류로 표시한다.

---

## 7. 신뢰도 산출

각 필드는 다음 신뢰도를 가진다.

| 신뢰도 | 조건 | 처리 |
|---|---|---|
| high | 선택지 1개가 명확함 | 기본값으로 채움 |
| medium | 선택지가 보이나 경계가 애매함 | 사용자 확인 권장 |
| low | 마크 위치가 불명확함 | 사용자 확인 필수 |
| error | 값 추출 불가 또는 다중 체크 | 저장 불가 |

## 10. 이미지 인식 MVP 전략

1차 MVP에서는 완전 자동화를 목표로 하지 않는다.

권장 MVP 수준:

1. 이미지 업로드
2. 자동 인식 시도
3. 인식 결과를 사용자가 확인·수정
4. 검증 통과 후 엑셀 저장

초기 버전에서 신뢰도가 낮은 항목은 자동 저장하지 않고 사용자가 직접 선택하도록 한다.

## 2026-07-29 현재 구현 메모

기본정보 인식은 완전 OCR이 아니라 ROI 기반 MVP로 단계적으로 구현한다.

현재 구현:

- `basic.gender`: CAGI 양식의 성별 체크 ROI를 분석한다.
- `basic.schoolType`: CAGI 양식의 학교유형 체크 ROI를 분석하고 `초등학교`, `중학교`, `고등학교`, `학교외기관` 값으로 변환한다.
- `basic.grade`: CAGI 양식의 학년 체크 ROI를 분석하고 `1학년`~`6학년` 값으로 변환한다.
- `basic.age`: 나이 숫자 OCR은 아직 수행하지 않고, 검수 화면에서 원본 영역 crop을 보여주는 field region으로 정의한다.

검수 화면 전달 데이터:

- 선택형 ROI 필드는 `draft.confidence[field]`와 `draft.candidates[field]`를 함께 전달한다.
- `basic.age`처럼 후보 점수가 없는 입력형 ROI도 crop API에서 영역 이미지를 생성할 수 있다.

로컬 서버 테스트 포인트:

- CAGI 실제 샘플에서 학교유형/학년 체크 위치가 정확히 선택되는지 확인한다.
- confidence가 낮거나 중간인 경우 검수 화면 강조와 crop preview가 함께 표시되는지 확인한다.
- 나이 crop이 실제 나이 입력칸을 포함하고, 너무 넓거나 좁지 않은지 확인한다.
- 저장 시 `validateStudent()`가 기본정보 값을 정상 통과시키는지 확인한다.
