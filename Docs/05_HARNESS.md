# HARNESS — 코딩에이전트 작업 통제·오류 방지 문서

## 1. 목적

이 문서는 코딩에이전트가 구현 과정에서 반복적으로 저지를 수 있는 실수를 사전에 차단하기 위한 하네스 문서이다.

에이전트는 기능 구현 전에 이 문서를 먼저 읽고, 각 작업 후 스스로 체크리스트를 통과해야 한다.

---

## 2. 절대 변경하면 안 되는 것

다음은 절대 변경하지 않는다.

1. 원본 엑셀 템플릿 파일
2. 엑셀 시트명
3. 코드 시트
4. 1~2행의 제목·예시 영역
5. 병합셀 구조
6. 기존 스타일
7. 기존 데이터 유효성 검사 규칙
8. `x14:dataValidations` 확장 영역

작업 파일은 항상 원본 템플릿의 복사본으로 생성한다.

---

## 3. 가장 중요한 비즈니스 규칙

### 3.1 만족도 A~D열은 만족도 이미지에서 읽지 않는다

만족도 파일의 A~D열은 선별검사지 이미지에서 추출한 기본정보를 그대로 복사해야 한다.

금지:

```text
만족도 이미지에서 연령대, 성별, 학교유형, 학년을 OCR로 찾기
```

허용:

```text
선별검사지 basic.age/gender/schoolType/grade 값을 만족도 A~D열에 복사
```

### 3.2 학생 1명은 두 파일의 같은 행 번호에 저장한다

예:

| 학생 | CAGI 행 | 만족도 행 |
|---:|---:|---:|
| 1 | 3 | 3 |
| 2 | 4 | 4 |
| 10 | 12 | 12 |

CAGI 파일과 만족도 파일의 행 번호가 어긋나면 실패이다.

### 3.3 행 삽입 금지

`insertRow`, `spliceRows` 등으로 행을 삽입하지 않는다.

3행부터 다음 빈 행에 값을 쓴다.

---

## 4. 예상 실수와 방지 규칙

| 예상 실수 | 방지 규칙 |
|---|---|
| 성별을 `남자`, `여자`로 저장 | 반드시 `남`, `여`로 정규화 |
| 만족도 문항1에 0 저장 | 문항1은 1~4만 허용 |
| 만족도 문항2~6에 4 저장 | 문항2~6은 0 또는 1만 허용 |
| 모든 만족도 문항을 0~4로만 검증 | 문항별 검증 규칙 적용 |
| CAGI와 만족도 행 번호 불일치 | 학생 리스트 기준 targetRow 계산 |
| 선별검사지 없이 만족도만 저장 | 저장 불가 처리 |
| 만족도 없이 선별검사만 저장 | 저장 불가 처리 |
| OCR 결과를 바로 엑셀 저장 | 사용자 확인 후 저장 |
| 낮은 신뢰도 값을 자동 확정 | 확인 필요 상태로 표시 |
| 원본 템플릿 수정 | 세션 복사본만 수정 |
| 엑셀 저장 후 드롭다운 사라짐 | 저장 후 x14 데이터 유효성 검사 보존 테스트 |
| 숫자를 문자열로 저장 | 숫자 필드는 number 타입 저장 |

## 5. 구현 순서 제약

코딩에이전트는 다음 순서로 구현한다.

1. 데이터 모델 및 검증 함수
2. 엑셀 템플릿 로드·복사·쓰기 기능
3. 엑셀 저장 후 검증 테스트
4. 이미지 업로드 UI
5. OCR/Form Recognition 모듈 인터페이스
6. 사용자 확인 화면
7. 학생 저장 트랜잭션
8. 다운로드 기능
9. 회귀 테스트

OCR 고도화보다 데이터 검증과 엑셀 안정성을 먼저 구현한다.

---

## 6. Definition of Done

기능 하나가 완료되었다고 판단하려면 다음 조건을 만족해야 한다.

1. 단위 테스트가 있다.
2. 잘못된 값에 대한 실패 테스트가 있다.
3. 예시 이미지 기대값을 기준으로 통합 테스트가 통과한다.
4. CAGI와 만족도 파일의 행 번호가 일치한다.
5. 저장된 엑셀 파일을 다시 읽었을 때 값이 정확하다.
6. 템플릿의 데이터 유효성 검사 규칙이 유지된다.
7. 사용자가 수정한 값이 OCR 값보다 우선한다.
8. 에러 메시지가 사용자 조치 중심으로 표시된다.

## 7. 코드 리뷰 체크리스트

### 데이터 검증

- [ ] 필수값 누락을 막는가?
- [ ] 성별을 남/여로 정규화하는가?
- [ ] 학교유형 허용값을 제한하는가?
- [ ] 학년 허용값을 제한하는가?
- [ ] CAGI 01~09를 0~3으로 제한하는가?
- [ ] 만족도 문항1을 1~4로 제한하는가?
- [ ] 만족도 문항2~6을 0~1로 제한하는가?
- [ ] 만족도 문항7~10을 0~4로 제한하는가?

### 엑셀 쓰기

- [ ] 데이터 시작 행이 3행인가?
- [ ] 행 삽입을 하지 않는가?
- [ ] CAGI A~M 매핑이 정확한가?
- [ ] 만족도 A~N 매핑이 정확한가?
- [ ] 만족도 A~D는 선별검사지 기본정보를 복사하는가?
- [ ] 숫자값이 number 타입으로 저장되는가?
- [ ] 두 파일의 행 번호가 항상 같은가?

### 이미지 인식

- [ ] 양식 종류를 분류하는가?
- [ ] CAGI 이미지와 만족도 이미지가 뒤바뀌면 감지하는가?
- [ ] 신뢰도 낮은 항목을 사용자 확인 대상으로 표시하는가?
- [ ] 다중 체크를 오류로 표시하는가?

### UX

- [ ] 사용자가 인식 결과를 수정할 수 있는가?
- [ ] 저장 전 전체 검증 결과를 볼 수 있는가?
- [ ] 재업로드할 수 있는가?
- [ ] 오류 메시지가 구체적인가?

## 8. 회귀 테스트 고정 사례

예시 이미지 기준 고정 기대값:

```json
{
  "basic": {
    "age": 14,
    "gender": "여",
    "schoolType": "중학교",
    "grade": "2학년"
  },
  "cagi": [0,0,0,0,0,0,0,0,0],
  "satisfaction": [4,1,1,1,1,1,4,4,4,4]
}
```

이 케이스는 회귀 테스트에 반드시 포함한다.

## 10. 금지 명령

코딩에이전트에게 다음 식으로 지시하지 않는다.

```text
대충 OCR해서 엑셀에 넣어줘.
```

```text
일단 엑셀에 저장되게만 해줘.
```

```text
나중에 검증은 추가하자.
```

이 프로젝트의 핵심은 빠른 저장이 아니라 중앙 시스템 업로드 실패를 줄이는 검증 가능한 저장이다.
