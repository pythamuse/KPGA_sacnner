## 0. 기준으로 삼는 의도 (사용자, 2026-09-02)

1. **항목별 이미지 추출·파서** — 스캔 한 장을 문항 단위 셀로 정확히 분해한다.
2. **항목 마킹 판정** — 각 문항에서 어느 선택지가 표시됐는지 결정한다.
3. **리마크** — 표시가 원래 자리에서 조금 벗어나거나, 모양이 이상하거나, 흐리면 **보정은 더하되
   최종 판단은 사람이 하도록 표시**한다.
4. **스캔이 현실적 상위권 입력**이다. 사진은 부차적이다.
5. 절대 규칙 **오답 0** — 자동 입력된 오답은 사람이 확인한 것처럼 저장된다. 빈칸은 키 한 번이다.
6. 여전히 관찰되는 증상: **잘못된 항목을 가리킴.**

### A.2 인식 스펙 (`04_OCR_FORM_RECOGNITION_SPEC.md`)

§2 파이프라인은 "업로드 → 방향 → 외곽선 → 원근 → 양식 분류 → ROI 분할 → 체크 감지 → OCR 보조
→ 변환 → 신뢰도 → 확인 화면"으로 의도 1·2를 담는다. 그러나:

- §6 판정 방식: "차점 차이가 작으면 `확인 필요`, 2개 이상이 임계값을 넘으면 `다중 체크` 오류" —
  **잉크 밀도 순위와 한 가지 여유 폭**만 정의한다. 자리 이탈·모양·흐림은 원인으로 언급되지
  않는다.
- §7 신뢰도표에 `error: 값 추출 불가 또는 다중 체크 → 저장 불가`가 있다. **코드의 신뢰도 타입은
  `'high' | 'medium' | 'low'` 뿐이다**(`markDensity.ts:74`, `detectCheckmarks.ts:116`). 스펙의
  네 번째 상태는 구현된 적이 없다.
- §8 후보 점수 페이로드는 실제로 전달된다(`draft.candidates` → `RecognitionReview.tsx:353`, 상위
  3개 표시). 일치.
- §9 재촬영 조건은 사진 전용. 스캔에 대한 품질 판정(예: 1비트/회색조, 기기 차이)은 없다.
- 2026-08-05 메모 "신뢰 가능한 외곽 프레임이 검출된 경우에만 ROI 채점 결과를 자동값으로 확정"
  — **이 문장이 설계의 핵심 안전장치인데, "신뢰 가능한 외곽 프레임"의 정의가 코드에서 너무
  넓다**(A.4).

### A.3 이미 있었던 재설계 (`Task/RECOGNITION_ARCHITECTURE_REDESIGN.md`, 2026-08-10)

같은 종류의 재검토가 한 번 있었다. 결론은 옳았다:

- §4 "**이미지가 진실이고, 템플릿은 스키마(개수)일 뿐 좌표가 아니다.**"
- §5 "폴백은 '값을 채우지 않는다'는 뜻이지 '틀린 좌표로 채운다'가 아니어야 한다."
- §10 "배지가 격자 검출인데도 신뢰도가 낮으면 그건 위치가 아니라 **마킹 판별** 문제 → 인쇄
  원문자와 수기 표시의 분리로 넘어간다."

그리고 그 원칙은 **격자 간격 대조 한 곳에만 적용됐다**(템플릿 간격 패턴 → 검출 행 균등성).
등록(종이 경계) 계층과 대체 경로에는 적용되지 않았고, 사이클 1(§17.1)이 정확히 §5의 위반이었다.
§10이 예고한 "마킹 판별 문제"는 §30·§31에서 재발견됐다(거절 칸의 77~90%가 순위는 맞음).

**교훈**: 재설계의 원칙이 문서에만 있고 **코드의 어느 지점이 그 원칙을 집행하는지**가 명시되지
않으면, 다음 라운드는 같은 위반을 새 이름의 버그로 다시 만난다(A.5).

### A.4 안전장치의 실제 정의 — 프레임 대체가 "확신"으로 계산된다

의도 3·5의 집행점은 "경계가 불확실하면 자동 확정 금지"다. 코드로 추적하면:

```
detectPaperBounds  절대 문턱 [195,170] (→ 유도값으로 수정됨, §17.1)
  └ 실패 → pageBounds = undefined
       └ detectFrameBounds(image)  어두운 행 ≥35% 를 프레임으로 → 책상 테두리가 잡힘
            └ contentBounds = 프레임(이미지의 ~90%), contentBoundsSource = 'frame'
                 └ contentBoundsConfident = paperContentBounds !== null || frameBounds !== null   ← markDensity.ts:476
                      └ resolveFormBoundsStatus: pageBounds 없음 → legacy 분기
                           폭≥72% · 높이≥78% · 가장자리 16% 이내 · 종횡비 → 'ok-legacy'
                                └ canAutoRecognize = true → 격자 검출이 프레임 좌표 위에서 'verified'
                                     └ 틀린 행에서 conf=high 값 생산 (cagi.q01 → "3", 7건)
```

**`contentBoundsConfident`가 "종이를 찾았다"가 아니라 "큰 어두운 테두리를 찾았다"를 뜻한다.**
BUG_REPORTS #11(2026-08-05)·#19·#20이 모두 이 정의 위에 서 있고, #11의 대응("`contentBoundsConfident
=== false`면 low만")은 프레임 경로에서 발화하지 않는다. 사이클 1은 촉발 조건(밝기 문턱)을 고쳤을
뿐 **이 정의는 그대로다.**

### A.5 같은 실패가 버그로 세 번 등재됐다

| 버그 | 제목 | 뿌리 |
|---|---|---|
| #11 | 종이 경계 불확실 상태에서 ROI 값 자동 확정 | 프레임 대체 = 확신 (A.4) |
| #19 | 격자 거부 후 템플릿 폴백의 역효과 | 폴백이 "틀린 좌표로 채움" (재설계 §5 위반) |
| #20 | 표시가 없는 칸에 값을 만들어내 `높음`으로 확정 | 잉크 총량 판정이 인쇄 잔여를 표시로 읽음 (재설계 §10) |

세 항목의 "대응"은 각각 조건 추가·미착수·형태 게이트였고, 세 번째는 재발이 기록돼 있다.
**한 설계 결함이 세 개의 버그 번호를 받았다.** 이것이 "계측·피드백만으로는 안 된다"는 사용자
판단의 문서상 근거다.

### A.6 요약 — 상위 문서에 없는 것

1. **입력 우선순위**(스캔 상위권)가 PRD에 없다 → CLAUDE.md §5.0에만 있다. PRD §1·§4에 반영 필요.
2. **리마크의 원인 구분**(자리·모양·흐림)이 PRD §8·스펙 §6~7 어디에도 없다. 신뢰도가 단일
   척도라 검수자는 "왜 확인해야 하는지"를 받지 못한다.
3. **다중 체크/경합 상태**가 요구사항에는 있고 구현에는 없다. 경합 배지는 그 대용품이다.
4. **"신뢰 가능한 외곽 프레임"의 정의**가 스펙에 없어서, 코드가 책상 테두리를 그 자리에 넣어도
   스펙 위반이 아니다.
5. **재설계 원칙의 집행 지점**이 적혀 있지 않아 원칙이 일부 계층에만 적용됐다.
