## 마스터 지시문

너는 도박예방교육 응답지 사진을 기반으로 중앙 시스템 업로드용 엑셀 파일 2개를 자동 작성하는 웹앱을 구현한다.

반드시 다음 문서를 먼저 읽고 구현 계획을 세워라.

1. `00_PRD.md`
2. `01_DATA_MAPPING.md`
3. `02_VALIDATION_SPEC.md`
4. `03_EXCEL_IO_SPEC.md`
5. `04_OCR_FORM_RECOGNITION_SPEC.md`
6. `05_HARNESS.md`
7. `06_TEST_PLAN.md`
8. `07_IMPLEMENTATION_PLAN.md`

핵심 비즈니스 규칙은 다음이다.

1. 학생 1명은 선별검사지 이미지 1장과 만족도 설문 이미지 1장으로 구성한다.
2. 선별검사지 이미지에서 연령대, 성별, 학교유형, 학년, CAGI 01~09를 추출한다.
3. 만족도 이미지에서는 문항1~10만 추출한다.
4. 만족도 엑셀의 A~D열은 만족도 이미지에서 추출하지 말고, 선별검사지에서 추출한 기본정보를 복사한다.
5. CAGI 파일과 만족도 파일은 같은 학생에 대해 같은 행 번호에 저장한다.
6. 데이터는 3행부터 입력한다.
7. 행 삽입을 하지 말고 다음 빈 행에 값을 쓴다.
8. 검증 실패 데이터는 엑셀에 저장하지 않는다.
9. OCR 결과는 사용자 확인 화면을 거친 뒤 저장한다.
10. 원본 엑셀 템플릿의 구조, 스타일, 병합셀, 코드 시트, 데이터 유효성 검사, x14:dataValidations를 보존해야 한다.

우선 구현 순서는 다음을 따른다.

1. 데이터 모델과 검증 함수
2. 엑셀 템플릿 복사 및 쓰기
3. 저장 후 엑셀 재검증
4. 웹 UI
5. 이미지 업로드
6. OCR/Form Recognition 인터페이스
7. 다운로드 기능
8. 통합 테스트

작업할 때마다 다음을 보고하라.

```md

- 구현한 파일:
- 변경한 함수:
- 테스트 결과:

- 엑셀 저장 테스트 통과 여부:
- 드롭다운 보존 여부:
- 행 번호 일치 여부:

## 남은 리스크
- 

## 다음 작업 제안
- 
```

절대 하지 말아야 할 것:

1. 원본 템플릿 직접 수정
2. 행 삽입
3. 만족도 이미지에서 A~D 기본정보 추출
4. 성별을 `남자`, `여자`로 저장
5. OCR 결과를 확인 없이 저장
6. 검증 함수를 나중으로 미루기
7. 템플릿 보존 테스트 없이 엑셀 라이브러리 확정

## Vercel 배포 환경 강제 지침

다음 규칙은 이미지·PDF 업로드, 인식, 검수, 저장 기능을 수정하거나 새로 작성할 때 반드시 지킨다.

1. **서버 함수의 메모리와 `os.tmpdir()`를 브라우저 요청 사이의 저장소로 사용하지 않는다.** Vercel은 같은 사용자의 연속 요청도 서로 다른 인스턴스에서 처리할 수 있으며, 각 인스턴스의 임시 디스크는 공유되지 않는다.
2. 업로드 API가 성공을 반환하기 전에 원본 파일과 페이지 순서는 외부 영속 저장소에 기록되어야 한다. 대안으로, 원본 파일을 받은 **같은 요청 안에서** 전체 인식까지 끝내고 결과만 반환할 수 있다. 여러 요청에 걸쳐 로컬 파일을 다시 읽는 설계는 금지한다.
3. PDF 일괄 업로드는 `PDF의 numPages`, 사용자 선택 업로드 칸, 페이지 순번, 영속 저장 성공 여부를 포함한 인벤토리를 만든다. 분석 시작 전 이 인벤토리의 기대 장수와 영속 파일 장수가 각각 일치해야 한다.
4. `COUNT_MISMATCH`는 영속 인벤토리에서 실제 누락 또는 중복이 확인된 경우에만 반환한다. 현재 함수 인스턴스에서 보이는 파일 수만으로 사용자가 사진을 누락했다고 안내하지 않는다. 저장소 확인이 불가능하면 `UPLOAD_INTEGRITY_ERROR`로 분리해 재시도·복구 안내를 제공한다.
5. `unknown` 양식 분류 폴백, 파일명 힌트, UI 장수 카운트는 파일 영속성 문제의 해결책이 아니다. 이 로직을 바꾸더라도 다중 인스턴스에서 파일이 유지되는지 별도로 검증한다.
6. 로컬 테스트만 통과한 상태를 Vercel 배포 검증 완료로 선언하지 않는다. 실제 스캐너 PDF로 PDF 페이지 수, 영속 인벤토리, 분석 입력 장수, 페어링 장수를 모두 대조하는 배포 테스트를 남긴다.
7. 원본 응답지에는 개인정보가 포함될 수 있으므로, 외부 저장소를 사용할 때는 비공개 접근, 짧은 보존 기간, 작업 종료·만료 시 삭제를 기본값으로 한다. 공개 URL, 파일명에 개인정보 삽입, 로그 본문 저장은 금지한다.

첫 작업으로 전체 구현 계획과 파일 구조를 제안하고, Phase 1 데이터 모델·검증부터 시작하라.
