# 실패 항목별 원인 소거표

인식이 채우지 못하는 항목마다 **이미 시험해서 기각된 가설**과 **아직 남은 후보**를 적는다. 새 라운드를 시작하기 전에 여기서 먼저 확인해, 같은 막다른 길을 다시 걷지 않도록 하는 것이 이 문서의 유일한 목적이다.

**기록 규칙**
- 기각은 반드시 **숫자와 함께** 적는다. "효과 없었다"만으로는 다음 사람이 다시 시도한다.
- 확정 사실과 추정을 섞지 않는다. 측정으로 뒷받침되지 않으면 "남은 후보"에 둔다.
- 새 가설을 기각하면 이 표에 한 줄 추가한다. 상세 경위는 `Task/` 문서 링크로만 남긴다.

**기준 측정**: 배포본 래스터(`PDF_RENDER_OPTIONS[0]` = scale 1.5, JPEG q0.86), 실제 스캔 6페이지, 정답표 대조.
**현재 상태**(2026-08-20, `main`): `CORRECT 102/135, WRONG 0, BLANK 33, OFF 10, MISSING 7`
**목표**([PRD §10-1](00_PRD.md)): `CORRECT ≥ 118, WRONG = 0`

## 1. 현재 실패 항목 — 33칸

진단 문구의 `src`와 `conf` 조합이 실패 계층을 결정한다.

| 계층 | 판별 조건 | 칸 수 | 해당 항목 |
|---|---|---:|---|
| **L1 OCR** | `src=fixed`, 연령 전용 | **6** | `basic.age` 6 |
| **L2 마킹 판별** | `src=grid` + `conf=low/medium` | **17** | 만족도 8, CAGI 6, 기본정보 3 |
| **L3 게이트 차단** | `src=grid` + **`conf=high`인데 빈칸** | **4** | `basic.gender` 2, `basic.grade` 1, `basic.schoolType` 1 |
| **L4 좌표 실패** | `src=fixed`/`row-fallback` (연령 제외) | **6** | 만족도 5, q01 1 |

**L3가 가장 이상한 계층이다.** 고신뢰로 값을 냈는데도 자동 입력이 막힌다 — 판정이 아니라 **게이트**의 문제다.

## 3. L1 — 연령대 OCR (6칸)

`basic.age`, 6페이지 전부 빈칸. 정답 `14, 14, 15, 15, 12, 13`.
2026-08-20 계측으로 **두 해상도 × 6페이지 = 12개 판독**을 전수 확보했다 → [[AGE_OCR_PREPROCESSING_2026-08-20]] §7

### 확정된 사실

| 사실 | 근거 |
|---|---|
| 워커 교착은 해소됐다 | 진단이 `worker was still initializing` → 실제 판정 결과로 바뀜. `langPath` 지정 |
| OCR은 매 페이지 끝까지 실행된다 | 두 리더 모두 완주, 타임아웃 없음 |
| **리더는 빈 문자열을 낸다** | 진단이 `nondigits=N`을 붙이게 되어 있는데 12개 판독 어디에도 없음 |
| **낱자는 높은 신뢰도로 읽힌다** | p1@3.0 둘째 자리 `4` **c92**, p5@1.5 전체 박스 `"12"` c39 |
| **항상 두 자리 중 하나가 침묵한다** | 낱자 신뢰도쌍 `(0,92)`·`(12,0)`·`(51,0)`·`(33,0)` |
| **인쇄 테두리가 살아남아 전 폭 성분이 된다** | 작업 이미지 폭과 **정확히 같은** 성분(408·552)이 1.5에서 4/6, 3.0에서 2/6 |
| `MIN_DIGIT_CONFIDENCE=60`이 오답을 막고 있다 | 문턱을 낮추면 p1에 `19`가 자동 입력됨 |

### 기각된 가설

| 가설 | 결과 |
|---|---|
| 해상도가 낮아서 못 읽는다 | **기각 2회.** 전처리 전 1.5/2.0/3.0, 전처리 후 1.5/3.0 — 다섯 번 모두 6/6 빈칸. 3.0에서는 p5의 정답 `"12"`마저 잃음 |
| 신뢰도 문턱을 낮추면 된다 | **금지.** 오답이 자동 입력됨 |
| 전처리(밑줄 제거 + 적응형 이진화 + 획 분리 + 2중 리더)로 해결된다 | **미달.** 합성 0/6→6/6이었으나 실제는 6/6 빈칸 그대로, 총점 102 무변화. 실패 지점만 이동 |
| `char_whitelist`가 LSTM에서 무시되어 `l`·`\|`로 읽힌다 | **기각.** 애초에 아무 문자도 나오지 않는다. **유사 문자 매핑은 시도할 필요가 없다** |
| 크롭·밑줄·이진화가 남은 장애물이다 | **기각.** 같은 파이프라인에서 c92가 나온다 |

### 남은 후보
- **작업 이미지의 전 폭·전 높이를 차지하는 성분 제거** — 두 자리 칸 안의 손글씨는 칸 전체만큼 넓을 수 없다(기하 규칙, 필드명 분기 아님)
- 침묵하는 자리와 획 폭의 상관 — 진단이 획과 낱자 신뢰도를 같은 순서로 짝지어야 판정 가능
- `SINGLE_CHAR`가 세로 막대 하나에 침묵하는 문제 — 렌더 여백·획 높이 조정

→ 진행 중: [[AGE_OCR_PREPROCESSING_2026-08-20]]

## 4. L2 — 마킹 판별 (17칸)

`src=grid`로 좌표는 검증됐는데 `conf`가 낮아 자동 입력되지 않는다. 만족도 8, CAGI 6, 기본정보 3.

### 확정된 사실

| 사실 | 근거 |
|---|---|
| 좌표는 정확하다 | `satisfaction.q01` 4페이지 모두 중심 오차 ≤0.004 |
| 인쇄 잔여가 모든 후보에 깔린다 | 후보 5개가 전부 0.02~0.05를 가짐 |
| **약한 표시는 인쇄 잔여보다 낮다** | 한 페이지 정답 `0.011` vs 같은 칸 인쇄 잔여 `0.020`. 정상 페이지 정답은 `0.067` (6배 차이) |
| 양쪽이 노이즈일 때 상대 대비는 무력하다 | 위 페이지의 배수 1.82배로 `high` 확정 → 오답 |
| 표기 방식이 두 가지다 | 기본정보는 13px 박스 **안의 작은 체크**, CAGI·만족도는 인쇄 글자를 **감싸는 큰 동그라미** |

### 기각된 가설

| 가설 | 결과 |
|---|---|
| 리샘플링 방식이 원인 | **기각** (G4) |
| 인쇄 요소 상쇄를 강화하면 된다 | **기각** (G5) |
| 인셋 비대칭(3px vs 4px)이 원인 | **기각.** 양쪽 20%로 통일하자 기본정보 `13→0` |
| 농도를 버리고 인쇄 독립성으로 교체 | **기각** (G6) |
| 농도와 인쇄 독립성의 최대값 | **기각** (G6-b). 기존 동작은 보존되나 순이득 0 |
| 절대 신호 하한만으로 오답을 거를 수 있다 | **부분 채택.** 0.021이 오답 1건 제거(`CORRECT 102, WRONG 0`). 그러나 약한 진짜 표시도 함께 막음 |
| 상대 대비 문턱을 낮추면 더 채워진다 | **기각.** 1.15와 1.25가 계측기에서 동일(`CORRECT 92`). 낮추면 마진만 잃음 |

### 남은 후보
- ~~둘 중 최대값~~ → 기각(G6-b). 농도가 애매할 때**만** 인쇄 독립성을 쓰는 조건부 방식은 미시험
- 잉크 무게중심의 셀 중심 대비 편향
- 두 표기 방식을 각각 만족하는 특징의 조합

→ 진행 중: [[MARK_EVIDENCE_WEAK_SIGNAL_2026-08-20]] 2차

## 5. L3 — 게이트 차단 (4칸) ★ 가장 명확한 결함

`conf=high`로 값이 나왔는데도 빈칸. 기본정보 전용.

### 확정된 사실

| 사실 | 근거 |
|---|---|
| 배수가 커도 막힌다 | 실사용 `여 21% / 남 4%`(5.25배), `여 15% / 남 3%`(5.00배) 모두 보류 |
| 상대 대비는 통과한다 | 5배 > 1.25 |
| **`hasUniqueDirectCheckboxEvidence` 하나가 원인** | `detectCheckmarks.ts:649`. "내부에 잉크가 있는 칸이 정확히 하나"를 요구 |
| 인쇄 테두리 잔여로 두 칸 모두 잉크 있음이 된다 | 인셋 실험에서 내부 표본을 넓히자 전 항목이 모호로 떨어짐 |
| 실사용에서는 6/6 전부 보류 | 계측기(3/5 통과)보다 훨씬 나쁨 — 브라우저 래스터 격차 |

### 기각된 가설

| 가설 | 결과 |
|---|---|
| `MIN_COMPONENT_SIZE=12`(절대 픽셀) 때문에 체크박스 검출이 탈락한다 | **이 해상도에서는 기각.** 6페이지 모두 12/12 정합 성공. 단 실사용 학생 5에서는 `did not match the complete 12-box baseline` 발생 — 더 낮은 해상도에서는 여전히 후보 |
| 인셋 대칭화로 해결 | **기각** (§4) |

### 남은 후보
- 게이트의 판정 근거를 "내부 잉크 유무"에서 다른 특징으로 교체(§4와 같은 뿌리)
- 실사용에서만 나타나는 12/12 정합 실패 — 브라우저 래스터에서 재현 필요

## 6. L4 — 좌표 실패 (6칸)

`src=fixed` 또는 `row-fallback`. 격자 검증에 실패해 자동 입력 자격이 없다.

### 확정된 사실

| 사실 | 근거 |
|---|---|
| 격자 거부 시 자동 입력은 **설계상** 차단된다 | 결함이 아니라 안전장치. C1-b에서 확정 |
| 하단 5점 척도 표의 실패 원인은 **선 누락**이었다 | 기대선 `y=943`이 3페이지에서 검출 목록에 아예 없었음. 감도 0.3→0.2로 해결(`+10 CORRECT`) |
| `satisfaction.q01`은 격자 문제가 **아니다** | 3칸 중 2칸이 `src=grid`인데 빈칸 → L2 소속 |

### 기각된 가설

| 가설 | 결과 |
|---|---|
| 매칭기가 선을 잘못 고른다(선택 실패) | **기각.** 진짜 선이 검출 자체에서 빠져 있었음 |
| `darkThreshold`를 180→200으로 올린다 | **기각.** p4·p5를 살리는 대신 p2·p3를 잃음(만족도 7~10 정답 22칸→13칸) |

### 남은 후보
- `satisfaction.q01` p6의 `row-fallback` 1칸 — 단독 조사 필요
- `rowSearchToleranceRatio: 0.1`이 표 높이의 2.7배를 검색 — 잡선 유입 여지
