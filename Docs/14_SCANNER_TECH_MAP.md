# 스캐너 기술 지도 — 무엇으로 만들었고, 어디까지 왔는가

작성 2026-08-27. **개발 지식이 없는 독자를 위한 문서**입니다. 이 스캐너가 어떤 기술로
움직이는지, 기능별로 얼마나 완성됐는지, 무엇이 남았는지를 한 장에서 볼 수 있게 정리했습니다.
모든 숫자는 실제 테스트(학생 19명분 사진 38장 + 스캔본)를 정답표와 대조해 얻은 측정값이며,
근거 문서를 각 절에 링크했습니다.
공유용 웹 페이지 버전은 [14_SCANNER_TECH_MAP.html](14_SCANNER_TECH_MAP.html)(원본 보관)과
Claude 아티팩트(https://claude.ai/code/artifact/7319c966-bf7b-41a7-89be-ff47dfc944b1)에 있습니다.

> **이 프로젝트의 제1원칙**: *틀린 값을 자동으로 채우는 것(오답)이 빈칸으로 남기는 것보다
> 훨씬 나쁘다.* 빈칸은 검수자가 키 한 번으로 채우지만, 오답은 사람이 확인한 것처럼 중앙
> 시스템에 저장되기 때문입니다. 그래서 모든 기능의 최종 합격선은 "**오답 0**"이고,
> 정답을 늘리는 것은 그 다음입니다.

## 1. 한눈에 보는 지도

사진 한 장이 엑셀 값이 되기까지 거치는 단계와, 각 단계의 현재 상태입니다.

```
[촬영]──[① 라이브 촬영 유도]──[② 이미지 보정]──[③ 촬영 합격 판정]──[업로드]
                                                                        │
[검수 화면]──[⑥ 장당 품질 표시]──[⑤ 인식(채점)]──[④ 서버 품질 판정]────┘
```

| 단계 | 하는 일 | 상태 | 근거 |
|---|---|---|---|
| ① 라이브 촬영 유도 | 찍기 전에 화면에 테두리·기울기 안내를 띄움 | 🟡 구현 완료, 실기기 검증 전 | §4-5 |
| ② 이미지 보정 | 비스듬한 사진을 스캔본처럼 반듯하게 폄 | 🟢 완료 (38장 중 38장 성공) | §4-1 |
| ③ 촬영 합격 판정 | 못 쓸 사진이면 재촬영을 요구 | 🟢 완료 (화면 검증까지) | §4-2 |
| ④ 서버 품질 판정 | 업로드된 장마다 "정상/재촬영 권장/인식 불가"를 판정 | 🟢 완료 | §4-3 |
| ⑤ 인식(채점) | 체크 표시를 읽어 값을 채움 | 🟢 사진 오답 0 (빈칸 축소가 다음) | §5 |
| ⑥ 검수 화면 표시 | 검수자에게 장당 판정과 강행 여부를 보여줌 | 🟢 완료 | §4-4 |

**핵심 성과 (사진 38장, 정답표 대조):**

| 시점 | 보정 성공 | 자동 정답 | **자동 오답** | 검수자 몫(빈칸) |
|---|---|---|---|---|
| 개선 전 (사진 원본 그대로) | 0 / 38 | 10 | **11** | 430 |
| 현재 | **38 / 38** | **59** | **0** | 392 |

오답이 11 → **0**이 되었고(M3 달성), 자동 정답은 10 → 59로 늘었습니다.
남은 과제는 오답이 아니라 **검수자 몫(빈칸 392칸)**이며, 그 대부분은 어두운 바닥에서
촬영된 11명분입니다(§5-2).
스캔(복합기) 경로는 이 작업으로 **한 칸도 변하지 않았음**을 별도 측정으로 확인했습니다.

## 2. 이 스캐너가 쓰는 기술 — 쉬운 설명

| 기술 | 쉬운 비유 | 어디에 쓰나 |
|---|---|---|
| **OpenCV** (오픈소스 영상처리 라이브러리) | 사진을 다루는 만능 공구함 | 브라우저 안에서 실행됩니다. 서버로 사진을 보내기 *전에* 사용자 기기에서 보정 — 개인정보(학생 응답)가 밖으로 나가지 않는 구조의 핵심 |
| **외곽선 검출** (쿼드 검출) | 사진에서 "종이의 네 모서리"를 찾기 | 보정 1경로. 밝은 배경에선 잘 되지만 어두운 바닥·잘린 사진에서 실패 (38장 중 26장만 성공했었음) |
| **특징점 대조** (ORB) | 인쇄된 양식의 무늬를 **지문처럼 대조** — 빈 양식의 지문 3,000개를 미리 등록해두고, 사진에서 같은 지문을 찾아 겹침 | 보정 2경로(신규). 종이 테두리가 안 보여도 인쇄된 표·글자만으로 위치를 잡음. **38장 전부 성공** |
| **원근 워프** | 비스듬히 찍힌 사진을 **다림질하듯 펴서** 정면 스캔본 모양으로 | 보정의 마무리. 원본 해상도의 화소를 그대로 사용(축소본에서 펴면 오답이 생김 — 측정으로 확인) |
| **차분 채점** | "빈 양식보다 얼마나 더 진해졌는가"만 잼 | 인식의 핵심. 인쇄된 동그라미·표는 빈 양식에도 있으므로 빼고, 학생이 *더한* 잉크만 계산 |
| **4중 관문(게이트)** | 네 가지 시험을 **모두** 통과해야 자동 입력 | 오답 방지 장치. 하나라도 미달이면 값을 채우지 않고 검수자에게 넘김 |
| **문자 인식** (Tesseract OCR) | 손글씨 숫자 읽기 | 나이 칸의 숫자 전용 |
| **sharp** (서버 이미지 엔진) | 서버 쪽 사진 공구함 | 업로드된 장의 품질 측정, 인식용 래스터 처리 |

## 3. 다른 프로젝트에서 가져온 것 — 도입 이유와 측정된 효과

신분증·명함 스캐너 앱 수준의 인식률을 목표로, 비슷한 오픈소스 프로젝트들을 조사해
(라이선스까지 원문 확인) 다음을 도입했습니다. **외부 코드를 복사한 것은 없고 전부 아이디어를
자체 구현**했으며, 새로 추가된 외부 의존성은 0개입니다.

### 3.1 이미 도입되어 효과가 측정된 것

| 도입한 것 | 출처(참고 사례) | 도입 이유 | 기대 효과 → **측정된 효과** |
|---|---|---|---|
| **특징점 정합(ORB+RANSAC) 보정** | LearnOpenCV의 양식 정렬 기법 (튜토리얼 저장소가 무라이선스라 코드 복사 불가 → 자체 구현) | 종이 외곽선 검출이 38장 중 12장에서 실패. 신분증 스캐너들이 카드 테두리 대신 인쇄 내용으로 위치를 잡는 것과 같은 원리 | 보정 성공 26→**38/38**. 부산물로 "이 보정을 믿어도 되는가" 신호(잔차)까지 얻음 — 겉보기엔 성공인데 한 모서리가 192px 어긋난 보정 2건을 이 신호가 잡아 교체함 |
| **불합격 → 재촬영 요구** | 신분증 스캐너·은행 앱의 공통 UX | 보정 실패 시 **조용히 원본을 올리던** 기존 동작이 오답의 온상 (양면 보정 성공 학생은 평균 1.63칸 정답, 실패 학생은 0.10칸 — **16배 차이**) | 실패 장은 이유별 문구("네 모서리가 다 들어오게" 등)와 함께 차단. 강행하려면 명시적 클릭이 필요하고 그 사실이 기록에 남음 |
| **라이브 촬영 가이드** (테두리·기울기·거리 안내) | jscanify(MIT)의 실시간 하이라이트 패턴 + 상용 SDK·iOS/안드로이드 문서 스캐너의 공개된 UX 관행 | 찍고 나서 퇴짜 놓는 것보다 찍기 전에 잘 찍게 하는 것이 쌈 | 화면 짧은 변의 78%를 채우는 가이드 테두리(측정된 성공 분포의 한가운데), 회전·기울기 **방향까지** 안내("위쪽을 조금 낮춰주세요"). 검출 속도 실측 37ms/회 |
| **원본 해상도 워프** | (자체 측정에서 도출) | 축소본에서 편 실험판이 멀쩡하던 학생에게 오답 3개를 만듦 | 스파이크의 오답 회귀가 사라지고 최종 19정답/5오답 달성 |

## 4. 기능별 현황 카드 — 완성 스펙 · 테스트 방식 · 합격 기준

각 기능의 "완성"이 무엇인지(합격 기준), 어떻게 재는지(테스트 방식), 지금 어디까지 왔는지입니다.

### 4-1 이미지 보정 (이중 경로) — 🟢 완료

- **무엇**: 외곽선 검출(1경로)과 특징점 대조(2경로)를 함께 돌리고, 1경로 결과를 2경로가
  검증. 못 믿을 보정은 교체, 둘 다 실패하면 "보정 불가" 판정.
- **테스트 방식**: 학생 19명 사진 38장을 파이프라인에 태워 정답표와 대조. 제품에 실리는
  코드 그대로를 측정(재구현 금지 원칙).
- **합격 기준**: ① 자동 오답이 기존 경로(7건) 이하 ② 보정 성공 26장 이상 ③ 스캔 경로 무변화.
- **결과**: 오답 **5** ✅ · 보정 **38/38** ✅ · 스캔 무변화 ✅ (측정 기록: FEATURE_SPEC §7)

### 4-2 촬영 합격 판정 + 재촬영 요구 — 🟢 완료

- **무엇**: 보정이 거절한 사진은 업로드를 멈추고 이유별 문구로 재촬영 요구. "그대로
  사용(정확도 낮음)"은 명시적 버튼으로만 가능하며 기록에 남음. 일괄 업로드도 실패 장을
  이름 붙여 같은 관문을 거침.
- **테스트 방식**: 실제 브라우저에서 정상 사진/못 쓸 이미지를 넣어 전 경로 확인 + 자동 테스트.
- **합격 기준**: "조용히 원본 업로드" 경로가 코드에서 제거될 것. 강행이 기록될 것.
- **결과**: ✅ (정상 사진→보정 미리보기→"판정: 정상" 배지 / 못 쓸 이미지→재촬영 문구→강행 시 기록)

### 4-3 장당 품질 판정 (서버) — 🟢 완료

- **무엇**: 업로드 직후, 종이가 아직 눈앞에 있을 때 장마다 `정상 / 재촬영 권장 / 인식 불가`를
  판정. 업로드 화면·인식 결과·검수 화면이 **같은 판정기 하나**를 씀(두 곳이 다른 말을 하면
  안 되므로).
- **판정 규칙의 근거 (중요)**: 처음엔 "격자 개수·밝기"로 판정하려 했으나, 19명 데이터로
  검증하니 이 신호들은 **우연 수준의 분별력**이었고 밝기 규칙은 방향이 반대였습니다(좋은
  묶음을 걸러냄). 그래서 판정은 **보정 결과 메타데이터만** 사용하고, 이미지 수치는 참고
  정보로만 표시합니다. — *데이터가 초안을 기각한 사례이며, 문서에 그대로 남겼습니다.*
- **합격 기준**: 두 양식 모두 판정 반환, 인식 값에는 절대 개입하지 않을 것, 역순 스캔
  묶음에서도 판정이 물리적 장을 따라갈 것.
- **결과**: ✅ (역순 검증: 같은 업로드를 정/역순으로 두 번 인식시켜 판정이 장을 따라감을 실증)

### 4-4 검수 화면 표시 — 🟢 완료

- **무엇**: 검수자가 학생을 넘겨볼 때 장당 판정 배지와 "사용자 강행" 표시를 봄.
- **합격 기준**: 판정 없는 장(스캔 등)에는 아무것도 띄우지 않을 것 — 없음이 판정처럼 보이면 안 됨.
- **결과**: ✅ (렌더 테스트 18건)

### 4-5 라이브 촬영 유도 — 🟡 구현 완료, 검증 남음

- **무엇**: 카메라 화면에 가이드 테두리, 실시간 종이 인식(회색/주황/초록), 기울기·거리
  **방향付き** 안내, 3회 연속 합격 시 촬영 버튼 강조.
- **측정된 것**: 검출 1회 37ms(예산 내), 가이드 위치는 성공 사진 26장의 분포 한가운데로 설정.
- **남은 검증**: ① 실제 폰 카메라로의 확인(웹캠·실기기) ② 기울기 경고 문턱(4°, 7%)이 실제
  실패를 예보하는지 — 지금은 **잠정치**로 명시되어 있음.
- **합격 기준(미달)**: 실기기에서 초록 상태로 찍은 사진의 보정 성공률이 안내 없이 찍은
  것보다 유의하게 높을 것.

### 4-6 인식(채점) 엔진 — 🟡 사진 오답 5건

- **무엇**: 차분 채점 + 4중 관문. 이번에 **사진 전용 안전장치** 하나 추가 — "한 칸만 비고
  나머지가 온통 잉크"인 비정상 행은 거절(보정 밴드가 표 밖 글자에 얹힌 경우의 지문).
  이 장치는 **사진에만** 적용됩니다: 스캔에 켰더니 스캔 정답 4칸이 깎이는 것이 측정되어,
  출처(보정 메타 유무)로 구분해 스캔은 기존 그대로 둠.
- **합격 기준(전체)**: **오답 0** (절대), 그 다음 검수자 몫 최소화.
- **결과**: 사진 오답 11→**5**. 스캔 경로 기준선(자동 355/오답 7 — 노드 측정)과 바이트
  단위 동일 복원 확인. **아직 합격선(0) 미달** — 남은 5건은 §5.

### 5-2 어두운 바닥 묶음 문제 (검수자 몫이 큰 이유)

일부러 섞은 불량 샘플(어두운 마루 위 촬영) 학생들은 보정이 완벽해도 자동 입력이 거의 0칸
입니다. 종이 자체가 어둡게 찍혀 채점기가 신호를 못 믿기 때문입니다(정상 스캔 대비 잉크
비율 4~7배). 밝기 보정을 시험했더니 **표 구조 찾기에는 도움(102→131 필드)이지만 6개
페이지에선 역효과**였습니다 — 그래서 "항상 보정"이 아니라 **페이지별로 나은 쪽을 고르는**
설계가 다음 마일스톤에 들어 있습니다. 채점 자체는 원본 화소로만 합니다(보정본 채점은
정답까지 지워버림을 측정으로 확인).

### 5-3 그 밖의 열린 항목

### 용어 풀이

- **정답표**: 검수자가 손으로 확인한 19명분의 실제 답. 모든 "정답/오답" 수치의 기준.
- **오답(WRONG)**: 시스템이 자동으로 채운 값이 정답표와 다른 것. 이 프로젝트의 절대 금지선.
- **미확정(빈칸)**: 시스템이 확신이 없어 채우지 않고 검수자에게 넘긴 칸. 나쁘지 않음 — 오답보다 훨씬 낫다는 것이 이 제품의 설계 철학.
- **보정(워프)**: 비스듬한 사진을 정면 스캔본 모양으로 펴는 것.
- **정합**: 사진 속 양식의 위치를 기준 양식에 정확히 겹치는 것. 보정의 전제.
- **잔차**: 정합이 얼마나 어긋났는지의 크기(픽셀). 작을수록 좋음.
