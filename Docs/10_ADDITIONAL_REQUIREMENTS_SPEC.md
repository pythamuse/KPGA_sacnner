# ADDITIONAL_REQUIREMENTS_SPEC — 추가 요구사항 정의 및 처리 명세

본 문서는 현장 모바일 카메라 촬영 편의성과 PC 대량 스캔(PDF/이미지 번들) 파일 일괄 처리를 위한 추가 요구사항 및 확장 사양을 명세합니다.

---

## 1. 업로드 모드 및 시나리오 정의

사용자는 작업 시작 시 다음 두 가지 시나리오 중 하나를 선택하여 진행합니다.

### 1.1 [모바일/개별 촬영 모드] (시나리오 A)
주로 모바일 기기 카메라를 사용하여 종이 설문지를 실시간으로 촬영 및 업로드하는 방식입니다. 내부적으로 두 가지 세부 옵션을 제공합니다.

#### 옵션 A-1. [양면순차 업로드]
* **동작**: 학생 1명당 {선별검사지} 업로드 후, UI가 자동으로 {만족도설문} 업로드 칸으로 전환되어 한 세트씩 완결하여 등록합니다.
* **매칭**: 이미지 쌍이 즉시 매칭되어 인식 결과 확인 화면을 거쳐 엑셀에 행 단위로 저장됩니다.

#### 옵션 A-2. [단면 2회 업로드]
* **동작**: 스마트폰 카메라로 연속 촬영을 편하게 하기 위한 모드입니다.
  * 1단계: 선별검사지(앞면) N장을 연속으로 촬영하여 이미지 그룹 1로 업로드합니다.
  * 2단계: 만족도설문(뒷면) N장을 연속으로 촬영하여 이미지 그룹 2로 업로드합니다.
* **유효성 검증**:
  * **장수 검사**: 업로드 완료 시점(또는 분석 트리거 시점)에 선별검사지 이미지의 개수와 만족도설문 이미지의 개수가 일치하는지 검사합니다. 개수가 다르면 분석을 진행하지 않고 즉시 **경고 알림창**을 출력합니다.
  * **안내 사항 출력**: 업로드 및 촬영 화면에 아래 경고 문구를 명확하고 눈에 띄게 노출해야 합니다.
    > ⚠️ **주의**: 각각 촬영/업로드 시 학생별 촬영 순서(일련번호)가 완벽하게 일치해야 데이터가 정확히 매칭됩니다.
* **매칭**: 이미지 그룹 1의 i번째 이미지와 이미지 그룹 2의 i번째 이미지를 동일 학생 세트로 묶어 순서대로 처리합니다.

---

### 1.2 [PC/일괄 스캔 모드] (시나리오 B)
일괄 스캐너를 이용해 하나의 파일에 N명의 설문지가 묶여있는 대용량 파일 2개를 업로드하는 방식입니다.

* **동작**:
  * **선별검사지 파일 1개** (N개 페이지로 구성된 PDF 또는 다중 이미지 티프 등) 업로드.
  * **만족도설문 파일 1개** (N개 페이지로 구성된 PDF 또는 다중 이미지 티프 등) 업로드.
* **파일 형식 확장**:
  * 기존 이미지 형식(JPG, PNG) 외에 **PDF 파일(.pdf)**을 공식 지원합니다.
* **유효성 검증**:
  * **페이지 수 검사**: 분할된 선별검사지 총 페이지 수와 만족도설문 총 페이지 수가 일치하지 않으면 분석을 거부하고 경고 알림창을 띄웁니다.
  * **순서 경고**: 모바일 단면 2회 업로드와 마찬가지로 파일 업로드 영역에 "두 파일 내의 학생 페이지 순서가 동일해야 올바르게 매칭됩니다"라는 안내를 노출합니다.
* **매칭**:
  * PDF의 경우 백엔드에서 각 페이지를 이미지로 변환 및 분할합니다.
  * 선별검사지 PDF의 i번째 페이지에서 추출된 데이터와 만족도 PDF의 i번째 페이지에서 추출된 데이터를 동일 학생의 세트로 묶어 엑셀의 동일 행에 순차적으로 기입합니다.

## 2. UI/UX 화면 설계 변경사항

### 2.1 메인 진입 화면
- 기존의 "새로 작성 시작" 클릭 시 바로 업로드로 가는 대신, **[업로드 방식 선택]** 모달 또는 라디오 그룹을 제시합니다.
  1. **개별/순차 촬영 (모바일 추천)**
     - [양면순차 업로드]
     - [단면 2회 업로드 (연속 촬영)]
  2. **일괄 스캔 파일 업로드 (PC 추천 - PDF 지원)**

### 2.2 단면 2회 / 일괄 스캔 업로드 UI 구성
- **두 개의 대형 업로드 박스** 제공:
  - 1번 박스: `선별검사지(앞면) 일괄 업로드 (PDF 또는 다중 이미지)`
  - 2번 박스: `만족도조사(뒷면) 일괄 업로드 (PDF 또는 다중 이미지)`
- **안내 메시지 뱃지**:
  - "앞면 N장 / 뒷면 M장 업로드됨" 상태 표시기.
  - 장수 불일치 시 붉은색 경고 박스로 "장수가 불일치합니다 (앞면: N장, 뒷면: M장). 누락된 사진이 없는지 확인해주세요." 출력.
  - "※ 주의: 각각 업로드 시 파일의 정렬 순서가 학생별로 완벽히 일치해야 합니다." 경고 문구 상시 노출.

## 3. 백엔드 처리 로직 확장 (PDF 및 페이지 분할)

### 3.1 PDF -> Image 변환 파이프라인
1. PC 스캔 모드로 PDF 업로드 접수.
2. 백엔드 서버(Node.js)에서 PDF의 각 페이지를 고해상도(최소 150 DPI 이상) 이미지 파일로 분할 변환합니다.
3. 분할된 이미지 파일들은 `tmp/jobs/{jobId}/uploads/cagi/page_001.png` 및 `tmp/jobs/{jobId}/uploads/satisfaction/page_001.png` 형태로 네이밍하여 순서를 보존합니다.
4. 이후 단계는 기존 단일 이미지 인식 모듈(`recognizeStudentForms`)을 페이지 순서대로 루프를 돌며 일괄 호출합니다.

### 3.2 이미지 묶음 순서 매칭
- 단면 2회 업로드로 제출된 개별 이미지 파일들은 파일명 정렬 또는 업로드된 시간 순서대로 정렬하여 인덱스를 부여하고, `i`번째 cagi 이미지와 `i`번째 satisfaction 이미지를 1대1 매핑합니다.
