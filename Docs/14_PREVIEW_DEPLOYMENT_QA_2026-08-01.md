## 1. 테스트 개요

- 대상: PR [#2](https://github.com/pythamuse/KPGA_sacnner/pull/2) (`feature/adult-cpgi-track` → `main`)
- 배포 URL: `https://kpga-sacnner-git-feature-adult-c-9fb4f9-amuseedu-3015s-projects.vercel.app`
- 방법: 실제 Chrome 브라우저를 직접 제어해 배포된 사이트에 접속, 청소년/성인 두 트랙을 각각 새 작업 생성 → 업로드 → 인식 → 검수 → 저장 → 다운로드까지 실제로 실행하고 네트워크 응답·콘솔 로그를 확인했다.

## 2. 정상 확인된 기능

### 2.1 트랙 선택 및 성인(CPGI) 흐름

- 첫 화면의 "청소년 (CAGI)" / "성인 (CPGI)" 대상 선택 카드가 배포본에서도 정확히 렌더링되고, 성인을 선택하면 "성인 양식은 아직 자동 체크마크 인식이 준비되지 않아, 검수 화면에서 값을 직접 입력해야 합니다." 안내가 표시된다.
- `POST /api/jobs`에 `track: 'adult'`를 넘기면 상단 상태 표시가 "성인 (CPGI)"로 바뀌고, 다운로드 카드 라벨도 `양식_성인도박문제선별검사_CPGI.xlsx` / `성인예방교육만족도.xlsx`로 정확히 표시된다.
- 이미지 업로드 → `/api/recognize` 호출 시 성인 트랙은 ROI 인식 없이 전 항목 `low confidence` 수동 입력 draft를 반환하고, 검수 화면에 학교유형·학년 없이 연령대(20~70대 select)·성별만 표시되며, CPGI 01~09는 0~3, 문항1~10은 전부 0~4로 정확히 렌더링됨을 확인했다.
- 값을 채우고 저장하면 `POST /api/students`가 200을 반환하고, 학생 목록에 "60대 / 남 / 엑셀 반영 완료"가 정상적으로 표시됐다(단, 아래 3.1 문제로 인해 이 성공이 영구적이지 않았다).

### 2.2 청소년(CAGI) 흐름 회귀 확인

- 청소년 트랙으로 새 작업을 만들어 업로드~검수까지 진행한 결과, 화면 구성(학교유형·학년 필드 포함, CAGI 01~09 및 문항1~10 라벨)이 이번 변경 이전과 동일하게 동작함을 확인했다(회귀 없음).
- 브라우저 콘솔에 에러가 전혀 기록되지 않았다(`read_console_messages` 결과 0건).

## 3. 발견된 문제

### 3.1 [Critical] Vercel 서버리스 인스턴스 분산으로 인해 저장된 작업 세션이 유실될 수 있음

**재현 절차:**

1. 배포본에서 새 작업(청소년 또는 성인 무관)을 생성하고 이미지 2장을 업로드한다.
2. `POST /api/recognize` — 정상적으로 200과 draft를 받는다.
3. 몇 초~수십 초 뒤(검수 화면에서 값을 입력하는 정도의 시간) `POST /api/students`를 호출하면 다음과 같이 실패한다.

   ```json
   { "error": "유효하지 않은 작업 세션입니다." }
   ```
   상태 코드 404. 같은 요청을 5회 재시도해도 계속 404.

4. 더 심각하게는, **저장이 실제로 성공했던 작업**(성인 트랙 테스트, `POST /api/students` 200 응답 확인, 학생 목록에 정상 반영됨)도 몇 분 뒤 `GET /api/download?jobId=...`를 호출하면 동일하게 404 `유효하지 않은 작업 세션입니다`를 반환했다. 즉 **저장에 성공했다는 화면 표시를 본 뒤에도, 실제 다운로드 시점에 해당 작업 전체가 사라져 있을 수 있다.**

**원인 추정:**

`src/lib/storage/jobStore.ts`는 작업 세션을 인메모리 `Map`(`activeJobs`)에 두고, 보조 수단으로 `os.tmpdir()/kpga-sacnner/jobs/{jobId}/session.json` 파일에도 저장한다(`getJobSession` → 메모리에 없으면 파일에서 복구). 이 방식은 **같은 서버리스 함수 인스턴스가 재사용될 때만** 유효하다. Vercel은 요청을 여러 함수 인스턴스로 분산시키며 각 인스턴스의 `/tmp`는 서로 공유되지 않는다. 작업을 처음 만든 인스턴스가 아닌 다른 인스턴스가 이후 요청(인식 재시도, 저장, 다운로드)을 처리하면 그 인스턴스의 로컬 디스크에는애초에 해당 `jobId`의 파일이 존재한 적이 없으므로, `session.json` 기반 복구조차 불가능해 무조건 404가 된다.

`04_OCR_FORM_RECOGNITION_SPEC.md`(2026-07-30 메모)에서 이미 이 위험을 인지하고 `getJobSession()`/`ensureJobSession()`을 통한 파일 기반 복구를 도입했지만, 이번 실측 결과 **그 완화책만으로는 부족하다**는 것이 실제 배포본에서 확인됐다. 특히 `/api/students`, `/api/download`, `/api/recognize`(재호출) 모두 여전히 로컬 `/tmp` 파일 존재 여부에 의존하므로, "복구할 파일 자체가 이 인스턴스에 없는" 상황은 근본적으로 해결되지 않는다.

**영향도:** 이 앱의 핵심 목적이 "학생별 응답을 모아 최종 엑셀 다운로드"이므로, 다운로드가 비결정적으로 실패할 수 있다는 것은 실사용에서 강사가 여러 학생을 입력한 뒤 마지막에 다운로드를 시도했을 때 전체 작업을 잃을 수 있는 치명적 리스크다. 로컬 개발 서버(단일 Node 프로세스)에서는 이 문제가 절대 재현되지 않기 때문에 그동안 발견되지 않았던 것으로 보인다.

**권장 조치(우선순위 높음, 별도 작업 필요):**

- 작업 세션(JobSession)과 업로드/작업 파일을 로컬 `/tmp`가 아니라 인스턴스 간 공유되는 외부 저장소로 옮긴다. 예: Vercel Blob Storage(파일), Vercel KV/Upstash Redis 또는 Postgres(세션 메타데이터).
- 최소한의 완화책으로, 세션 유실이 감지되면(예: 저장 시 404) 사용자에게 "서버 인스턴스 문제로 작업을 잃어버렸을 수 있습니다. 처음부터 다시 진행해주세요" 같은 명확한 안내와 함께, 검수 화면에 입력해둔 값을 잃지 않도록 로컬(localStorage)에 draft를 임시 보관하는 방안도 고려할 수 있다. 다만 이는 근본 해결책이 아니다.

### 3.2 [Medium] 성인 트랙 검수 화면의 "연령대" crop 미리보기가 청소년 좌표를 사용함

검수 화면에서 신뢰도가 `high`가 아닌 `basic.age` 필드는 트랙과 무관하게 항상 원본 이미지 crop 미리보기(`GET /api/uploads/crop?...&field=basic.age`)를 시도한다(`RecognitionReview.tsx`의 `renderFieldCropPreview`). 그런데 `src/app/api/uploads/crop/route.ts`의 `findFieldRegion()`/`findChoiceGroup()`은 트랙 구분 없이 `cagiTemplate`/`satisfactionTemplate`(둘 다 청소년 전용 좌표)에서만 영역을 찾는다. 성인 트랙에는 별도 ROI 좌표가 아예 정의되어 있지 않으므로, 성인 이미지에 대해 "연령대" crop을 요청하면 **청소년 양식 기준 좌표로 성인 이미지의 엉뚱한 영역을 잘라서** 보여주게 된다(요청 자체는 200으로 성공해 오류처럼 보이지 않는다는 점이 더 위험하다).

**권장 조치:** 성인 ROI 좌표가 실제로 정의되기 전까지는, `track === 'adult'`일 때 `basic.age` crop 미리보기 자체를 표시하지 않도록 `RecognitionReview.tsx`에서 막는 것이 좋다(현재도 성인 트랙의 다른 필드는 `candidates`가 비어 있어 crop을 시도하지 않는데, `basic.age`만 예외 처리되어 있어 이 필드에서만 발생한다).
