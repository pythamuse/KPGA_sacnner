# 27. ROI 오정렬 확정 원인 및 수정 - 파일 선택 업로드에도 원근보정 적용

관련 문서: [[26_RECOGNITION_ARCHITECTURE_REDESIGN_OPTIONS]]에서 A안(자체 처리)으로 방향을 확정한 뒤, 실제 ROI 확인 스크린샷으로 원인을 확정한 결과.

## 확정된 원인 (실제 크롭 이미지로 확인)

사용자가 보내준 "ROI 확인" 크롭들을 보면, 저신뢰도(낮음)라서 그런 게 아니라 **좌표 자체가 완전히 다른 위치를 찍고 있다**:

- `basic.schoolType`(학교유형) 크롭 — 체크박스가 아니라 CAGI 설문 상단 안내 문구("~안 자신이 이런 경험들을...")가 찍힘.
- `cagi.q04` 크롭 — "4~6회 7회이상 있다 있다" 텍스트가 찍힘. 이건 4번 문항이 아니라 **8~9번 문항의 보기 라벨**이다.
- `cagi.q07`, `cagi.q08`, `cagi.q09` 크롭 — "(전화, 내방 등)... 집·이용 동의서를" 텍스트가 찍힘. 이건 CAGI 응답 표가 아니라 **페이지 맨 아래 개인정보 수집·이용 동의서 영역**이다.

반면 만족도조사(`satisfactionTemplate`) 쪽 크롭 대부분(문항2~6, 8~10)은 실제 응답 표의 해당 행을 비교적 정확히 잡고 있다. 즉 문제는 **CAGI 이미지 하나의 페이지 경계 추정**에 집중되어 있고, 문항 아래로 갈수록 오차가 누적되는 패턴이다(위쪽 `basic.gender`는 74% 신뢰도로 맞았고, 아래로 갈수록 완전히 다른 섹션을 찍는다) — `detectContentBounds`/`detectFrameBounds`가 페이지 실제 높이보다 짧은 영역을 "종이 경계"로 오판했을 때 나타나는 전형적인 패턴이다.

## 왜 이 사진에서만 이 정도로 심하게 틀렸나

이번 테스트는 **"파일 선택"으로 이미 촬영된 사진을 직접 업로드**한 경로였다(`컴퓨터 환경에서 아까 첨부한 이미지로 테스트`). [[21_MOBILE_CAPTURE_PERSPECTIVE_CORRECTION_DESIGN]]에서 만든 원근보정(OpenCV로 문서 사각형 검출 → 투영변환으로 정면 이미지로 보정)은 **카메라 실시간 촬영 흐름에만** 적용되도록 의도적으로 범위를 좁혔었다(그 문서 3.2절: "파일 선택 업로드 경로는 1차 범위에서 제외한다... 필요해지면 같은 보정 모듈을 파일 선택 업로드 흐름에도 재사용"). 즉 이번에 오정렬이 심하게 난 사진은 **원근보정을 한 번도 거치지 않은 원본**이 그대로 서버 인식 파이프라인에 들어간 것이다. 카메라 촬영 경로였다면 보정 후 업로드됐을 것이고, 결과가 달랐을 가능성이 크다.

## 수정 방향

이미 만들어 검증된 `src/lib/documentScanner/loadOpenCv.ts`, `src/lib/documentScanner/perspectiveCorrect.ts`의 보정 파이프라인(사각형 검출 → 투영변환 → 보정 미리보기 확인/재선택)을 **"파일 선택"으로 선택한 이미지 파일에도 동일하게 적용**한다.

`src/components/ImageUploadPanel.tsx`의 `handleSequentialFileChange`(개별/순차 모드의 "파일 선택")에서:

1. 사용자가 파일을 선택하면 즉시 업로드하지 않고, 파일을 이미지로 로드해 캔버스에 그린 뒤 카메라 캡처와 동일하게 `loadOpenCv()` → `detectDocumentQuad()` → 성공 시 `warpToRectangle()`을 시도한다.
2. 사각형 검출에 성공하면 보정된 이미지를 `correctionPreview`와 같은 방식으로 미리보기 확인("이대로 사용"/"다시 선택") 단계를 거친 뒤 업로드한다.
3. 실패(사각형 미검출, opencv 로드 타임아웃 등)하면 지금처럼 원본 파일을 그대로 업로드한다(항상 폴백, 기능 저하 없음 — 이 원칙은 [[21_MOBILE_CAPTURE_PERSPECTIVE_CORRECTION_DESIGN]]과 동일하게 유지).
4. "1단계/2단계 묶음" 일괄 업로드(`handleBatchFileChange`, PDF 변환 제외)에도 같은 보정을 적용할지는 별도 검토 — 이번 범위는 개별/순차 모드의 "파일 선택" 단일 이미지 업로드로 한정한다(사용자가 재현한 시나리오와 일치, 일괄 업로드는 장수가 많아 매번 확인 UI를 거치면 번거로울 수 있어 후속 과제로 남긴다).

## 한계

- 학교유형·CAGI 04·07~09 외 나머지 CAGI 문항들(낮음/동점 점수)의 오차가 순수히 이 페이지-경계 오정렬 때문인지, 아니면 체크 표시 신호 자체도 약한 것인지는 원근보정 적용 후 재테스트해야 완전히 분리해서 판단할 수 있다.
- 이번 수정도 실기기 실제 사진으로 재테스트가 필요하다.
