# 작업 B — 연령대 OCR 전처리 (2026-08-20~)

연령대는 6페이지 **전부 빈칸**이다. 워커 교착은 이미 해소됐고 OCR은 매 페이지 실제로 실행되지만, 손글씨 숫자를 읽지 못한다.

상위 문서: [Docs/00_PRD.md §10-1](../Docs/00_PRD.md) — 자동 입력률이 제품 성립 조건이다.
선행 스레드: [[MEASUREMENT_RENDER_PARITY_2026-08-19]] 사이클 4, [[OCR_ANCHORED_ROW_DETECTION]]

---

## 1. 배경 — 반드시 먼저 읽을 것

### 1.1 이미 해결된 것 (다시 건드리지 마라)

콜드 스타트마다 5MB 영문 모델을 CDN에서 받다가 6초 예산을 넘기고, 그 뒤 모든 페이지가 `worker_pending` 가드에 걸리던 교착은 **`langPath` 지정으로 해소됐다**(`eng.traineddata`가 `src/lib/recognition/assets/`에 있고 배포 번들에 포함된다). 진단 문구가 `worker was still initializing`에서 실제 판정 결과로 바뀐 것이 그 증거다.

### 1.2 확정된 실패 지점

임시 계측으로 실제 OCR 출력을 확인했다.

| 페이지 | 정답 | OCR 텍스트 | confidence |
|---|---|---|---|
| p1 | 14 | **19** | 53 |
| p2 | 14 | **4** | 43 |
| p3 | 15 | (빈 문자열) | 0 |

`MIN_DIGIT_CONFIDENCE = 60`이 이 오답들을 막고 있다. **이 문턱을 낮추면 p1에 `19`가 자동 입력된다 — 절대 금지.**

### 1.3 해상도 가설은 기각됐다

`REAL_SCAN_RENDER_SCALE`을 1.5 / 2.0 / 3.0으로 올려 측정했으나 **셋 다 6/6 빈칸**이었다. 크롭을 키우는 방향은 답이 아니다.

### 1.4 확정된 원인 — 전처리

OCR 입력 이미지를 저장해 눈으로 확인한 결과 두 가지가 보였다.

1. **인쇄된 칸 밑줄이 크롭에 그대로 포함된다.** `getAgeDigitsRect`가 상하 12%만 잘라내는데 그것으로는 제거되지 않는다. Tesseract가 이 선을 글자의 일부로 보거나 레이아웃 분석이 무너진다.
2. **`threshold(190)` 고정 이진화가 얇은 획을 부순다.** p3의 `5`가 점 몇 개로 흩어져 빈 문자열이 됐다.

크롭 실측: `digitsCrop = 68×16px` (배포본 래스터 기준). 이를 4배 확대(최소 320×96)해 OCR에 넣는다.

## 2. 목표와 합격 기준 (착수 전 확정)

`REAL_SCAN_RENDER_SCALE` 기본값(배포본 래스터)에서 6페이지를 측정한다. 정답은 `14, 14, 15, 15, 12, 13`이다.

| # | 기준 |
|---|---|
| **필수** | **`WRONG = 0`.** 틀린 나이가 자동 입력되면 즉시 기각 |
| **필수** | 전체 `CORRECT ≥ 102` (현재 기준선) |
| **목표** | `basic.age` 자동 입력 **6칸 중 3칸 이상** 정답 |

빈칸은 검수자의 키 입력 한 번이지만, 틀린 나이는 사람이 확인한 것처럼 저장된다.

## 3. 방향 제안 (하나 이상을 조합하고 이유를 문서에 남길 것)

### 방향 1 — 인쇄 밑줄 제거 (권장, 근거가 가장 명확)

이미 `subtractTemplateDigits`가 빈 양식 기준 차감을 하고 있다. 그것으로 밑줄이 지워지지 않는다면:

- 크롭 안에서 **가로로 길게 이어진 어두운 행**(폭의 60% 이상)을 찾아 흰색으로 지운다. 숫자 획은 그렇게 길지 않다.
- 또는 밑줄 위치를 찾아 그 아래를 잘라낸다.

### 방향 2 — 적응형 이진화

`threshold(190)` 고정값 대신 크롭의 밝기 분포에서 문턱을 계산한다(Otsu 또는 백분위 기반). 흐린 스캔에서 획이 살아난다.

### 방향 3 — Tesseract 파라미터

숫자 전용으로 이미 영문 워커를 쓰고 있으나, `tessedit_char_whitelist = 0123456789`와 `tessedit_pageseg_mode`를 손글씨 두 자리에 맞게 조정하면 오독이 줄 수 있다.

## 4. 제약 (위반 시 되돌림)

1. **`MIN_DIGIT_CONFIDENCE`를 낮추지 마라.** 지금 오답을 막고 있는 유일한 방어선이다. 문턱을 낮춰 숫자를 올리는 것은 이 작업의 실패다.
2. **소유 파일**: `src/lib/recognition/ocrTextLines.ts`. **이 파일 외의 소스 파일을 수정하지 마라** — 다른 작업이 `basicCheckboxDetection.ts` · `detectCheckmarks.ts` · `markDensity.ts`에서 동시에 진행 중이다. 크롭 영역 조정이 필요하면 `getAgeDigitsRect`(`detectCheckmarks.ts`)를 고치는 대신 `ocrTextLines.ts` 안에서 받은 크롭을 추가로 좁혀라.
3. **`tests/real-scan-measure.test.ts`, `local-scans/`, `templates/`, `src/lib/recognition/assets/`를 수정하지 마라.**
4. 필드명이나 페이지 번호로 분기하지 마라.
5. `npm test`·`npm run build` 통과. 특히 `tests/age-ocr.test.ts`가 통과해야 한다. 버전 마커는 갱신하지 마라(병합은 지휘자가 한다).
