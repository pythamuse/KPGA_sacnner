## 2. 남은 문제 A — 만족도 문항1의 템플릿 Y좌표가 틀렸다 (명백한 버그)

검수 화면에서 문항1의 crop은 `아니오 / 예` 헤더와 그 아래 동그라미를 보여준다. 이건 **문항1의 표가 아니라 문항2~6 표**다. 문항1은 `없음/1회/2회/3회이상` 4지선다 별도 표에 있다.

빈 양식 fixture(`tests/fixtures/blank-form/satisfaction-blank.png`)로 실측했다:

| 항목 | 실측값 | 현재 템플릿 | 판정 |
|---|---|---|---|
| **문항1 응답 행 중심 y** | **0.2852** | **0.43** | **오차 0.145 — 완전히 다른 표를 가리킴** |
| 문항1 표 괘선 y | 0.2207(표 상단), 0.2676(헤더/응답 경계), 0.3027(표 하단) | — | |
| 열 중심 x | 0.6911, 0.7712, 0.8515, **0.9419** | 0.691, 0.772, 0.852, **0.933** | 앞 3개는 정확, 4번째만 0.009 어긋남 |

**X좌표는 거의 정확한데 Y만 틀렸다.** 참고로 실측한 만족도 q02(다른 표의 첫 행) 중심이 0.4293인데, 템플릿의 0.43이 바로 그 위치다 — 즉 **다른 표의 행 좌표가 문항1에 잘못 들어간 것**으로 보인다.

이 상태에서는 `buildSatisfactionQuestionOneDetection`이 y=0.43 주변만 탐색하므로, 아무리 검출을 잘해도 구조적으로 옳은 표를 찾을 수 없다. 화면상 `행 검출`로 표시되지만 **엉뚱한 표를 성공적으로 검출한 것**이라 더 위험하다(실패보다 나쁨 — 사용자가 검출 성공으로 오인함).

## 3. 남은 문제 B — 기본정보 4개는 구조적으로 격자 검출 대상이 아니다

`연령대·성별·학교유형·학년`은 이번 배포 후에도 전부 `위치 특정 실패 (구역 전체 표시)`다. 원인은 검출 실패가 아니라 **애초에 검출 대상에 포함되지 않은 것**이다. `tableGridDetection.ts`의 `buildCagiGridDetection`을 보면:

```ts
const basicGroups = getGroups(cagiTemplate.choiceGroups, ['basic.gender','basic.schoolType','basic.grade']);
return {
  overrides: result.overrides,          // ← q01~q09만 들어있음
  fieldRects: { ...mapGroupsToUnionRects(image, basicGroups), ... },  // ← crop 표시용일 뿐
};
```

`basicGroups`는 **crop 좌표(`fieldRects`)에만 기여하고 `overrides`(실제 인식 좌표)에는 절대 들어가지 않는다.** 따라서 항상 고정 템플릿 좌표로 폴백한다.

기본정보 표는 CAGI 상단의 3행짜리 실제 표지만, 셀 구조가 `좌측라벨|값|우측라벨|값`의 비정형 2차원이라 현재의 "N행 × 균등 M열" 격자 검출 모델에 맞지 않는다. 따라서 **기본정보 표의 행 괘선만 검출해 Y를 보정하고, X는 템플릿 값을 그대로 쓰는** 별도 경로가 필요하다.

## 4. 남은 문제 C — 연령대 숫자 OCR 미구현

crop 위치는 이제 올바른 영역(`만 [ ] 세`)을 가리키지만 값이 비어 있다. §2.2·§9.1에서 계속 "미구현"으로 기록돼 온 그대로다. 이미 `tesseract.js`가 서버에 통합돼 있고([[OCR_ANCHORED_ROW_DETECTION]]), crop 좌표도 정확해졌으므로 이제 구현 가능한 조건이 갖춰졌다.

## 5. 문제 아님 — 의도된 안전장치

낮은 신뢰도 11개 중 상당수(CAGI 04·05·08, 만족도 1·7·8·9·10)는 `requiresHighVisualConfidence` 목록에 있어 **35% 이상이 아니면 medium 승격이 금지**된다. 빈발 응답 편향으로 인한 위험한 오확정을 막으려 의도적으로 넣은 장치이므로(§9.2) 이번에도 건드리지 않는다.

## 6. 작업지시서 (Codex, Luna-Max)

**§2를 최우선으로 하되, A·B·C를 각각 독립적으로 커밋 가능하게 진행할 것.**

### A. 만족도 문항1 좌표 수정 (최우선, 명백한 버그)

1. `src/lib/recognition/roiTemplates.ts`의 `satisfaction.q01`:
   - y를 `0.43` → **`0.2852`** 로 수정.
   - `satisfactionFrequencyXs`의 마지막 값을 `0.933` → **`0.9419`** 로 수정(앞 3개 `0.691, 0.772, 0.852`는 실측과 일치하므로 유지).
2. 이 값들은 빈 양식 fixture 실측치다. **수정 후 `tests/blank-form-detection.test.ts`에 문항1의 검출된 행 중심이 0.2852 ±0.01 안에 드는지 확인하는 assertion을 추가**할 것. 지금 테스트는 source가 `fixed`가 아닌지만 보므로, **엉뚱한 표를 검출해도 통과한다** — 그게 이 버그를 놓친 이유다. 좌표까지 검증해야 한다.
3. 같은 취약점이 다른 필드에도 있는지 확인: `tests/blank-form-detection.test.ts`의 좌표 검증이 **CAGI Q1~Q9·만족도 Q1~Q10 전부**에 대해 실측 기준값과 대조하도록 확장한다. 기준값은 [[BLANK_FORM_GROUND_TRUTH_MEASUREMENT]] §2 표와 위 §2 표를 쓴다.

### B. 기본정보 행 좌표 보정 (§3)

4. CAGI 상단 기본정보 표의 **행 괘선만** 검출해 `basic.gender`/`basic.schoolType`/`basic.grade`의 Y를 보정하는 경로를 추가한다. X는 템플릿 값을 그대로 쓴다(열 구조가 비정형이므로 건드리지 말 것).
5. 검출 실패 시에는 지금처럼 안전하게 폴백하고, 성공 시 `recognitionCropSource`가 `'row'`(또는 적절한 값)로 표시되게 한다. 빈 양식 fixture에서 이 3개 필드가 `'fixed'`가 아니게 되는지 테스트로 확인.

### C. 연령대 숫자 OCR (§4)

6. `basic.age`의 crop 영역(`만 [ ] 세`의 숫자 칸)에 대해 tesseract 숫자 인식을 수행해 `draft.basic.age`를 채운다. 반드시 지킬 것:
   - **숫자만 허용**(`tessedit_char_whitelist`), 결과가 1~2자리 정수가 아니면 값을 채우지 않는다.
   - PRD 6.2의 허용 범위(**1~20**)를 벗어나면 채우지 않는다.
   - OCR 실패·타임아웃 시 조용히 빈 값으로 두고 절대 예외를 던지지 않는다([[OCR_ANCHORED_ROW_DETECTION]]에서 확립한 규칙).
   - **전체 요청 시간 예산을 초과하지 않도록** 기존 `ocrDeadlineAt` 메커니즘을 그대로 사용할 것. 19쌍 배치에서 페이지마다 OCR이 추가되므로, 예산을 넘기면 건너뛰어야 한다(184초 사고 재발 방지).
   - 자동 확정하지 말고 medium 이하 신뢰도로 두어 검수를 거치게 한다.
