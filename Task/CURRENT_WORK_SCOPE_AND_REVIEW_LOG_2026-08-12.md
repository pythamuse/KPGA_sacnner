## 2. 이번 작업에서 하려던 일

1. 고정된 양식인데도 기본정보, CAGI 후반 문항, 만족도 7~10번에서 반복되는 잘못된 ROI(관심영역) 위치 판정을 재현 가능한 방식으로 분리한다.
2. "그럴듯한 잘라내기"나 응답 빈도만으로 자동 입력하지 않고, 행과 열 구조가 확인된 경우에만 자동 입력하도록 안전 기준을 강화한다.
3. 모든 문항을 하나의 좌표 보정 규칙으로 처리하지 않고 다음 영역별로 인식 규칙을 분리할 준비를 한다.
   - 기본정보: 연령, 성별, 학교유형, 학년
   - CAGI 1~7번 일반 응답 행
   - CAGI 8~9번 별도 응답 행
   - 만족도 1번 횟수 문항
   - 만족도 2~6번 이분형 문항
   - 만족도 7~10번 5지선다 문항
4. 검수 화면에서 자동 인식, 미확정, 후보 거절, 행 대체 사용 여부와 근거를 확인할 수 있도록 진단 정보를 보존한다.
5. 좌표 인식 문제와 별개인 저장 API의 비 JSON 응답 및 XLSX 손상 문제를 분리해 추적한다.

### 3.2 코드와 작업 트리 상태

- `src/lib/recognition/detectCheckmarks.ts`에 미커밋 변경이 존재하는 상태를 확인했다.
- 해당 변경은 행 대체 후보를 양식 호환성 기준으로 거절하고, 거절된 후보를 검수 진단에 남기려는 방향으로 보인다.
- 이 기록 작성 시점에는 그 변경의 빌드, 자동 테스트, 실제 PDF 재시험, 커밋 또는 배포를 수행하지 않았다.

따라서 위 코드는 "현재 검토한 미검증 구현 방향"이지, 이 문서에서 효과가 확인된 수정이라고 기록하지 않는다.

### 3.3 사용자 제공 검수 화면

- 값이 입력돼 보이는 항목 중 일부는 사용자가 다음 학생 검수로 진행하기 위해 직접 입력한 값이다.
- 따라서 화면의 값 자체를 자동 인식 성공 근거로 사용하지 않는다.
- 자동 인식 여부는 `자동 인식`, `낮음`, `미확정`, 후보 거절 사유, ROI 오버레이, 진단 메시지를 기준으로 판단한다.

## 4. 테스트로 확인된 사실

1. 빈 양식의 기준 좌표가 대체로 맞더라도, 실제 스캔에서는 모든 필드가 같은 방식으로 정렬되거나 같은 격자 구조를 갖지 않는다.
2. CAGI 1~7번과 만족도 2~6번 중 일부는 검증된 격자 및 마크 근거를 바탕으로 자동 입력 후보가 될 수 있다.
3. CAGI 8~9번, 만족도 7~10번, 기본정보는 같은 규칙으로 처리할 때 후보 거절, 행 대체, 불충분한 선 검출, 열 구조 미검증이 반복된다.
4. 연령대는 ROI가 확보되어도 OCR 워커 초기화 또는 제한 시간 문제로 값 추출이 완료되지 않는 사례가 있다. 이는 체크 마크 인식 실패와 다른 문제다.
5. PDF 렌더링 과정에는 JBIG2 디코딩 및 보정 엔진 사용 불가 경고가 발생한 이력이 있다. 이는 페이지별 이미지 품질/정렬 문제와 연결될 수 있으나, 모든 좌표 오류의 단일 원인으로 확정되지 않았다.
6. 여러 학생을 저장한 뒤에는 요청 본문 증가 및 비 JSON 응답을 JSON으로 파싱하려는 흐름이 별도로 실패했다. 이는 좌표 인식 품질과 별개로 수정해야 하는 저장 계약 문제다.

## 5. 아직 검증되지 않은 가정

1. 기본정보의 낮은 성공률이 단순 좌표 오차가 아니라, 서로 다른 행과 열 구조를 하나의 공통 격자 탐지로 해석한 결과일 수 있다.
2. CAGI 8~9번과 만족도 7~10번의 반복 실패는 일반 문항과 다른 행 높이, 열 개수, 병합 셀, 인접 라인 때문에 발생할 수 있다.
3. PDF의 JBIG2 경고가 특정 페이지의 래스터 품질 저하를 일으켜 선/마크 탐지에 영향을 주었을 수 있다.
4. 응답 빈도 가중치는 동률 해소 보조로는 쓸 수 있으나, 잘못된 ROI 또는 미검증 격자를 정답으로 바꾸는 근거가 될 수 없다.

위 항목은 다음 테스트에서 반증 또는 확인해야 한다. 구현 근거로 고정하지 않는다.

## 6. 현재 단계에서 하지 않기로 한 것

- 검증되지 않은 행 대체 후보를 자동 입력값으로 승격하지 않는다.
- "자주 선택되는 응답"만으로 낮은 신뢰도 값을 자동 확정하지 않는다.
- 모든 문항의 임계값을 일괄 완화하지 않는다.
- 사용자가 수동으로 입력한 값을 OCR/마크 인식 성공으로 기록하지 않는다.
- 좌표 오류, PDF 렌더링 오류, 저장 API 오류, XLSX 생성 오류를 하나의 원인으로 합치지 않는다.

## 7. 다음 구현 전 확인해야 할 항목

1. `detectCheckmarks.ts`의 미커밋 변경이 타입 검사와 기존 테스트를 통과하는지 확인한다.
2. 각 필드 그룹별로 등록 결과, 탐지된 행/열, 후보 거절 사유, 최종 ROI를 구조화된 로그 또는 테스트 산출물로 남긴다.
3. 동일한 두 PDF로 자동 입력 항목과 미확정 항목을 학생별로 비교한다. 수동 수정값은 비교 대상에서 제외한다.
4. 기본정보와 만족도 7~10번을 일반 격자 규칙과 분리해 전용 등록/격자 검증 규칙을 설계한다.
5. 연령 OCR은 워커 초기화 완료, 타임아웃, 실제 OCR 결과를 별도 관측한다.
6. 저장 API는 UI용 이미지 데이터와 저장 DTO를 분리하고, 응답의 HTTP 상태 및 Content-Type을 확인한 뒤에만 JSON을 파싱한다.
7. XLSX 생성물은 다운로드 후 실제 Excel로 열리는지 별도 회귀 테스트한다.

## 8. 이 작업 기록의 결론

현재 작업은 좌표를 임의로 더 움직이는 작업이 아니라, 자동 입력을 허용할 수 있는 증거와 허용할 수 없는 후보를 분리하는 작업이다. 이번 기록 기준으로 실제 확인을 마친 것은 반복 실패 패턴과 진단 메시지이며, 아직 완료되지 않은 것은 필드 그룹별 전용 등록 로직의 구현 검증과 저장/XLSX 경로의 회귀 검증이다.
