# 무수정 4번 페이지 기준 원인 분석 및 수정 계획 (2026-08-12)

## 1. 목적과 판정 원칙

이 문서는 동일한 비공개 원본 PDF로 반복한 인식 테스트에서 나타난 좌표 및 인식 실패를 정리한다. 목적은 다음 수정이 기존의 추측을 반복하지 않도록, **확인된 사실**, **아직 검증되지 않은 가설**, **수정 전 반드시 계측할 값**을 분리하는 것이다.

판정 원칙은 다음과 같다.

1. 사용자가 다음 학생으로 넘어가기 위해 검수 화면에서 직접 입력하거나 선택한 값은 자동 인식 성공의 증거로 사용하지 않는다.
2. 자동 인식의 증거는 수정 전 화면의 `낮음`, `확인`, `선택 안 함`, 좌표 진단 메시지, 자동 확정 상태, 그리고 원본 PDF의 해당 페이지 대조로만 판단한다.
3. 원본 PDF, 원본 이미지, 학생별 정답값, 이름·전화번호 등 개인정보는 Git에 추가하거나 진단 로그에 평문으로 남기지 않는다.
4. 빈도가 높은 응답값은 자동 입력의 근거가 아니라, 검수 우선순위나 후보 정렬에만 제한적으로 사용한다.

## 2. 이번 기준 사례

### 2.1 입력과 범위

- 입력: 기존에 반복 사용한 `선별검사 샘플1.pdf`, `만족도조사1.pdf`
- 기준 페이지: 두 PDF의 4번째 페이지, 학생 4번
- 기준 화면: 사용자가 어떠한 값을 수정하지 않았다고 명시한 캡처
- 화면 버전: `v2026-08-11.3`
- 원본 PDF 4페이지는 로컬에서 렌더링하여 실제 기입 위치를 대조했다. 대조 결과 자체와 학생 데이터는 비공개로 취급한다.

### 2.2 수정 전 관측 결과

| 영역 | 수정 전 자동 결과 | 신뢰도/진단 | 판정 |
| --- | --- | --- | --- |
| 기본정보 연령대 | 빈 값 | `확인` | 자동 OCR 결과가 저장되지 않음 |
| 기본정보 성별 | 선택 안 함 | `낮음`, 격자 후보 거절 | 자동 확정 차단 |
| 기본정보 학교유형 | 선택 안 함 | `낮음`, 좌표 불일치/선 부족 진단 | 자동 확정 차단 |
| 기본정보 학년 | 선택 안 함 | `낮음`, 격자 후보 거절 | 자동 확정 차단 |
| CAGI 1~9 | 모두 자동값 표시 | `높음` | 같은 페이지에서 일반 격자 판독은 성공 |
| 만족도 1~6 | 자동값 표시 | `높음` | 같은 페이지에서 상단/중단 표 판독은 성공 |
| 만족도 7~10 | 선택 안 함 | `낮음`, 격자 후보 거절 | 하단 5점 척도 표에서 자동 확정 차단 |

위 화면의 요약은 `낮은 신뢰도 7개, 확인 권장 1개`였다. 즉 기본정보 4개와 만족도 7~10이 문제 영역이며, 나머지 15개 선택형 항목은 같은 원본 페이지에서 자동 확정 경로를 통과했다.

## 3. 확인된 사실

### F-01. 전체 페이지 보정 실패만으로 현재 증상을 설명할 수 없다

PDF 업로드 시 다수 페이지에 `보정 엔진을 사용할 수 없어 원본으로 업로드` 메시지가 표시됐다. 브라우저 PDF 렌더러의 JBIG2/WASM 디코드 경고가 동반된 사례도 있었다. 이는 입력 품질과 보정 가능성을 낮출 수 있는 위험 신호다.

그러나 동일한 무수정 4번 페이지에서 CAGI 1~9와 만족도 1~6은 자동 확정됐다. 따라서 보정 실패는 조사해야 할 입력 조건이지만, 현재의 기본정보 및 만족도 7~10 실패를 단독으로 설명하는 원인은 아니다.

### F-02. 기본정보 선택 항목은 현 구조상 자동 확정 경로에 들어가기 어렵다

`src/lib/recognition/tableGridDetection.ts`는 기본정보 성별·학교유형·학년에 대해 `fixed` 또는 행 후보 기반 등록 결과를 만든다. 반면 `src/lib/recognition/detectCheckmarks.ts`는 선택형 값의 자동 반영을 `source === 'grid'` 이고 `status === 'verified'` 인 경우로 제한한다.

따라서 기본정보 성별·학교유형·학년은 후보 크롭과 후보 점수는 표시될 수 있어도, 현재 경로에서는 일반 격자와 같은 방식으로 자동 확정되기 어렵다. 이는 단순 임계값 문제가 아니라 **등록 결과의 종류와 자동 반영 조건이 서로 맞지 않는 구조적 원인**이다.

### F-03. 연령대 빈 값의 즉시 원인은 “수용된 OCR 결과 없음”이다

연령대는 격자 체크 판독이 아니라 `recognizeDigitsInRegion` 결과가 숫자로 수용됐을 때만 초안에 반영된다. 현재 빈 값은 OCR 호출 자체가 생략됐는지, 시간 제한에 걸렸는지, 크롭이 맞지 않았는지, OCR 결과가 비어 있었는지, 숫자/신뢰도 검증에서 탈락했는지를 화면만으로 구분할 수 없다.

즉 **연령대 실패의 최종 원인은 아직 미확정**이다. 다만 자동으로 수용 가능한 숫자 결과가 초안에 도달하지 않았다는 점은 코드와 화면으로 확인된다.

### F-04. 만족도 7~10은 안전장치가 실제로 동작한 결과다

만족도 7~10의 진단에는 `Grid candidate rejected`, `row fallback used`, 행·열 간격/잔차 관련 메시지가 표시된다. 후보 격자는 보이지만 행/열 구조가 독립적으로 검증되지 않아 자동 반영이 차단된 것이다.

현재 코드는 후보 격자를 자동 채택하지 않도록 되어 있다. 이 차단을 풀어 값만 채우면 잘못된 행과 문항을 연결하는 기존 문제가 재발할 수 있다.

### F-05. 빈 양식의 좌표 측정값만으로 학생별 페이지 등록 성공을 보장할 수 없다

빈 양식 기준 측정은 표준 양식의 기준 좌표를 제공한다. 그러나 개별 PDF 페이지에서는 렌더링 해상도, 누락된 보정, 선 품질, 기울기, 부분적 확대/축소, 손글씨와 체크 표시가 별도로 영향을 준다.

따라서 기준 좌표를 그대로 잘라 후보 이미지를 보이는 것과, 실제 문항의 행·열 좌표가 독립적으로 검증되는 것은 다른 문제다.

## 5. 배제하거나 금지할 접근

1. 전역 선 검출 임계값을 낮추어 모든 후보 격자를 자동 채택하지 않는다. 동일 페이지의 성공 영역까지 오탐 위험이 커진다.
2. `candidate` 또는 `rejected` 등록을 `verified`처럼 취급하지 않는다. 후보 좌표가 보인다는 사실은 문항-응답 셀 대응이 맞다는 증거가 아니다.
3. 자주 선택되는 응답값을 불확실한 항목에 자동 기입하지 않는다. 이는 실제 이상 응답과 조기개입 판단을 왜곡할 수 있다.
4. 검수 화면에서 수기 입력한 값을 자동 인식 정확도로 집계하지 않는다.
5. 원본 PDF나 학생별 수기 기입값을 테스트 픽스처·로그·커밋에 넣지 않는다.
6. `example`, 특정 이름 등 파일명에 의존하는 예외 처리로 실운영 판독값을 덮어쓰지 않는다. 테스트 전용 fixture는 운영 인식 경로와 분리한다.

## 6. 수정 전 계측 계획

코드 수정의 첫 단계는 인식 결과를 더 많이 채우는 것이 아니라, 각 항목이 왜 빈 값 또는 후보 거절이 되었는지 재현 가능하게 남기는 것이다.

### P0. 필드별 결정 추적 추가

각 인식 필드에 아래 정보가 남는 `RecognitionDecisionTrace`를 설계한다. 원본 이미지나 개인정보 텍스트는 저장하지 않는다.

| 분류 | 기록할 값 |
| --- | --- |
| 입력 식별 | 양식 종류, 페이지 번호, 비식별 입력 해시, 렌더 해상도 |
| 좌표 등록 | 템플릿 직사각형, 매핑 직사각형, 등록 소스, 상태, 변환 종류 |
| 표 검증 | 예상/관측 행·열 수, 간격 오차, 잔차, 후보 거절 이유 |
| 체크 판독 | 각 선택지의 비식별 점수, 자동 반영 허용 여부, 최종 결정 이유 |
| OCR | 시도 여부, 제한시간 잔여 여부, 빈 결과/파싱 탈락/신뢰도 탈락/성공 코드 |
| 사용자 보정 | `auto`, `manual`, `unresolved` 출처와 수정 시점 |

검수 UI는 자동값과 수기 보정값을 별도 표시해야 한다. 지금처럼 수기 보정 후에도 낮은 신뢰도와 원래 진단이 함께 보이는 상태는 유지하되, 값의 출처까지 표시해야 테스트 해석 오류를 막을 수 있다.

### P0 완료 기준

- 모든 빈 연령대에는 `ocr_not_started`, `deadline_exhausted`, `empty_ocr`, `parse_rejected`, `confidence_rejected`, `accepted` 중 하나의 종료 이유가 남는다.
- 모든 후보 격자에는 자동 반영 차단 여부와 구체적 거절 사유가 남는다.
- 원본 OCR 문자열, 학생 이름, 전화번호, 원본 크롭 이미지는 영구 로그에 남기지 않는다.

## 7. 기능 수정 계획

### P1. 기본정보 전용 등록기

대상: 연령대, 성별, 학교유형, 학년

일반 선택지 격자에 억지로 맞추지 않고, 상단 기본정보 표만을 위한 등록기를 분리한다.

1. 양식의 정적 라벨과 외곽선/열 경계를 앵커로 사용해 기본정보 영역을 먼저 국소 정합한다.
2. 성별, 학교유형, 학년은 각각의 실제 선택 셀 집합을 정의하고 행·열 구조를 독립적으로 검증한다.
3. 연령대는 체크 셀이 아닌 숫자 기입칸의 확대 ROI와 숫자 전용 OCR 경로를 사용한다.
4. 정합 또는 OCR 검증이 실패하면 빈 값으로 남기되, P0의 구체적 종료 이유를 표시한다.
5. `fixed` 좌표라는 이유만으로 자동 확정하지 않는다. 독립 앵커 또는 충분한 기하 검증이 있어야 `verified`로 승격한다.

### P2. 만족도 7~10 전용 하단 표 등록기

대상: 만족도 7~10의 4행 x 5열 리커트 표

1. 만족도 1~6과 분리된 `satisfaction.bottomLikert` 표 모델을 만든다.
2. 하단 표의 외곽선, 네 개 행 구분선, 다섯 선택 열 경계를 이용해 국소 변환을 계산한다.
3. 행 수, 열 수, 간격 오차, 중심점 변위, 표 영역 이탈을 각각 검증한다.
4. 검증에 통과한 경우에만 문항별 선택 셀을 자동 반영한다. 통과하지 못한 후보는 검수용 크롭만 제공한다.
5. 이 표의 체크/동그라미 모양에 맞는 별도 판독 임계값을 사용하되, 전역 임계값을 변경하지 않는다.

### P3. 연령대 OCR 복구

1. P0 진단으로 실제 실패 지점을 확인한 뒤에만 OCR 파라미터를 조정한다.
2. ROI 확대, 이진화 방식, 숫자 전용 문자 집합, 기울기 보정, 다중 후보 합의를 비교한다.
3. 단일 공용 시간 제한 때문에 후속 페이지 OCR이 건너뛰지 않도록 필드별/페이지별 예산을 분리하고, 만료를 추적한다.
4. 숫자 범위와 신뢰도 검증을 유지한다. 범위 밖 또는 불확실한 값은 자동 입력하지 않는다.

### P4. 응답 빈도 사전값의 제한적 사용

응답 빈도는 좌표 검증과 독립적인 보조 신호로만 사용한다.

- 기하 검증과 체크 점수가 충분한 자동 결과는 사전값으로 덮어쓰지 않는다.
- 두 후보가 근소하게 경쟁하지만 둘 다 자동 확정 기준을 만족하지 못한 경우, 검수 화면의 추천 순위에만 반영한다.
- 고위험 문항, 조기개입 판단과 연결되는 문항, 사용자가 별도로 지정한 “높은 신뢰도 필요” 문항은 사전값만으로 자동 확정하지 않는다.

### P5. 운영 경로의 테스트 예외 제거

파일명·예시명에 따라 답을 덮어쓰는 개발 편의용 분기는 운영 인식 코드에서 제거하거나 테스트 fixture 전용 경로로 격리한다. 실제 업로드 파일에 영향을 주는 숨은 예외가 있으면 이번과 같은 테스트 결과의 해석이 불가능해진다.

## 8. 검증 계획

### 8.1 로컬 비공개 골든 테스트

원본 PDF는 저장소에 넣지 않는다. 대신 로컬 무시 파일에 다음만 둔다.

- 비식별 입력 해시와 페이지 번호
- 항목별 기대 상태(자동 확정 / 미확정)와 기대 선택지 인덱스
- 원본을 재배포하지 않는 실행 스크립트 설정

이 테스트는 검수 화면을 열기 전 자동 결과만 비교한다. 사용자의 수기 편집이 한 번이라도 발생한 실행은 골든 정확도 결과로 집계하지 않는다.

### 8.2 공개 가능한 회귀 테스트

- 합성 양식 또는 개인정보가 제거된 표/숫자 크롭으로 기본정보 등록과 하단 5점 척도 등록을 단위 테스트한다.
- `candidate`와 `rejected` 등록이 자동 반영되지 않는 회귀 테스트를 둔다.
- OCR 종료 이유가 누락되지 않는 테스트를 둔다.
- CAGI 1~9 및 만족도 1~6의 현재 성공 경로가 회귀하지 않는 테스트를 둔다.

### 8.3 수용 기준

1. 무수정 4번 페이지에서 기본정보 네 항목과 만족도 7~10은 각 항목마다 자동 확정 또는 명시적 미확정 사유를 남긴다. 단순 빈 값은 허용하지 않는다.
2. 전용 등록기가 `verified`가 아닌 경우 어떠한 값도 자동 반영하지 않는다.
3. 페이지 4에서 이미 성공한 CAGI 1~9, 만족도 1~6은 자동 확정 상태를 유지한다.
4. 진단 화면에서 자동값과 수기 보정값의 출처가 구분된다.
5. 원본 PDF, 개인정보, 원본 OCR 텍스트는 저장소와 지속 로그에 남지 않는다.
6. 수정 후에는 같은 비공개 골든 실행을 수기 편집 없이 재실행하고, P0 진단과 원본 대조 결과를 함께 검토한다.

## 9. 구현 순서

1. P0 결정 추적과 값 출처 표시를 먼저 구현한다.
2. P1 기본정보 전용 등록기를 구현하고 비공개 골든 4번 페이지에서 검증한다.
3. P2 만족도 7~10 전용 등록기를 구현하고 같은 페이지에서 검증한다.
4. P3 연령대 OCR은 진단 결과에 맞춰 좁게 수정한다.
5. P4 사전값은 자동 확정 품질이 확인된 뒤 검수 추천에만 추가한다.
6. P5 운영 경로의 테스트 예외를 제거하고, 공개 가능한 회귀 테스트와 비공개 골든 테스트를 모두 통과한 뒤 배포한다.
