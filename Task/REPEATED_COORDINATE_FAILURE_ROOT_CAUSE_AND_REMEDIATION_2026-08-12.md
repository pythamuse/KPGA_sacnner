# 반복 좌표/응답 인식 실패: 근거 기반 원인 판정과 해소 계획

작성일: 2026-08-12  
대상: 선별검사지(CAGI) 및 예방교육 만족도조사 일괄 스캔 인식

## 1. 분석 범위와 증거 규칙

이번 판정에는 다음만 사용한다.

- 사용자가 값을 수정하기 **전**의 검수 화면
- `낮음`, `미확정`, `자동 인식`, `표본/좌표 후보`, `Grid candidate rejected` 등 상태와 진단 문구
- 업로드된 동일 PDF와 비어 있는 원본 템플릿의 측정 결과
- 실제 인식 코드의 좌표 등록, 표 검출, OCR 흐름

다음은 인식 정확도 근거로 사용하지 않는다.

- 다음 학생으로 진행하기 위해 사용자가 직접 입력하거나 선택한 값
- 검수 완료 뒤 표에 표시된 저장값
- 응답 빈도 우선순위만으로 만들어진 값

수기 수정값은 업무 결과로는 유효하지만 자동 인식 엔진의 정답 라벨이 아니다. 자동 인식률, 오답률, 좌표 정확도는 수정 전 결과 또는 별도 정답 라벨이 있는 자료로만 계산한다.

## 2. 결론 요약

반복되는 문제의 주원인은 "고정 좌표 자체가 모두 틀렸다"가 아니다. 비어 있는 원본 템플릿 측정에서는 주요 좌표가 충분히 정확했고, 실제 스캔에서는 **양식 구역마다 서로 다른 구조를 단일 보정/표 검출 규칙으로 처리하려 한 것**이 핵심이다.

현재의 엄격한 자동 입력 차단은 일부 경우 올바르게 작동한다. 즉 `Grid candidate rejected` 또는 `미확정`은 실패한 값이 자동 저장되는 것을 막는다. 그러나 그 결과가 많이 나타난다는 것은, 해당 구역에 맞는 독립적인 좌표 검증 계약이 아직 없다는 뜻이다. `높음`이나 `자동 인식`도 현재 규칙을 통과했다는 의미일 뿐, 사람의 정답 라벨과 대조되기 전에는 정답을 보장하지 않는다.

## 4. 특정 문항에서 문제가 더 심한 이유

### 4.1 CAGI 8~9

CAGI 1~7의 주 표와 달리 8~9는 하단의 짧고 분리된 보조 표다. 반복 행과 열의 수가 적고, 주변의 설명 문장 및 경계선 영향을 더 크게 받는다. 따라서 주 표에서 얻은 변환을 그대로 적용하거나 행 후보 하나만으로 열을 추정하면 `row fallback` 또는 `Grid candidate rejected`로 이어진다.

이는 화면 진단과 양식 구조로부터의 강한 추론이며, 다음 구현에서는 "CAGI 하단 보조 표"를 별도 표 군으로 로그와 정답 라벨로 검증해야 한다.

### 4.2 만족도 7~10

7~10은 상단 만족도 문항과 다른 하단 5점 척도 표다. 열 수와 폭, 행 간격, 인접 문항 텍스트가 다르며 얇은 내부선과 인쇄된 원형 보기표가 있다. 동일한 일반 표 규칙은 선택지 칸, 인쇄된 기호, 필기 흔적을 혼동하기 쉽다. 화면의 `candidate rejected`, 열 잔차, 선 검출 부족 진단은 이 구역에 독립적인 등록 및 마킹 판별이 필요함을 보여 준다.

### 4.3 기본정보(성별·학교유형·학년)

기본정보는 병합 셀, 체크박스, 라벨 텍스트가 섞인 헤더다. 규칙적인 응답 표가 아니므로 행·열 격자 검증을 적용하는 방식이 맞지 않는다. 행 후보가 있어도 열 기하가 독립 검증되지 않아 차단되는 현상은 설계상 예상 가능한 결과다.

### 4.4 연령대

연령대는 손글씨 숫자 영역이다. 일반 OCR은 손글씨 숫자에 약하고, 현재 화면에는 작업자 초기화 중 또는 허용 시간 내 완료하지 못했다는 별도 진단도 나타난다. 따라서 해결은 좌표만 이동하는 것이 아니라 (1) 숫자 전용 OCR 작업자 준비 상태, (2) 숫자 칸의 독립 크롭, (3) 손글씨 숫자 인식 결과의 보수적 승인으로 나누어야 한다.

### 4.5 인쇄 기호와 실제 마킹의 혼동

응답칸에는 원래 인쇄된 원형 보기표와 표선이 존재한다. 전체 어두운 픽셀량이나 단순 대비만 보면 인쇄 기호·표선이 실제 펜 마크보다 크게 작용할 수 있다. 빈 템플릿 기준선 차감은 이미 필요조건으로 확인됐지만, 그것만으로 펜 획을 완전히 구분하지는 못한다.

## 6. 재발 방지 설계

### 6.1 페이지 보정은 1차, 구역 등록은 2차로 분리

1. 페이지 전체에서 문서 외곽/기준 앵커로 거친 변환만 수행한다.
2. 각 응답 구역에서 해당 양식의 선·앵커·셀 구조로 별도 국소 변환을 계산한다.
3. 국소 변환의 잔차, 행·열 수, 셀 크기, 앵커 일치도를 통과한 경우에만 자동 입력한다.
4. 조건을 통과하지 못하면 좌표 후보나 응답 우선순위를 사용해 자동 입력하지 않고 `미확정`으로 남긴다.

구역 군은 최소한 아래처럼 분리한다.

- `cagi-main`: CAGI 1~7 주 표
- `cagi-late`: CAGI 8~9 하단 보조 표
- `satisfaction-frequency`: 만족도 1
- `satisfaction-binary`: 만족도 2~6
- `satisfaction-scale`: 만족도 7~10 하단 5점 척도
- `basic-checkbox`: 성별·학교유형·학년
- `basic-age`: 연령대 숫자 칸

### 6.2 공통 표선 검출 계약

- 모든 표 군은 같은 선 검출 모듈과 같은 기준선 보정 규칙을 사용한다.
- 임계값을 전역으로 낮추지 않는다. 얇은 내부선은 예상 행·열 수, 선의 연속성, 인접 간격으로 판정해 잡음과 구분한다.
- 한 단계가 검출한 행·열 집합과 다른 단계가 사용하는 집합을 진단 로그에서 비교할 수 있어야 한다.

### 6.3 마킹 판별 계약

- 빈 템플릿의 인쇄 기호·표선 기준선을 먼저 차감한다.
- 각 선택지 셀 안에서 펜 획의 연결 성분, 획 방향, 대비 변화, 중심 위치를 별도로 평가한다.
- 응답 빈도는 동점 해소용 검토 순서에만 쓴다. 시각 근거가 부족한 경우의 자동 입력 근거로 쓰지 않는다.

### 6.4 OCR 및 기본정보 계약

- 연령대는 숫자 전용 OCR 작업자를 미리 준비하고, 준비 실패·시간 초과·낮은 신뢰도는 명확히 `미확정` 처리한다.
- 성별·학교유형·학년은 OCR 문장 인식이 아니라 각 체크박스 또는 선택 칸의 마킹 판별로 처리한다.
- OCR 결과가 있어도 해당 크롭이 검증된 기본정보 영역에서 나왔는지 확인한 뒤에만 반영한다.

### 6.5 PDF 입력 계약

- 업로드 시 JBIG2 등 지원 불가 압축을 명확히 탐지한다.
- 브라우저 PDF 디코더 실패와 좌표 보정 실패를 같은 메시지로 묶지 않는다.
- 가능하면 서버 또는 통제된 변환 경로에서 동일 해상도의 래스터를 만들고, 페이지별 렌더 성공 여부를 먼저 보장한다.

## 7. 구현 순서

### P0. 관측 가능성 확보

각 페이지·구역마다 개인식별정보 없이 다음을 저장/표시한다.

- 양식군 ID, 페이지 번호, 이미지 해시
- 페이지 변환과 구역 변환
- 사용한 앵커와 검출된 행·열 수
- 기대 행·열 수, 셀 크기, 잔차, 거부 사유
- 마킹 판별 점수와 자동/미확정 결정 사유
- OCR 작업자 상태와 처리 시간

목표는 "왜 이 좌표를 썼는지"를 카드 한 장과 구조화 로그에서 같은 내용으로 확인하는 것이다.

### P1. 재현 가능한 평가 세트

- 현재 사용 중인 동일 PDF를 입력 고정 표본으로 등록한다.
- PDF 원본과 렌더된 페이지의 해시·해상도·회전 정보를 기록한다.
- 사용자 수정값과 분리된 실제 정답 라벨을 소수 페이지부터 만든다.
- 빈 템플릿, 실제 스캔, 기울어진 사진을 서로 다른 세트로 유지한다.

### P2. 확인된 선 검출 결함 수정

- 표 행 검출과 격자 검출이 서로 다른 0.3/0.5 임계값을 임의로 쓰지 않도록 공통 계약으로 통합한다.
- 빈 양식에서만 통과하는 완화가 아니라 실제 스캔에서도 예상 행·열 수와 간격이 맞을 때만 허용한다.
- 기존 CAGI 주 표와 만족도 2~6이 퇴행하지 않는 회귀 테스트를 추가한다.

### P3. 특수 표 군 구현

- CAGI 8~9에 하단 보조 표 전용 앵커·행·열 검증을 추가한다.
- 만족도 7~10에 4행 x 5선택지 척도 전용 등록 및 마킹 판별을 추가한다.
- 검증 실패 시 행 후보를 자동 선택값으로 승격하지 않는다.

### P4. 기본정보 및 OCR 분리

- 기본정보 체크박스 전용 검증을 표 격자와 분리한다.
- 연령 숫자는 워커 준비 완료 후에만 실행하고, 결과가 없으면 빈 값과 원인을 남긴다.

### P5. PDF·저장·Excel 별도 안정화

- JBIG2 렌더 실패를 입력 오류로 정확히 분류한다.
- 저장 API의 응답 Content-Type 및 JSON 계약을 검증한다.
- 생성된 XLSX는 내려주기 전 OOXML 검사/열기 테스트를 수행한다.

## 8. 금지할 변경

아래 변경은 재발 방지 원칙상 금지한다.

- 후보 좌표가 있다는 이유만으로 자동 입력 허용
- 전 구역에 같은 임계값 완화 적용
- 응답 빈도/사전확률만으로 빈 응답을 자동 채움
- 수기 수정 후 표시된 값을 자동 인식 성공으로 기록
- PDF 렌더 실패를 보정 실패로 감추고 원본 좌표를 자동 승인
- 개인식별정보가 포함된 원본 이미지나 OCR 원문을 진단 로그에 기록

## 9. 완료 기준

다음 조건을 모두 충족해야 자동 입력 확대를 승인한다.

1. 동일 PDF의 각 페이지에서 사용한 양식군과 좌표 결정 사유를 재현할 수 있다.
2. CAGI 8~9 및 만족도 7~10은 검증된 국소 격자를 사용하거나, 실패 시 반드시 `미확정`이다.
3. 기본정보와 연령은 표 격자 후보를 근거로 자동 입력하지 않는다.
4. 자동 입력된 응답은 정답 라벨 세트와 비교해 측정하며, 수기 수정값은 평가에서 제외한다.
5. 거짓 자동 입력은 허용하지 않는다. 낮은 커버리지는 일시적으로 허용하되 이유가 진단에 남아야 한다.
6. PDF 디코딩 실패, 저장 API 실패, XLSX 생성 실패는 서로 다른 사용자 메시지와 로그를 가진다.

## 10. 다음 작업의 우선순위

다음 코드 변경은 한 번에 전체 알고리즘을 바꾸지 않는다.

1. P0 진단 데이터와 고정 재현 세트를 먼저 완성한다.
2. P2 공통 표선 검출 계약을 고친 뒤 주 표 회귀를 확인한다.
3. P3의 `cagi-late`와 `satisfaction-scale`을 각각 독립 배포/검증한다.
4. P4 기본정보·연령을 별도 파이프라인으로 교체한다.
5. P5의 PDF, 저장 API, XLSX 문제는 인식 변경과 분리해 해결한다.

이 순서를 지키면 낮은 신뢰도를 감추기 위해 자동 입력을 늘리는 대신, 어떤 구조에서 왜 미확정이 되는지를 먼저 확정할 수 있다.
