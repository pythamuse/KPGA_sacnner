# 배치 OCR 및 격자 후보 검증 기록 (2026-08-12)

## 1. 목적

같은 19쪽 선별검사지/만족도조사 PDF를 반복 처리할 때 나타난 연령대 공란과
문항별 좌표 불일치를, 관찰된 사실과 아직 검증되지 않은 가정으로 분리한다.

이 문서는 개인식별정보가 들어 있는 원본 PDF, 원본 이미지, OCR 전문을 보관하지
않는다. 검증은 애플리케이션과 같은 PDF.js 렌더러 설정으로 만든 임시 로컬 산출물과
코드 경로만 사용했다.

## 2. 재현 조건

| 구분 | 내용 |
|---|---|
| 입력 | 사용자가 반복 시험한 동일한 19쪽 선별검사지/만족도조사 PDF 묶음 |
| 렌더러 | 애플리케이션 의존성과 같은 PDF.js 6.1.200 |
| 래스터화 | 배율 1.5, JPEG 품질 0.86 |
| 비교 대상 | 학생 1, 학생 2의 CAGI 1~9번과 만족도 1~10번 카드 결과 |
| 제외 | 개인식별정보, 원본 이미지/문서, 텍스트 OCR 결과의 저장·Git 추가 |

## 3. 확인된 사실

### FACT-01. 로컬 재현과 배포 화면의 결과 패턴은 일치한다

- 동일 PDF를 위 조건으로 렌더링해 현재 인식 코드를 실행했을 때, 배포 화면에서
  보인 학생별 고신뢰/저신뢰 분포와 격자 후보 거부 패턴이 재현됐다.
- 따라서 이번 증상은 브라우저 캐시, 배포 버전 불일치, PDF 페이지 순서 뒤바뀜,
  또는 단순한 무작위성만으로 설명되지 않는다.

### FACT-02. 격자 후보를 자동 채택하면 일부 문항의 선택 순위가 더 나빠진다

- 학생 2의 만족도 2~6번과 CAGI 8~9번에서 후보 격자의 중심은 고정 템플릿 대비
  대략 2~4% 이동했고, 행 간격/잔차 품질도 검증 기준을 통과하지 못했다.
- 해당 후보 셀을 강제로 적용해 선택지별 잉크 점수를 비교했을 때, 고정 템플릿보다
  실제 표시와 맞지 않는 선택지가 상위로 올라가는 문항이 있었다.
- 그러므로 `candidate` 격자를 `verified`와 동일하게 자동 반영하는 것은
  해결책이 아니라 오인식 확대 위험이다.

### FACT-03. 현재 격자 품질 게이트는 후보 자동 채택을 막고 있다

- `tableGridDetection.ts`는 행/열 간격 편차, 선 잔차, 후보 중심 이동과
  분산을 확인한다.
- `detectCheckmarks.ts`는 검증된 격자만 자동 채점 셀로 쓰고, 후보 격자는
  검수 오버레이와 진단 정보로만 남긴다.
- 화면의 `grid candidate rejected` 또는 `좌표 후보` 표시는 실패한
  자동 보정이 저장값으로 사용되지 않았다는 안전 표시다.

### FACT-04. 연령 숫자 OCR과 행 앵커 OCR은 동일한 배치 마감시각을 공유한다

- API 라우트는 배치 시작 시 한 번 만든 `ocrDeadlineAt`을 모든 학생의
  `recognizeStudentForms()` 호출에 전달한다.
- `recognizeDigitsInRegion()`은 마감시각이 지난 경우 OCR을 시도하지 않고
  `undefined`를 반환한다.
- 따라서 앞 학생 처리에 시간이 쓰이면 뒤 학생의 연령 숫자 OCR 시도 자체가
  건너뛰어질 수 있는 코드 경로가 존재한다.

### FACT-05. 연령 공란은 시간 예산 문제만으로 단정할 수 없다

- 이전 테스트에서 손글씨 연령 숫자는 유효 범위를 벗어나거나 낮은 신뢰도로 읽혀
  자동 저장이 차단된 적이 있다.
- 즉 특정 학생의 공란은 (a) OCR 미시도, (b) OCR 시도 후 낮은 신뢰도, (c) 손글씨
  숫자 분리 실패 중 하나일 수 있다.
- 현재 화면만으로 각 요청에서 어느 원인이 발생했는지는 확정할 수 없다.

## 4. 기각한 가정

| 가정 | 판정 | 이유 |
|---|---|---|
| 격자 후보를 자동 채택하면 문항 위치 문제가 해결된다 | 기각 | 일부 문항에서 선택지 점수 순위가 악화됐다. |
| 전역 격자 허용 기준을 완화하면 같은 PDF 전체가 좋아진다 | 기각 | 잘못된 후보 좌표도 통과시켜 오답 자동 저장 위험이 커진다. |
| 연령 공란은 ROI 좌표가 틀렸다는 뜻이다 | 기각 | 올바른 ROI에서도 손글씨 숫자 OCR 자체의 한계가 관찰됐다. |
| 연령 공란은 항상 OCR 모델의 정확도 문제다 | 기각 | 배치 공용 마감시각으로 인해 OCR을 시도하지 않는 경로가 확인됐다. |
| 자주 나오는 응답값을 자동 보정값으로 넣어도 된다 | 기각 | 실제 응답을 사전 분포로 덮어쓸 위험이 있다. |

## 5. 아직 열려 있는 가정

| 가정 | 상태 | 검증 방법 |
|---|---|---|
| 후속 학생의 연령 OCR 공란 중 일부는 공용 마감시각 만료 때문이다 | 열린 가정 | 연령 OCR 전용 마감시각과 시도/종료 사유를 비식별 진단으로 기록해 비교한다. |
| 템플릿-대상 차이 영상의 선택지별 잉크 분석이 저신뢰 문항을 개선한다 | 열린 가정 | 빈 양식 기준선과 표시된 샘플을 분리해 선택지 순위 정확도를 측정한다. |
| 문항군별 행 등록을 별도로 보정하면 만족도 2~6번의 안정성이 높아진다 | 열린 가정 | 전체 격자 완화가 아닌 해당 표의 행/열 품질과 선택지 순위를 사전·사후 비교한다. |

## 6. 이번 수정 범위

1. 행 앵커 OCR의 배치 전체 시간 예산은 유지한다. 장시간 PDF 처리에서 요청 시간이
   학생 수에 비례해 증가하는 회귀를 막기 위해서다.
2. 연령 숫자 OCR에는 학생별 별도 짧은 마감시각을 부여한다. 첫 번째 요청은 워커
   초기화를 고려해 더 긴 예산을 쓰고, 이후 요청은 작은 예산으로 제한한다.
3. 어느 OCR도 기한 내 신뢰도 기준을 넘지 못하면 자동값을 만들지 않고 검수 공란을
   유지한다.
4. 후보 격자를 자동 반영하거나 전역 격자 기준을 완화하지 않는다.

## 7. 다음 검증 기준

- 단위 테스트에서 행 앵커 마감시각은 배치 공용으로 유지되고, 학생 2 이후에도
  연령 OCR 마감시각이 이미 만료된 공용 시각을 재사용하지 않는지 확인한다.
- 빌드와 전체 테스트를 통과한다.
- 다음 배포 테스트에서는 화면 버전, 학생 순번, 연령 OCR의 시도 여부/종료 사유만
  비식별 진단으로 확인한다. 이름·전화번호·OCR 원문은 기록하지 않는다.
- 만족도 2~6번 및 CAGI 8~9번은 자동 채택률이 아니라, 원본 표시와 일치하는
  선택지 순위의 정확도로 별도 평가한다.
