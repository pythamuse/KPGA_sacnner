# 나이 크롭 상단 인셋 — 계측·판정 (2026-09-06) → **기각**

표적은 `getAgeDigitsRect`의 상단 인셋 0.12. 발단은 [Docs/18_GROUND_TRUTH_VALIDITY.md](../Docs/18_GROUND_TRUTH_VALIDITY.md) §5.2 —
나이 크롭이 손글씨 숫자의 윗부분을 자르고 있고, 그것이 3·5를 7로 읽게 만든다는 관찰.

## 1. 계측 — 상단 인셋 쓸기

도구: [tests/_probe-age-crop-bounds.test.ts](../tests/_probe-age-crop-bounds.test.ts). 상단 인셋만 바꿔가며
**두 자리 순수 판독**(게이트 없음)을 검증된 정답표와 대조한다. 착수 전에 적어 둔 반증 조건: *크롭을 위로 넓혀도
정확도가 평평하거나 떨어지면 잘림 가설은 죽는다.*

| 상단 인셋 | 세트1 | 세트2 | 세트3 | 세트4 | 합계 |
|---|---|---|---|---|---|
| **0.12 (현재)** | 13/4 | 9/7 | 11/5 | 13/4 | 46 정답 · 20 오답 |
| **0.06** | 14/3 | 12/4 | 12/5 | 13/4 | **51 · 16** |
| 0 | **15/2** | 9/7 | 10/7 | 13/4 | 47 · 20 |
| −0.06 | 9/7 | 8/9 | 7/11 | 9/6 | 33 · 33 |
| −0.12 · −0.20 (세트1만) | 7/6 · 1/5 | | | | 급락 |

**가설은 절반만 맞았다.** 인셋이 자르는 것은 사실이지만, 숫자가 템플릿 상자 **위로** 나가 있다는 그림은 틀렸다 —
상자 밖으로 넓히면 인쇄 선과 윗 행이 들어와 획 분할이 깨진다. 백지 채움은 16개 조합 전부 0이었다.

**세트 1만 봤다면 0을 골랐을 것이다**(세트 1 최고, 세트 2·3에서는 악화). §5.4의 "한 세트에 맞춘 것"의 사례.

## 2.1 브라우저 판정 (§5.1의 판정자) — **중립**

`src/`가 아침 기준선 커밋과 바이트 동일이므로 그날의 측정을 `off`로 쓰고 `on`만 새로 돌렸다.
인식은 `/api/recognize`에서 서버 측으로 도니 dev 서버의 환경변수가 플래그를 정한다.

| | off (0.12) | on (0.06) |
|---|---|---|
| 자동 입력 | 358 | **358** |
| 정답 | 352 | **352** |
| 오답 | 6 | **6** (같은 6칸) |
| 미확정 빈칸 | 74 | **74** |
| `basic.age` | 자동 10 · 정답 10 · 오답 0 | **동일** |

셀 단위 diff는 **두 칸뿐이고 서로 상쇄한다**:

```
p7  basic.age: 14/auto      -> null/unresolved   (맞던 값을 잃음)
p10 basic.age: null/unresolved -> 15/auto        (맞는 값을 얻음)
```

§5.4: **브라우저 합계 변화 없음 → 병합하지 않는다.** 노드에서 오답이 늘었으므로 판정은 그대로 기각이고,
브라우저는 "노드 손해를 상쇄할 이득이 실사용 경로에 있는가"에 **없다**고 답한다.
**기각**([CLAUDE.md](../CLAUDE.md) §5.4: 오답이 늘면 정답이 올라도 기각). 특히 사진 경로의 오답 0은 네 세트에서
유지돼 온 성질이고 이 변경이 그것을 깬다.

## 3. 늘어난 오답의 기제 — 서로 다른 둘

| 칸 | 값 | 기제 |
|---|---|---|
| 스캔2 p16 `basic.age` | 15 (정답 13) | 분류기가 0.12에서도 15로 읽었지만 **신뢰도 0.41이라 거절**됐다. 0.06에서 같은 오독의 **신뢰도가 1.00**이 되어 게이트를 통과한다 |
| 사진2 p17 `basic.age` | 15 (정답 13) | 같은 기제(사진 경로) |
| 스캔3 p10 `basic.age` | 19 (정답 15) | 분류기는 0.06에서 15를 **정확히** 읽는다(1.00,1.00). 이 19는 **tesseract**가 넓어진 크롭에서 만든 값이고, tesseract 경로에는 학년 범위 게이트가 없다 |

## 4. 이 라운드가 남기는 것

- **순수 판독 정확도는 제품 지표가 아니다.** 쓸기는 51/16 대 46/20으로 개선을 예측했고 제품 측정은 반대였다.
  이유는 **신뢰도가 크롭에 대해 보정돼 있지 않다**는 것 — 크롭을 넓히면 맞는 판독만큼 **틀린 판독의 신뢰도도** 올라가
  신뢰도 게이트가 하던 일을 못 하게 된다. §2의 "계측기가 무엇을 재고 있는지 확인한다"가 이번엔 필자에게 적용됐다.
- **크롭은 분류기와 tesseract에 동시에 먹인다.** `recognizeDigitsInRegionDetailed`가 사각형 하나를 받아 두 소비자에게
  주므로, 분류기를 위해 넓히면 게이트가 약한 tesseract도 같이 넓어진다.
- **`AGE_CROP_TOP_V2` 플래그는 남기지 않았다**(변경 자체를 되돌렸다). 다시 열려면 §1의 쓸기부터 재현한다.

## 5. 닫지 않은 갈래 (측정된 후보, 착수 전)

1. **크롭 0.06 + 신뢰도 문턱 상향.** 게이트를 **조이는** 방향이므로 §5.4가 금지하는 완화가 아니다. 스캔2 p16이
   0.41 → 1.00으로 올라온 것을 막으려면 문턱만으로는 부족할 수 있다(1.00은 어떤 문턱도 통과한다) — 그렇다면 이 갈래는 죽는다.
2. **분류기에만 넓은 크롭, tesseract에는 현재 크롭.** 스캔3 p10을 설명하는 기제에 직접 대응한다. 호출부를 둘로 나눠야 한다.
3. **하단 인셋은 재 본 적이 없다.** 이 라운드는 상단만 쓸었다.
4. **p3(세트1)의 `strokes 0`은 크롭이 원인이 아니다** — 여섯 설정 어디에서도 두 획이 되지 않는다.
   [Docs/18](../Docs/18_GROUND_TRUTH_VALIDITY.md) §5.2에 크롭 절단으로 적었던 것을 정정했다.
