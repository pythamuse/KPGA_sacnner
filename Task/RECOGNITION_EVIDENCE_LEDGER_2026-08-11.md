# 인식 오류 증거·가정 분리 대장 (2026-08-11)

## 1. 목적

이 문서는 선별검사지(CAGI)와 예방교육 만족도조사의 업로드, PDF 렌더링,
양식 분류, 좌표 등록, 체크 인식, 기본정보 OCR, 엑셀 생성 과정에서 발생한
오류를 한 기준으로 기록한다.

가장 중요한 목적은 다음 둘을 분리하는 것이다.

1. 특정 시점에 가능하다고 생각했던 **가정 또는 설계 가설**
2. 입력 파일, 코드 추적, 재현 테스트 또는 실제 배포 테스트로 확인된 **사실**

과거 Task 문서는 당시의 판단과 작업 맥락을 보존한다. 과거 문서에 어떤 원인이
적혀 있다는 사실만으로 그 원인이 확정되는 것은 아니다. 이 문서가 현재의
사실 판정과 다음 수정의 출발점이다.

## 2. 판정 표기와 증거 등급

| 표기 | 의미 | 코드 변경 가능 여부 |
|---|---|---|
| `FACT` | 재현 입력, 코드 추적, 로그 또는 테스트로 직접 확인됨 | 원인에 맞는 제한적 수정 가능 |
| `HYPOTHESIS` | 증상은 관찰됐지만 원인이 여러 개일 수 있음 | 단독 근거로 임계값 또는 자동입력 정책 변경 금지 |
| `REJECTED` | 테스트로 반증됐거나 범위가 더 좁은 것으로 확인됨 | 같은 전제로 재시도 금지 |
| `OPEN` | 아직 충분한 입력 또는 측정이 없음 | 진단과 재현 입력 확보가 먼저 |

증거의 강도도 함께 기록한다.

| 등급 | 근거 | 증명하는 범위 |
|---|---|---|
| E0 | 사용자 화면 캡처 또는 구두 관찰 | 증상이 실제 사용자 환경에 존재함 |
| E1 | 코드 경로, 브라우저 콘솔, 서버 응답 추적 | 특정 경로가 실행됐거나 실패한 이유 |
| E2 | 실제 입력을 같은 렌더링 조건으로 로컬 재현 | 해당 입력과 로컬 코드 조합의 동작 |
| E3 | 빈 양식/회귀 테스트 | 고정된 조건에서의 재발 방지 |
| E4 | 버전 표기가 확인된 프로덕션 재테스트 | 실제 배포본에서의 해결 여부 |

E3 통과는 E4를 대신하지 않는다. 합성 테스트나 빈 양식 테스트가 통과해도
수기 표시, 낮은 대비, 스캐너 압축, Vercel 런타임을 자동으로 증명하지 않는다.

## 3. 현재 확정된 사실 요약

1. PDF.js로 렌더링한 PDF 페이지는 이미 직사각형 래스터다. 카메라 사진용
   원근 보정 Worker를 PDF에 적용해도 좌표 등록이 좋아지지 않았고, Worker
   초기화 실패 시 페이지 수만큼 같은 경고가 반복됐다.
2. 2026-08-10에 실측한 빈 양식은 CAGI와 만족도 응답 표의 템플릿 기준점이
   전반적으로 맞음을 보였다. "고정 템플릿 자체가 전체적으로 틀렸다"는
   일반 가정은 반증됐다.
3. 실제 19페이지 PDF에서는 얇은 표 외곽선이나 내부선이 JPEG 변환 뒤 약해질
   수 있다. 이 문제는 템플릿 전체가 틀린 문제가 아니라 표선 검출과 후보선
   선택 문제다.
4. 기본정보의 연령대 `14`가 비었던 사례는 ROI가 완전히 벗어난 것이 아니라,
   수기 `1`을 일반 숫자 OCR이 분리하지 못한 사례였다. 잘못 읽은 값을 저장하지
   않기 위해 현재는 수동 검수로 남긴다.
5. 학교유형과 학년은 비정형 기본정보 표에서 행 또는 열 근거가 독립적으로
   검증되지 않으면 자동값을 만들지 않는다. 빈 값은 "값 없음"이 아니라
   "자동 확정 근거 부족"일 수 있다.
6. 응답 빈도는 위치 또는 체크 판별 실패를 고치는 근거가 아니다. 제공된
   빈도는 자동 입력이나 빈칸 보정에 사용하지 않는다.
7. Excel 복구 경고는 인식 좌표와 별개의 OOXML 네임스페이스 병합 문제였다.
   이 문제의 수정과 검증은 인식 정확도가 올랐다는 증거가 아니다.
8. 동일한 19페이지 PDF의 1·2번째 묶음을 실제 PDF.js 렌더 조건으로 다시
   실행했을 때, 페이지별 격자 품질과 마크 점수가 달랐다. 특히 만족도 2~6번과
   CAGI 8~9번의 `candidate grid`를 강제로 사용해도 일관되게 더 좋은 결과가
   나오지 않았다.
9. 현재 `/api/recognize`는 OCR 행 앵커와 연령 숫자 OCR에 같은 배치 마감시각을
   전달한다. 배치의 앞부분에서 6초가 지나면 이후 학생의 연령 OCR은 시도 전에
   종료될 수 있다. 이 경로는 수기 숫자 OCR의 자체 한계와 별개다.

### REC-05. "표선 수가 모자라면 허용오차를 넓히면 된다"는 가정

### REC-07. OCR 텍스트 앵커가 좌표 문제의 주 해결책이라는 가정

| 구분 | 내용 |
|---|---|
| 증상 | 고정 ROI 대신 OCR 텍스트 위치로 행을 찾으려는 시도, 배치 처리 지연 |
| 당시 가정 | OCR 앵커가 표선 검출보다 안정적으로 행 위치를 고정할 수 있음 |
| 확인된 사실 | OCR은 낮은 대비, 수기 표시, PDF 처리 시간 예산에 영향을 받으며 표선/템플릿 등록을 대체하는 일반 기준으로 검증되지 않았다. 일부 경로에서는 지연과 불확실한 결과가 확인됐다. |
| 판정 | `REJECTED` - OCR을 표 좌표의 기본 기준으로 사용 |
| 현재 정책 | OCR은 보조 신호로만 사용하고, 시간 예산을 넘기면 건너뛴다. 격자 또는 독립 기하 검증이 없는 경우 자동값을 만들지 않는다. |

### REC-09. 학교유형과 학년의 빈값을 고정 X/Y 좌표 이동으로 해결할 수 있다는 가정

| 구분 | 내용 |
|---|---|
| 증상 | 학교유형과 학년 crop이 인접 행/안내문을 포함하거나 자동 선택되지 않음 |
| 당시 가정 | 템플릿 좌표를 미세 이동하면 자동 선택할 수 있음 |
| 확인된 사실 | 기본정보 표는 균일한 N행 x M열 표가 아니며, 일부 사례는 행 후보가 있어도 열 기하를 독립적으로 검증하지 못했다. 고정 좌표를 미세 이동해도 선택지의 실제 체크 셀이라는 증거가 되지 않는다. |
| 판정 | `OPEN` - 더 나은 기본정보 등록 방법은 미확정. 고정 좌표 이동은 해결책으로 채택하지 않음 |
| 현재 정책 | 독립적인 행과 열 검증이 실패하면 자동 선택하지 않고 넓은 검수 crop만 제공한다. |
| 근거 | `Task/REMAINING_FIELD_FIXES_AFTER_BLANK_FORM.md`, `Task/COORDINATE_REGISTRATION_DIAGNOSTICS_IMPLEMENTATION.md` |

### REC-10. 응답 빈도 가중치로 낮은 신뢰도를 자동 보정할 수 있다는 가정

| 구분 | 내용 |
|---|---|
| 증상 | CAGI는 `0`, 만족도 일부는 `1` 또는 `4` 응답 비율이 높다는 운영 관찰 |
| 당시 가정 | 빈도가 높은 응답에 가중치를 주면 낮은 신뢰도 자동 인식이 개선될 수 있음 |
| 확인된 사실 | 현재 저장값별 실제 분포, 문항별 false positive/false negative, 입력 종류별 오류율이 충분히 측정되지 않았다. ROI가 틀린 상태에서 사전확률을 적용하면 잘못된 위치의 답을 더 확신 있게 저장할 위험이 있다. |
| 판정 | `HYPOTHESIS` - 자동값 보정에는 사용 금지 |
| 현재 정책 | 사전확률은 자동 확정, 빈칸 채움, 좌표 실패 보정에 사용하지 않는다. 향후에도 시각 근거를 뒤집지 못하는 검수 우선순위 보조 신호로만 검토한다. |
| 근거 | `Task/COORDINATE_REGISTRATION_AND_RESPONSE_PRIOR_PLAN.md` |

## 6. 이후 수정 전 필수 절차

1. 새 증상을 먼저 E0 관찰로 기록한다. 버전, 입력 종류(카메라/이미지/PDF),
   페이지 번호, 양식 슬롯, 카드의 좌표 출처 배지, 오류 문구를 함께 남긴다.
2. 같은 입력 또는 개인정보를 제거한 등가 입력으로 E1/E2 재현을 만든다.
   원본 개인정보 PDF와 사진은 Git, 고정 fixture, 문서 본문에 저장하지 않는다.
3. 원인 후보가 두 개 이상이면 코드 변경 전에 후보별로 예측을 쓴다.
   예: "PDF Worker 문제라면 Worker 호출이 0회여야 한다"처럼 반증 가능한
   기준을 먼저 정한다.
4. 수정은 확인된 원인 한 개를 겨냥해 최소 범위로 한다. 낮은 신뢰도를 없애기
   위해 전역 임계값을 넓히거나 사전확률로 값을 채우지 않는다.
5. E3 회귀 테스트에는 실패 케이스도 넣는다. 특히 다른 설명선, 한쪽만 남은
   외곽선, 빈 캔버스, 잘못된 열 수, 유사한 표가 있는 입력을 포함한다.
6. 실제 배포 전과 후에 버전 표기를 확인한다. E4 재테스트 결과가 없으면 문서의
   상태는 "해결"이 아니라 "배포 후 검증 대기"로 기록한다.
7. 테스트가 원본 템플릿, 사용자 PDF, Blob 개인 파일을 변경하거나 Git에
   추가하지 않았는지 `git status`와 staged file 목록으로 확인한다.

## 7. 금지된 재시도 목록

- PDF 페이지마다 카메라 원근 보정 Worker를 다시 호출하지 않는다.
- 빈 양식 실측을 무시하고 템플릿 좌표 전체를 눈대중으로 이동하지 않는다.
- 부분선 누락을 이유로 페이지 전체 기준 허용오차를 넓히지 않는다.
- 격자 또는 독립 기하 검증이 실패한 답을 "자주 나오는 응답"으로 자동 입력하지 않는다.
- 수기 연령 OCR의 낮은 신뢰도 값을 유효한 나이로 변환하지 않는다.
- 실제 PDF 재테스트 없이 합성 테스트 통과만으로 배포 문제를 "해결"로 선언하지 않는다.
- 개인정보가 포함된 이름, 전화번호, 이메일 OCR 결과를 진단 로그, 문서, 테스트
  fixture, 엑셀 데이터에 넣지 않는다.
