# 빈 양식 기준 응답 인식 및 엑셀 복구 검증 (2026-08-11)

## 1. 범위

2026-08-10.8 검수 화면과 다운로드한 엑셀의 오류를 재현해 다음 네 가지를 분리 검증했다.

1. 고정 템플릿 좌표와 실제 배치 PDF의 정합
2. 인쇄된 표선·동그라미와 수기 체크의 분리
3. 연령 손글씨 OCR의 오인식 경계
4. ExcelJS 저장 뒤 복원하는 확장 XML의 네임스페이스 무결성

입력 검증에는 사용자가 제공한 선별검사지·만족도조사 PDF의 첫 페이지를 로컬 일회성 회귀 입력으로만 사용했다. 개인정보가 포함될 수 있으므로 해당 PDF는 저장소에 추가하지 않는다. 런타임에 필요한 개인정보 없는 빈 양식 이미지만 `src/lib/recognition/assets/`에 포함한다.

## 2. 진단 결과

### 2.1 좌표 등록은 템플릿 기준에서 정상

빈 양식의 실제 인쇄 영역을 등록 기준으로 삼아 사용자의 PDF 첫 페이지를 검사했다.

| 영역 | 결과 | 최대 좌표 오차 |
|---|---|---:|
| CAGI Q1~Q7 | 격자 검증 통과 | x 0.19%, y 0.34% |
| CAGI Q8~Q9 | 격자 검증 통과 | x 0.07%, y 0.17% |
| 만족도 Q1~Q6 | 격자 검증 통과 | 0.4% 이하 |
| 만족도 Q7~Q10 | 독립 격자 검증 통과 | x 0.37%, y 0.22% |

따라서 "고정 좌표가 본질적으로 틀렸다"가 아니라, 이전 경로가 페이지의 어두운 픽셀 외곽을 등록 기준으로 사용해 책상 그림자·여백·다른 표를 함께 포함하거나, 좌표는 맞아도 인쇄된 동그라미를 수기 체크로 오인한 것이 주된 원인이다.

### 2.2 CAGI 및 만족도 문항 인식 저하의 직접 원인

기존 마크 점수는 각 선택 칸의 전체 어두운 픽셀 비율이었다. 모든 칸에는 이미 인쇄된 동그라미와 표선이 있으므로, 수기 표시보다 인쇄물 농도가 점수를 좌우했다. 특히 좁은 CAGI 선택칸과 만족도 Q7~Q10의 다섯 점 척도는 이 영향이 커서 서로 다른 문항이 비슷한 점수로 보였다.

빈 양식의 같은 후보 셀을 동일한 크기로 정렬하고 배경 밝기를 보정한 뒤, 실제 스캔에서 새로 늘어난 어두운 획만 계산하도록 바꿨다. 이 방식은 원본 양식의 인쇄 위치를 마커로 쓰되, 인쇄 자체를 응답으로 해석하지 않는다.

### 2.3 연령 `14`가 비어 있던 이유

연령 ROI는 이제 `세` 글자가 아니라 빈 양식에서 계측한 숫자 입력 상자에 정확히 고정된다. 그러나 실제 PDF의 손글씨 `4`는 상자 하단선·세로 구분선과 붙어 있고, Tesseract 영문 숫자 모델은 이를 `9`로 읽었다. 빈 양식 차분 뒤에도 OCR 결과는 `19`, 신뢰도 55였다.

이 문제는 좌표 실패가 아니라 손글씨 숫자 OCR의 모델 한계다. 이번 변경은 신뢰도 60 미만의 연령 값을 자동 저장하지 않게 하여 `19` 같은 잘못된 연령이 엑셀에 반영되는 것을 막는다. 검수 화면에서는 비어 있는 후보로 남긴다. 손글씨 연령까지 자동 확정하려면 별도 손글씨 모델(PaddleOCR/PP-OCR 계열 또는 개인정보 처리 기준을 충족한 비전 서비스)을 도입하고 표본 검증을 해야 한다.

### 2.4 학교유형·학년의 처리 원칙

학교유형과 학년은 한 행 안에 여러 문구와 선택칸이 섞인 2단 구조다. 현재는 행 후보가 보여도 열 기하를 독립적으로 검증할 수 없으면 후보 ROI만 표시하고 자동 값을 확정하지 않는다. 이는 잘못된 좌표의 값을 사실처럼 저장하는 문제를 막기 위한 의도된 검수 경계다.

### 2.5 다운로드 엑셀 복구 경고의 원인

다운로드 파일의 `xl/worksheets/sheet1.xml`에 ExcelJS가 지운 `extLst`를 복원할 때, `xr`, `x14`, `xm` 같은 접두사가 루트 `worksheet`에 선언되지 않은 채 삽입될 수 있었다. Excel의 "선언되지 않은 접두사" 복구가 이를 삭제하면서 빈 통합문서처럼 보인 것이다.

복원 시 원본 `worksheet` 루트의 네임스페이스와 `mc:Ignorable` 토큰을 병합하고, 생성 파일에서 확장 XML이 사용하는 미선언 접두사를 검사하도록 수정했다.

## 4. 실사용 PDF 회귀 판정

빈 양식 차분 점수로 실제 PDF 첫 페이지를 판독한 결과는 다음과 같다. 모든 값은 가장 높은 후보가 명확해 고신뢰로 판정됐다.

| 설문 | 기대값 | 회귀 결과 |
|---|---|---|
| CAGI Q1~Q9 | `0, 0, 0, 0, 0, 0, 0, 0, 0` | 모두 `0` |
| 만족도 Q1 | `4` | `4` |
| 만족도 Q2~Q6 | `1, 1, 1, 1, 1` | 모두 `1` |
| 만족도 Q7~Q10 | `4, 4, 4, 4` | 모두 `4` |
| 연령 | `14` | `19 / 신뢰도 55`를 차단, 수동 검수 |

이 결과는 문항 위치와 응답 판독이 해결된 경로와, 손글씨 연령 OCR이 별도의 후속 과제임을 명확히 구분한다.

## 5. 회귀 방지 기준

1. 빈 양식 기준선이 존재하는 양식에서 raw dark-density만으로 응답을 판정하지 않는다.
2. 응답 빈도 가중치는 저신뢰 후보를 자동 확정하거나 ROI 실패를 숨기는 데 사용하지 않는다.
3. 격자 등록 상태가 `verified`가 아니면 자동 저장하지 않는다.
4. PDF·사진 경로 모두 같은 템플릿 등록과 격자 검증을 사용한다. 다만 이미 평면 래스터인 PDF.js 렌더 페이지에는 카메라 전용 원근 보정 Worker를 호출하지 않는다.
5. `extLst`를 복원하는 코드에는 네임스페이스 병합과 ZIP/XML 검증 테스트가 함께 있어야 한다.
6. 개인 스캔본·개인정보가 포함된 PDF·사진은 테스트 고정 자산이나 Git 커밋에 포함하지 않는다.

## 7. PDF 배치 회귀 보완 (2026-08-11.3)

실사용 19페이지 CAGI PDF와 19페이지 만족도 PDF를 PDF.js와 동일한 해상도(1.5배 렌더, JPEG 변환)로 재현해 다시 점검했다.

### 7.1 확인된 원인

1. PDF 페이지도 카메라 사진과 동일하게 OpenCV 원근 보정 Worker로 보냈다. PDF.js가 이미 평면 사각형 이미지를 만들었는데도 Worker 초기화 실패를 페이지마다 다시 기록해, 38개의 동일한 보정 경고가 표시됐다. 이는 보정 실패가 아니라 잘못된 처리 경로였다.
2. 양식 분류는 raw 종이 외곽 기준, 실제 판독은 빈 양식 템플릿 프레임 기준으로 계산되어 있었다. 평면 만족도 PDF가 CAGI 앵커로 점수화될 수 있어, 선택한 업로드 칸과 이미지 양식이 다르다는 오탐이 발생했다.
3. 실사용 PDF에서는 만족도 표의 일부 바깥 세로선과 CAGI 8~9번 표의 내부 가로선이 옅어졌다. 기존 로직은 모든 선이 보여야만 통과하거나, 짧은 표에서 가까운 설명 구분선을 실제 표선으로 잘못 선택했다.

### 7.2 변경 및 안전 경계

- PDF는 카메라 보정 Worker를 호출하지 않고 서버 템플릿 등록으로 전달한다. 직접 사진만 Worker를 준비·실행한다.
- 양식 분류도 CAGI와 만족도 각각의 템플릿 등록 프레임에서 독립적으로 점수화한다.
- 표선 일부가 누락된 경우에는 최소 두 개 이상의 실제 내부선, 거의 동일한 표 비율, 제한된 평행 이동, 후보 셀 중심 일치를 모두 만족할 때만 누락선을 보간한다.
- 표 길이에 비례한 오차 한도를 적용한다. 특히 CAGI 8~9번처럼 짧은 표에서는 인접한 설명선이 행 경계로 들어오는 것을 막는다.
- 선이 많이 보이지만 템플릿 패턴과 다른 큰 표는 보간하지 않고 검수 후보로 남긴다. 응답 빈도 가중치로 자동 확정하지 않는다.

### 7.3 재현 결과

동일 PDF 첫 페이지의 브라우저 렌더본에서 다음을 확인했다.

| 영역 | 변경 전 | 변경 후 |
|---|---|---|
| PDF 보정 경고 | 38개 반복 | PDF 경로에서 발생하지 않음 |
| 양식 분류 | 프레임 불일치 가능 | CAGI / 만족도 각각 올바른 프레임에서 분류 |
| CAGI Q1~Q7 | 검증 가능 | 모두 `verified` |
| CAGI Q8~Q9 | 설명선 오선택으로 후보 | 누락 내부선 보간 후 모두 `verified` |
| 만족도 Q1~Q10 | 외곽선 누락으로 대량 후보 | 내부선 기반 복원 후 모두 `verified` |
| 연령 수기 `14` | OCR이 빈 값 또는 오인식 | 자동 확정하지 않고 검수 유지 |

연령은 좌표 문제가 아니다. 숫자 상자에서 `4`는 분리되지만 `1`이 상자 선과 유사해 일반 Tesseract 영문 숫자 모델이 두 자리 숫자로 신뢰성 있게 읽지 못한다. 개인정보가 포함된 손글씨를 임의 추정해 저장하지 않기 위해, 현 단계에서는 값이 비어 있는 검수 항목으로 유지한다. 전용 손글씨 숫자 모델을 별도 도입할 때에만 자동 확정을 검토한다.
