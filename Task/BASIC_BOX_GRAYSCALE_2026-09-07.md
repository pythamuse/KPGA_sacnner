# 기본정보 체크박스 (회색조) — 계측으로 축을 닫음 (2026-09-07)

표적은 회색조(세트 4)의 학교유형 9칸 + 학년 7칸. 고른 이유는 세 가지가 겹쳐서다: 사용자가 실제로 쓰는 계급이
회색조 600dpi이고, 이 두 필드가 **나이의 범위 재료**이며(나이 14칸이 비어 있다), 성별 오답도 같은 배치 경로다.

**코드는 한 줄도 쓰지 않았다.** 계측이 후보 수정을 먼저 죽였다.

## 1. 표적 크기 — 회색조가 1비트보다 유독 나쁘다

`ok/blank/wrong`, 19쪽:

| 세트 | 나이 | 성별 | 학교유형 | 학년 |
|---|---|---|---|---|
| 1 (1비트) | 8/10/0 | 15/2/0 | 13/6/0 | 16/3/0 |
| 2 (1비트) | 6/12/0 | 11/6/**2** | 13/6/0 | 16/3/0 |
| 3 (1비트) | 7/11/0 | 11/6/0 | 15/4/0 | 15/4/0 |
| **4 (회색조)** | 4/**14**/0 | 15/2/**1** | 10/**9**/0 | 12/**7**/0 |

## 2. 16칸의 분해 (`_probe-tracedump`)

| 집단 | 칸 | 무엇이 막았나 |
|---|---|---|
| **A** | 7 | 채점기는 통과(`refused=none`)했는데 값이 안 들어갔다 — 기본정보 증거 게이트가 거부 |
| **B** | 9 | 채점기의 절대 바닥 미달(최고 점수가 문턱 0.021의 0.10~0.81배). 여기서 얻으려면 문턱을 내려야 하고 §5.4가 금지한다 |

집단 A가 표적처럼 보였다. 채점기는 상자 전체를 36×28로 정렬·형태까지 보고 판정하는데 게이트는 **안쪽 8×8만**
본다. 표시가 테두리에 걸치면 `inner≈0.000`이 되어 강한 신호(p17은 대비 57.6배)도 버려진다.

## 3. 그 수정을 죽인 측정 — 네 세트를 모은 39칸

"채점기가 통과시켰는데 값이 안 들어간" 칸을 네 세트에서 모아, **통과시켰다면 맞았을지**를 정답표로 물었다.

```
39칸  =  CORRECT 28  ·  wrong 11
```

**게이트를 열면 정답 28에 오답 11이 따라온다.** §5.4는 오답이 늘면 정답이 올라도 기각이다.

거부가 옳았던 11칸:

| 반복되는 것 | 칸 | 성격 |
|---|---|---|
| p1 학년 `1학년 → 2학년` | **네 세트 모두** | 취소 표시. 1학년에 굵은 취소 자국, 2학년에 체크 — 규칙이 오답을 막는 장면 |
| **빈칸이어야 하는 칸을 채움** | set1 p3 성별, set3 p12 성별 | 이 프로젝트 최악의 실패 형태 |
| 그 밖 | set2 p4·set3 p3·set4 p15×2·set4 p16 | 이웃 상자 오선택 |

**부분 집합으로도 안전해지지 않는다.** 게이트가 쓰는 `inner`로 잘라 봐도 오답 4개가 그대로 따라온다:

```
inner < 0.0005 :  11 정답 / 4 오답      (set1 p3의 빈칸 채움이 여기 포함된다)
inner < 0.01   :  13 정답 / 4 오답
inner < 0.05   :  15 정답 / 4 오답
```

## 4. 한 세트로 봤으면 틀렸을 것

세트 4만 봤을 때는 상대 대비가 정답(5.12·5.45·57.60배)과 오답(1.49·2.10·2.22배)을 가르는 것처럼 보였다.
네 세트를 모으니 **완전히 겹친다** — 정답 1.02~57.60, 오답 1.15~4.93. n=7에서 잡은 문턱은 그 세트에 맞춘 것이었다.

## 5. 판정

**기본정보 회색조 빈칸은 지금 있는 신호로는 §5.4 아래에서 손댈 수 없다.** 집단 A는 게이트가 순이득을 내고 있고,
집단 B는 문턱 완화 외에 길이 없다. 사이클 6이 1비트에서 링 신호로 닫은 축이 회색조에서는 **더 강한 이유로** 닫힌다 —
그때는 신호가 분리되지 않았고, 이번에는 거부권이 실제로 제 일을 하고 있다.

다시 열려면 새 증거가 필요하다: 상자 밖 표시를 **오답을 늘리지 않고** 잡는 신호, 또는 회색조에서 획을 더 두껍게
얻는 입력 쪽 변경(스캔 설정).

## 6. 집단 B도 측정했다 — 절대 바닥을 내리면 첫 칸이 빈칸 채움이다

§2에서 집단 B(9칸)를 "문턱 완화 외에 길이 없다"로 넘겼는데, 사용자 지시로 실제로 얼마인지 쟀다.
네 세트의 트레이스에서 **바닥 계열(`absolute-floor`·`medium-floor`)만으로 거부된** 칸 —
즉 바닥을 내리면 실제로 들어올 칸 — 을 뽑아 정답표와 맞췄다.

```
들어오는 칸 7개  =  정답 5 · 오답 2
```

| 세트 | 칸 | 채점기 1위 → 정답 | 점수 | |
|---|---|---|---|---|
| set4 | p4 성별 | 여 → 여 | 0.019 | 정답 |
| **set1** | **p16 학교유형** | **고등학교 → 중학교** | **0.018** | **오답** |
| **set1** | **p12 성별** | **남 → 빈칸이어야 함** | **0.017** | **오답(§3 절대 조건)** |
| set3 | p11 성별 | 남 → 남 | 0.017 | 정답 |
| set4 | p14 학교유형 | 중학교 → 중학교 | 0.017 | 정답 |
| set4 | p19 학교유형 | 중학교 → 중학교 | 0.017 | 정답 |
| set4 | p4 학교유형 | 중학교 → 중학교 | 0.015 | 정답 |

**문턱을 어디에 두든 같은 7개다.** 0.014·0.010·0.007·0.005 전부 5/2로 같다 — 오답 둘(0.018·0.017)이
정답들(0.019~0.015) **한가운데** 있어 점수로 갈리지 않는다. 그리고 바닥을 조금이라도 내리면 제일 먼저
들어오는 것이 **[CLAUDE.md](../CLAUDE.md) §3의 빈칸이어야 하는 칸**(set1 p12 성별)이다.

### 두 갈래 합산

| 갈래 | 열었을 때 | 빈칸 채움 |
|---|---|---|
| A. 증거 게이트 | 정답 28 · 오답 11 | 2 |
| B. 절대 바닥 | 정답 5 · 오답 2 | 1 |
| **합계** | **정답 33 · 오답 13** | **3** |

오답 1개당 정답 2.5개다. §5.4 아래에서 **기본정보는 지금 신호로 코드에서 얻을 것이 없다.**

## 7. 대신 입력 쪽에 큰 숫자가 있다

세트 1(1비트)과 세트 4(회색조)는 **같은 학생·같은 종이를 스캔 설정만 바꿔 뜬 것**이다. 기본정보 57칸을
짝지어 채점기 1위 점수를 비교했다:

```
회색조 / 1비트   중앙값 0.339   (p10 0.065 · p90 0.908)
```

**같은 연필 자국이 1비트로 스캔하면 약 3배 진하게 잡힌다.** 빈칸 수도 그대로 따라간다 —
학교유형 6칸 대 **9칸**, 학년 3칸 대 **7칸**.

절대 바닥 `0.021`은 **두 계급에 똑같이** 적용된다. 트레이스에 `class=grayscale-scan`이 찍히고
`GRAY_CLASS`가 기준선은 계급별로 스케일하는데, 바닥은 스케일하지 않는다. 그렇다고 바닥을 계급 상수로
보정할 수도 없다 — 비율 분포가 0.02~0.91로 너무 넓어 상수가 아니고, §6이 보여주듯 낮춘 바닥이
집어오는 첫 칸이 빈칸 채움이다.

## 8. 1비트 표본이 오면 잴 것 (사용자가 준비 중)

같은 9명을 **흑백 1비트**로 다시 스캔한 것을 받는다(600dpi 유지, Epson Scan 2의 이미지 유형만 변경).

**정답표 없이 판정한다.** 새 표본의 정답표는 앱 내보내기라 정확도 판정에 못 쓴다
([Docs/18](../Docs/18_GROUND_TRUTH_VALIDITY.md)). 대신 두 축으로 잰다:

1. **자동 입력 칸 수** — 기본정보 4필드가 회색조 대비 몇 칸 더 채워지는가. 값이 맞는지와 무관하게
   비교 가능하고, 이 라운드의 가설(입력이 병목)을 직접 시험한다.
2. **두 스캔의 값 일치** — 같은 종이를 두 설정으로 뜬 것이므로 자동값이 서로 달라지면 둘 중 하나가 오답이다.
   불일치 칸만 종이로 확인한다(§3.1의 "코드를 의심하기 전에 종이를 본다").
3. **나이 연동** — 회복된 학년·학교유형이 `12+N±1` 범위를 만들어 나이가 몇 칸 따라 오르는지.
   배포본 4/9의 나머지 5칸이 전부 범위 부재이므로 여기가 직접 연결된다.

회복 폭이 크면 "회색조로 스캔하지 마라"가 근거 있는 운영 안내가 된다. 작으면 입력 가설도 닫히고,
기본정보는 새 신호가 나올 때까지 손대지 않는다.

### 8.1 결과 (2026-09-07 저녁) — 입력 가설도 닫힘. 전체는 좋아졌고 기본정보는 그대로

사용자가 같은 9명을 흑백으로 다시 떴다. 표기는 100dpi였지만 파일은 **1654×2337 = 200dpi, 1비트 CCITTFax** —
세트 1~3과 같은 형식이다. 회색조 원본(600dpi)과 정답표 없이 짝 비교했다(`bitcompare/`).

| | 회색조 600dpi | 흑백 200dpi |
|---|---|---|
| 자동 입력 (207칸) | 145 | **158** (+13) |
| 미확정 빈칸 | 62 | **49** |
| **기본정보 (36칸)** | **23** | **23 (변화 없음)** — 나이 +1 · 성별 −1 · 학교유형 0 · 학년 0 |
| 나이 | 4/9 | 5/9 |
| 파일 크기 | 19.7MB | 437KB |

**+13은 전부 CAGI·만족도 표에서 나왔다.** 기본정보는 필드 합계가 같고 학생별로 요동만 친다 — p2는 회색조에서 4칸이
다 차는데 흑백에서 4칸이 다 빈다(등록 정상, 신뢰도 high→medium으로 보류), p1·p5·p8은 반대로 흑백에서 회복된다.
같은 종이가 스캔 한 번에 이만큼 흔들린다는 것이 이 신호가 얼마나 경계에 있는지를 보여준다.

**두 스캔이 모두 채운 123칸 중 불일치는 1칸**: `p7 satisfaction.q01` 흑백=4, 회색조=3. 이 칸은 종이로 확인된 것이
있다(④ 표시, ③ 깨끗) — **회색조가 틀렸고 흑백이 맞다.** 정답표 대조도 같은 방향(불일치 3 → 2). 나이는 두 스캔 모두
채운 칸이 전부 정답표와 일치한다(4/4, 5/5).

**판정**: 입력 쪽 가설은 기본정보에 대해서는 **기각**. 오늘 코드 두 갈래(§3·§6)와 입력(§8.1)이 모두 닫혔다.
다만 운영 권고는 나왔다 — **흑백 200dpi로 스캔하는 편이 낫다**(자동 +13, 확인된 오답 1 제거, 파일 45배 축소).
비트 깊이와 해상도가 함께 바뀌어 원인은 못 가르지만, 어느 설정으로 뜰지에 대한 답으로는 충분하다. 가르려면 600dpi 흑백 한 벌.
