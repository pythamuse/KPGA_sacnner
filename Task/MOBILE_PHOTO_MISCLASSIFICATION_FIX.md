# 휴대폰 촬영 사진 양식 오판정 수정

> 이 문서는 기존 `Docs/20_MOBILE_PHOTO_FORM_MISCLASSIFICATION_FIX.md`를 이전한 문서입니다.

## 배경

사용자가 실제 모바일 기기에서 "개별/순차 촬영" 모드로 실제 종이 서류를 직접 촬영해 테스트했다. 만족도조사 칸에 만족도조사 사진을 올렸는데도 다음과 같은 오류가 발생했다:

> `satisfaction_....jpg` 파일은 만족도조사 칸에 업로드됐지만, 이미지 내용은 선별검사지 양식으로 보입니다. 올바른 칸에 다시 업로드해주세요.

## 작업 내용

### 원인 분석

`src/lib/recognition/classifyForm.ts`의 `classifyByImageContent`는 파일명 힌트(업로드 칸)와 별개로, 이미지 내용을 분석해 CAGI/만족도 각각의 정규화 ROI 좌표에서 어두운 픽셀 밀도를 측정하고 점수가 더 높은 쪽으로 판정을 덮어쓴다. 이 정규화 좌표는 `src/lib/recognition/markDensity.ts`의 `detectFrameBounds`가 종이 테두리를 직선으로 정확히 찾아낸다는 전제 위에서만 신뢰할 수 있다 — 스캐너/PDF처럼 원근 왜곡이 없는 이미지에서는 잘 동작한다.

하지만 휴대폰 카메라로 책상 위 종이를 촬영하면 원근 왜곡·기울기·불균일한 조명 때문에 `detectFrameBounds`가 깨끗한 직선 테두리를 찾지 못하는 경우가 흔하다. 이 경우 더 거친 대체 로직(`detectContentBounds`)으로 넘어가는데, 이 대체 경계는 실제 종이 위치와 어긋나기 쉬워 ROI 좌표가 엉뚱한 부분을 샘플링하게 된다. 그 결과 내용 기반 점수가 노이즈에 가까워지고, 실제로는 만족도조사인 사진이 CAGI로 오판정되는 사례가 발생했다.

### 수정 내용

- `src/lib/recognition/markDensity.ts`: `ImageAnalysisData`에 `contentBoundsConfident: boolean` 필드 추가. `loadImageAnalysisData`가 `detectFrameBounds`를 한 번만 호출해 결과를 재사용하고, 테두리 검출 성공 여부를 기록.
- `src/lib/recognition/classifyForm.ts`: `classifyByImageContent`가 `image.contentBoundsConfident`가 `false`이면 즉시 `'unknown'`을 반환해 파일명 힌트를 그대로 신뢰하도록 함. 즉 테두리를 신뢰성 있게 검출한 경우(스캐너/PDF 품질)에만 내용 기반 판정이 파일명 힌트를 뒤집을 수 있고, 휴대폰 촬영처럼 테두리 검출이 실패한 경우엔 사용자가 선택한 업로드 칸을 그대로 존중.

기존 "양식 오인식 감지" 안전장치(`Docs/00_PRD.md`에 명시된 의도된 기능)는 테두리가 잘 검출되는 스캐너/PDF 경로에서는 그대로 유지된다.

구현은 Codex CLI(GPT-5.5, `--dangerously-bypass-approvals-and-sandbox`)에 위임하고 결과 diff를 리뷰해 스펙과 정확히 일치함을 확인했다. Codex가 짠 코드에는 회귀 테스트가 없어서, 테두리 없는 합성 이미지(체크 표시는 CAGI 레이아웃을 흉내내지만 테두리 사각형은 그리지 않음)를 만족도 칸에 업로드했을 때 파일명 힌트(`satisfaction`)를 따르는지 검증하는 테스트를 `tests/form-classifier.test.ts`에 직접 추가했다.

## 다음 작업을 위한 피드백

- 실제 문제를 일으킨 사용자의 원본 휴대폰 사진 파일은 서버에 보존되지 않아(임시 파일) 직접 재현·회귀 테스트에 사용할 수 없었다. 이번 수정은 코드 분석을 통한 원인 진단과 그 진단을 정확히 반영하는 합성 테스트로만 검증했다.
- **배포 후 사용자가 동일한 사진으로 재테스트해 실제로 통과하는지 최종 확인 필요** — 아직 확인되지 않음.

## 2026-08-05 재발 분석 및 2차 수정

### 관찰

새 샘플의 실제 내용은 다음과 같이 정상이다.

- `만족도조사 샘플.jpg`: 예방교육 후 만족 및 평가 설문
- `선별검사 샘플.jpg`: 도박문제 선별검사지

두 원본을 현재 `markDensity` 로직에 직접 대입하면 모두 신뢰 가능한 외곽 프레임을 찾지 못한다(`contentBoundsConfident === false`). 따라서 원본 파일이 수정 없이 서버에 전달됐다면, 기존 방어 로직은 파일명 힌트를 따라야 하며 만족도조사를 CAGI로 뒤집을 수 없다. 화면에 표시된 `satisfaction_...jpg` 오류는 다음 두 경우 중 하나로 설명된다.

1. 파일 선택·카메라 경로에서 OpenCV Worker가 원본을 보정본으로 바꾸었고, 보정 결과의 내부 표를 문서 외곽으로 잘못 선택했다.
2. 보정된 이미지 또는 이전 배포본에서 프레임이 신뢰된 것으로 처리되어, 어두운 픽셀 밀도 점수가 업로드 칸 힌트를 뒤집었다.

### 직접 원인

기존 Worker는 Canny/adaptive threshold에서 찾은 **모든 convex 4점 사각형 중 기하학 점수가 가장 높은 후보**를 보정에 사용했다. 이 점수에는 “실제 페이지 외곽인지”, “문서 내부 표인지”, “보정 후 양식 구조가 유지됐는지” 검사가 없었다. 내부 표가 페이지 크기로 확대되면 서버의 프레임 검출과 양식 ROI 점수가 모두 그릇된 좌표를 기준으로 계산된다.

또한 서버 양식 분류는 선택지 주변의 어두운 픽셀 밀도만 비교하므로, 만족도조사의 긴 표 선이 CAGI 선택지 영역의 밀도로 잘못 누적될 수 있었다. 제목이나 표의 의미를 읽는 분류기가 아니므로, 단일 점수 우세만으로 양식 유형을 확정하는 것은 안전하지 않다.

### 2차 수정

- `src/lib/documentScanner/perspectiveCorrect.ts`: 평균 사각형 폭이 입력 폭의 55% 미만이거나 평균 높이가 입력 높이의 70% 미만인 후보를 문서 외곽으로 거부한다. 내부 표를 페이지 크기로 확대하는 보정 경로를 차단한다.
- `src/lib/recognition/markDensity.ts`: 프레임 후보의 위·아래·왼쪽·오른쪽 네 변이 충분히 연속적인지 확인한다. 긴 가로 표 선과 짧은 세로선 조합은 `contentBoundsConfident === false`로 처리한다.
- `src/lib/recognition/classifyForm.ts`: 만족도 문항 7~10의 5점 척도와 CAGI 상단 기본정보 영역을 양식별 signature로 추가한다. 전체 배치 점수, signature 점수, 최소 점수 차이를 모두 만족한 경우에만 파일명 힌트를 뒤집고, 그 외에는 `unknown`을 반환해 업로드 칸을 존중한다.

### 검증

- `tests/form-classifier.test.ts`: 기존 양식 판별 및 경계 없는 휴대폰 사진 fallback 통과
- `tests/recognize-form-mismatch.test.ts`: 고품질 합성 이미지의 업로드 칸 불일치 감지 유지
- `tests/perspective-correct.test.ts`: 내부 표 사각형을 문서 외곽으로 채택하지 않음
- `tests/recognition-mark-density.test.ts`: 끊어진 내부 프레임을 신뢰하지 않음
- 대상 테스트 4개 파일, 16개 테스트 통과

### 남은 확인 사항

- 개인정보가 포함된 실제 샘플은 저장소에 커밋하지 않는다.
- 실제 Vercel 배포가 이번 수정 커밋을 사용하고 있는지 확인한 뒤, 새 샘플로 만족도조사·선별검사지 각 1장씩 재검증해야 한다.
- 실제 보정본이 생성된 경우에는 보정 미리보기에서 문서 전체와 제목·표·하단 영역의 순서가 유지되는지도 함께 확인해야 한다.
