# 사진 일괄 등록의 순서 보장과 촬영 프레임 — 현황·제안·라운드 (2026-09-09)

사용자 요청 둘: (1) 촬영 외에 **사진 목록 일괄 등록**을 두되 세트별 순서가 어긋나는 것을 막을 방법을 제안(모바일에서는 선택할 때마다
사진 옆에 순서 숫자를 표기). (2) 카메라에 **프레임**을 넣어 문서를 맞춰 찍게 하고, 프레임 대비 틀어짐·기울어짐(사다리꼴)을 판정하고
밝기 문제는 재촬영을 요구.

## 2. 순서가 어긋나는 경로 세 가지

1. **OS 선택기가 주는 순서가 선택 순서가 아니다.** 안드로이드 사진 선택기는 대체로 탭한 순서지만, iOS는 앨범 정렬(촬영 시각)이나
   불확정 순서로 돌려준다. 같은 19장을 두 번 고르면 다른 순서가 올 수 있다.
2. **앞면 묶음과 뒷면 묶음을 따로 고른다.** 한쪽에서 한 장을 빼먹거나 순서를 바꾸면 장수가 같아도 짝이 밀린다. 지금 장치는 장수 비교뿐이다.
3. **스캐너 PDF는 뒷면이 역순**이다(이미 토글로 해결).

## 3. 제안 — 채택안

**원칙: 순서를 사용자 기억에 맡기지 않고, 기기가 가진 사실(촬영 시각)로 정한 뒤 숫자로 보여 주고, 두 묶음의 시각을 맞춰 본다.**

- **A. 결정적 정렬.** 선택된 이미지는 EXIF `DateTimeOriginal` → 없으면 `File.lastModified` → 파일명 숫자 순으로 정렬한다. 선택기가 어떤 순서로
  주든 같은 결과. 현장에서 학생 순서대로 찍었다는 사실 하나만 가정한다.
- **B. 숫자 표기 목록(사용자 제안).** 선택 직후 업로드하지 않고 **번호 붙은 썸네일 목록**을 먼저 보여 준다. 각 장에 ①②③… 번호와 촬영 시각,
  빼기·위/아래 이동 버튼. "이 순서로 등록"을 눌러야 보정·업로드가 시작된다. OS 선택기 안에 숫자를 그릴 수는 없으므로(웹에서 접근 불가)
  선택기가 닫힌 직후 화면이 그 역할을 한다.
- **C. 짝 대조 띠.** 두 묶음이 다 들어오면 n번 학생 = 앞면 n번 썸네일 + 뒷면 n번 썸네일을 나란히 보여 준다(역순 토글 반영). 사람이 짝을
  눈으로 확인하는 마지막 관문.
- **D. 시각 정합 경고.** 두 묶음 모두 촬영 시각이 있으면, 짝지은 뒤 뒷면 시각이 앞면 순서와 단조롭지 않거나 짝 사이 간격이 이상하게 크면
  "n번 학생의 앞·뒷면 촬영 시각 순서가 다릅니다"를 띄운다. 자동으로 고치지 않는다 — B의 목록에서 사람이 옮긴다.
- **E. (다음 라운드) 한 번에 전부 선택.** 38장을 한 번에 고르면 시각순 정렬 후 양식 분류(`classifyForm`, 서버에 이미 있음)로 앞면·뒷면을 자동 분리하고
  짝짓는다. 두 묶음 문제(§2-2) 자체가 사라진다. 촬영 흐름이 "앞·뒤·앞·뒤"든 "앞 19장 → 뒤 19장"이든 시각순+분류로 같은 결과.

이번 라운드는 **A·B·C·D**를 구현한다. E는 분류 오류 시 짝이 통째로 밀리는 위험이 있어 별도 판정.
