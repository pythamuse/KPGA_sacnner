# 최신 양식 불일치 재발 대응

## 재현 범위

- 화면의 임시 표시 `테스트 버전 v2026-08-05.4`가 보이는 최신 프론트엔드에서, 선별검사지 사진을 선별검사지 칸에 올려도 `FORM_TYPE_MISMATCH`가 발생했다.
- 사용 샘플은 기존 `선별검사 샘플.jpg`, `만족도조사 샘플.jpg`와 동일하다.

## 분석 결과

1. 이전에 의심한 구 배포본은 화면 버전 표기로 제외했다.
2. 원본을 브라우저 업로드 크기 수준으로 축소한 뒤 서버 분류를 수행했을 때, 두 샘플은 각각 올바르게 CAGI와 만족도조사로 분류됐다.
3. 따라서 단순 이미지 축소는 직접 원인이 아니다.
4. 클라이언트 보정 Worker는 문서 외곽 사각형을 찾지 못한 경우에도 내부 표의 긴 선으로 기울기를 추정해 자동 deskew를 수행했다. 이 경로는 전체 이미지를 고정 템플릿 크기로 다시 만들기 때문에, 내부 표를 기준으로 한 보정본이 이후 양식 분류를 오염시킬 가능성이 있다.

## 수정 내용

- `src/lib/documentScanner/perspectiveCorrect.ts`: 보정 사각형은 폭 70%, 높이 78%, 네 변이 원본 외곽 20% 안에 있는 경우에만 통과한다. 서버의 문서 프레임 검증과 같은 기준이다.
- `src/lib/documentScanner/perspectiveCorrect.worker.ts`: 신뢰된 문서 외곽 사각형이 없을 때의 자동 deskew와 고정 크기 리사이즈를 제거했다. 신뢰된 원근 보정만 새 파일로 만들며, 그 외에는 원본이 업로드된다.
- `src/app/api/recognize/route.ts`: 자동 판정이 업로드 칸과 충돌하면 기본적으로 중단한다. 사용자 승인 요청에 한해 선택한 업로드 칸을 사용하고, 검수 단계에 경고를 남긴다.
- `src/app/page.tsx`: 불일치 응답에서만 사용자에게 선택한 업로드 칸을 기준으로 계속 진행할지 묻는다. 자동으로 우회하지 않는다.
- 인식 정책 버전은 `2026-08-05.4`, 화면 임시 테스트 표시는 `v2026-08-05.5`다.

## 검증 기준

1. `GET /api/recognize`가 `recognitionPolicyVersion: "2026-08-05.4"`를 반환한다.
2. 페이지 오른쪽 상단에 `테스트 버전 v2026-08-05.5`가 보인다.
3. 동일 샘플을 각 칸에 올려 검수 화면으로 이동하는지 확인한다.
4. 불일치가 남아도 사용자가 선택한 업로드 칸 우선을 승인하면 검수 화면으로 진행하고, 원본 검토 경고가 표시되는지 확인한다.

## 남은 위험

이 변경은 Worker가 생성한 실제 브라우저 보정본을 프로덕션에서 다시 검증해야 최종 확정할 수 있다. 새 보정본을 직접 저장하지 않는 현재 구현에서는, 사용자 테스트 시 화면 버전과 API 정책 버전을 함께 기록해야 재현 경로를 정확히 비교할 수 있다.
