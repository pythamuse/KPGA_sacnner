# 작업 A — 약한 표시의 마킹 판별 (2026-08-20~)

기본정보·만족도 문항1·CAGI 8·9의 빈칸이 **하나의 뿌리**를 공유한다. 좌표는 검증됐고(`src=grid`) 표시도 실제로 있는데, **신호가 약할 때 인쇄 잔여와 구분하지 못해** 자동 입력이 막힌다.

상위 문서: [Docs/00_PRD.md §10-1](../Docs/00_PRD.md) — 자동 입력률이 제품 성립 조건이다.
선행 스레드: [[MEASUREMENT_RENDER_PARITY_2026-08-19]]

## 1. 배경 — 반드시 먼저 읽을 것

### 1.1 이미 네 번 실패했다

잉크 경로를 건드린 시도가 모두 배포본 해상도에서 악화됐다. **같은 방식을 반복하지 마라.**

| 시도 | 결과 |
|---|---|
| 면적 평균 리샘플링 (상대 대비 없이) | WRONG 1 → 4 |
| 빈 양식 3×3 팽창 차감 | CORRECT 92 → 64 |
| 인셋 대칭화 (양쪽 20%) | 기본정보 13 → **0** |
| 면적 평균 리샘플링 (상대 대비 있이) | scale 1.5에서 WRONG 0 → 4 |

**임계값·인셋·리샘플링 방식 조정은 이 작업의 대상이 아니다.** 판별에 쓰는 **특징(feature) 자체**를 바꾸는 것이 이번 과제다.

### 1.2 현재 판별 방식

두 개의 게이트가 순서대로 걸린다.

1. **`analyzeChoiceGroup`** (`markDensity.ts`) — 빈 양식 차분 후 잉크 총량으로 점수를 매기고, 절대 하한(`HIGH_ABSOLUTE_SIGNAL = 0.021`) + 상대 대비(`HIGH_RELATIVE_CONTRAST = 1.25`) + 형태 게이트(`hasStructuredTemplateMark`)를 통과해야 `high`.
2. **`hasUniqueDirectCheckboxEvidence`** (`detectCheckmarks.ts:649`) — 기본정보 전용. 후보 박스 내부에 잉크가 있는 칸이 **정확히 하나**여야 자동 확정.

### 1.3 확정된 실패 메커니즘

**(a) 기본정보 — 게이트 2가 막는다.** 실사용 6명 전원 보류이며, 다음이 결정적이다.

```
학생 4 성별: 여 21% / 남 4%  (5.25배)  →  보류
학생 6 성별: 여 15% / 남 3%  (5.00배)  →  보류
```

배수가 5배인데도 막힌다. 상대 대비(1.25)는 여유롭게 통과하므로 **`hasUniqueDirectCheckboxEvidence` 하나가 원인**이다. 인쇄된 체크박스 테두리 잔여 때문에 **두 칸 모두 "잉크 있음"**이 되어 모호로 떨어진다.

**(b) 만족도 q01·CAGI 8·9 — 게이트 1이 막는다.** 좌표는 `src=grid`인데 `conf=low`다.

**(c) 약한 표시는 노이즈와 구분되지 않는다.** 한 페이지에서 실측한 값:

```
정상 페이지 정답:  0.067
약한 페이지 정답:  0.011   ← 6배 흐림
같은 칸 인쇄 잔여: 0.020   ← 정답보다 높음
```

절대 하한 0.021은 이 오답을 막지만, 동시에 약한 진짜 표시도 함께 막는다.

## 2. 목표와 합격 기준 (착수 전 확정)

`REAL_SCAN_RENDER_SCALE` 기본값(배포본 래스터)에서 6페이지를 측정한다.

| # | 기준 |
|---|---|
| **필수** | **`WRONG = 0`.** 하나라도 늘면 즉시 기각. 예외 없음 |
| **필수** | 전체 `CORRECT ≥ 102` (현재 기준선) |
| **목표** | 기본정보 자동 입력 증가 (현재 성별 3/5·학년 3/6·학교유형 5/6) |
| **목표** | `satisfaction.q01` 2칸, `cagi.q08`·`cagi.q09` 2칸 회복 |
| 상한 | 넷을 다 회복하면 `CORRECT 112` |

**빈칸과 오답을 맞바꾸지 않는다.** 빈칸은 검수자의 키 입력 한 번이지만, 오답은 사람이 확인한 것처럼 중앙 시스템에 저장된다.

## 3. 방향 제안 (하나를 고르고 이유를 문서에 남길 것)

### 방향 1 — 인쇄 요소와 연결되지 않은 성분으로 판정 (권장)

지금은 "칸 안에 잉크가 있는가"를 본다. 대신 **"빈 양식에 잉크가 없던 자리에 새 성분이 있는가"**를 본다.

- 빈 양식 셀을 이진화해 인쇄 마스크를 만든다
- 실제 셀의 잉크 중 **인쇄 마스크에 닿지 않는 연결 성분**만 남긴다
- 그 성분의 크기·개수로 판정한다

손으로 그린 동그라미·체크는 인쇄 원/박스를 **가로지르거나 벗어나므로** 반드시 마스크 밖 성분을 남긴다. 반면 정렬 오차로 생기는 테두리 잔여는 인쇄 획에 **붙어 있다**.

### 방향 2 — 잉크 무게중심의 편향

인쇄 요소는 셀 중앙에 대칭으로 놓인다. 손 표시는 한쪽으로 치우친다. 차분 잉크의 무게중심이 셀 중심에서 얼마나 벗어났는지를 특징으로 쓴다.

### 방향 3 — 게이트 2를 완화하되 근거를 강화

`hasUniqueDirectCheckboxEvidence`가 "잉크 있는 칸 == 1"을 요구하는 것을 "**방향 1의 마스크 밖 성분이 있는 칸 == 1**"로 바꾼다. 게이트를 없애는 것이 아니라 판정 근거를 교체하는 것이다.

## 4. 제약 (위반 시 되돌림)

1. **`WRONG`을 늘리지 마라.** 유일한 절대 조건이다.
2. **필드명·후보 인덱스로 분기하지 마라.** `field === 'basic.gender'` 같은 예외는 표본에 코드를 맞추는 것이며 금지다. 수정은 판별 방식의 일반적 성질이어야 한다.
3. **소유 파일**: `src/lib/recognition/basicCheckboxDetection.ts`, `src/lib/recognition/detectCheckmarks.ts`, `src/lib/recognition/markDensity.ts`. **이 셋 외의 소스 파일을 수정하지 마라** — 다른 작업이 `src/lib/recognition/ocrTextLines.ts`에서 동시에 진행 중이다.
4. **`tests/real-scan-measure.test.ts`, `local-scans/`, `templates/`, `src/lib/recognition/assets/`를 수정하지 마라.** 계측기와 정답표를 고쳐 숫자를 맞추는 것은 금지다.
5. **병렬 판별 경로를 추가하지 마라.** 기존 경로를 고치되, 두 번째 판별기를 나란히 두면 어느 쪽이 판정했는지 알 수 없게 된다.
6. `npm test`·`npm run build` 통과. 버전 마커는 갱신하지 마라(병합은 지휘자가 한다).

## 6. 사이클 기록

### 사이클 1 — 판별 특징을 인쇄 독립 면적으로 **교체** (기각)

`CORRECT 102 → 57`. CAGI·만족도는 인쇄 글자를 **감싸는** 동그라미라 마스크 밖 면적이 남지 않는다. 합성에서는 전 항목 개선으로 보였다 → [[15_FAILURE_ELIMINATION_TABLE]] G6, G9

### 사이클 2 — 농도와 인쇄 독립성의 **최대값** (기각)

`CORRECT 102 → 101`. 게이트만 원복한 변형은 정확히 102로 이득 0. 상대 대비는 후보 **간** 비교이므로 2등이 오르면 1등이 막힌다(`satisfaction.q07` ok→BLANK) → G6-b, G6-c

### 사이클 3 — 게이트의 판정 근거 교체 (기각)

`hasUniqueDirectCheckboxEvidence`의 칸별 술어를 "빈 양식보다 어두운 표본이 있다"에서 **"빈 양식에 없던 연결 획이 있다"**로 바꿨다. 등록 정합 후 인쇄 잉크에 인접한 잔여를 버리고, 남은 잉크가 박스 면적의 7% 이상·가로세로 각각 25% 이상을 차지하는 **연결 성분**을 이룰 것을 요구한다.

**결과: `CORRECT 102 → 97`. `WRONG`은 0 유지.**

| p | 항목 | 기준선 | 사이클 3 |
|---|---|---|---|
| 1 | gender | ok `여` | **BLANK** |
| 2 | schoolType | ok `중학교` | **BLANK** |
| 2 | grade | ok `2학년` | **BLANK** |
| 3 | grade | ok `3학년` | **BLANK** |
| 4 | schoolType | ok `중학교` | **BLANK** |

**5칸 손실, 0칸 회복.** 기본정보 자동 입력 `11 → 6`.

게이트가 느슨해진 것이 아니라 **더 엄격해졌다.** 배포본 래스터에서 기본정보 박스는 13px이므로 "가로세로 25% 이상"은 약 3×3셀, "면적 7%"는 169셀 중 12셀이다. 실제 스캔의 옅은 체크는 이 문턱에 닿지 않는다. 합성으로 잰 분리(무표시 ≤9셀 / 체크 14~19셀)가 실제 필기에는 성립하지 않았다.

**[[15_FAILURE_ELIMINATION_TABLE]] G9의 세 번째 사례다.**

### 사이클 3이 남긴 것 — 진단은 유효하다

코드는 되돌렸으나 측정 두 가지는 살아 있다. 둘 다 **인쇄물을 배포본 래스터로 축소한 실제 인쇄면**에서 얻은 것이다.

| # | 사실 | 의미 |
|---|---|---|
| A1 | **표시가 전혀 없는 페이지에서 기존 술어가 성별 두 칸 모두 "잉크 있음"으로 답한다. 신호 최대 `0.0815`** | 점수기의 절대 하한 `0.021`의 **4배**. 성별 보류는 애초에 표시 판별 문제가 아니라 **인쇄 잔여** 문제였음이 확정됨 |
| A2 | **`matchBasicCheckboxes`가 성별 박스를 12px 박스에서 ~5px 어긋나게 놓는다** | 창의 42%가 어긋나면 인쇄 테두리가 창 한가운데 들어온다. **어떤 내부 판별식을 써도 인쇄를 본다.** 이 코드는 `basicCheckboxDetection.ts`에 있어 이번 작업의 소유 밖이었다 |
| A3 | 빈 양식 자산이 런타임 래스터의 ~1.85배다 | 고정 3px/4px 인셋이 두 창에서 서로 다른 비율(25% vs 18%)을 덮는다. **계측기(11칸 자동 입력)와 실사용(0칸)의 격차를 설명할 후보** |

A2가 사실이라면 그것이 L3의 진짜 뿌리다. 판별식이 아니라 **창의 위치**가 틀린 것이다.

**단 A1~A3는 축소한 빈 양식에서 잰 값이며 실제 스캔에서 확인하지 않았다.** 합성이 세 번 속인 뒤이므로, 다음 라운드는 고치는 것이 아니라 **실제 스캔에서 이 배치 오차를 숫자로 노출하는 계측**이다. 연령 OCR에서 같은 순서(계측 → 판정 → 수정)가 통했다.

### 8.2 기전

**6~17px 튄 창은 엉뚱한 인쇄물 위에 내려앉아 "두 번째 표시"를 만들어낸다.** 게이트는 주어진 증거에 대해 **정확히 옳게** 두 표시 사이에서 선택을 거부한다. p4 성별은 더 나쁘다 — 창 #1이 12.6px 튀어 진짜 표시를 **아예 보지 않으므로** 증거 없음으로 거부된다.

**게이트도 판별식도 결함이 아니었다.** 사이클 1~3은 모두 **오염된 입력에 대해 제 일을 하고 있던 함수**를 고치고 있었다. 계측을 먼저 하지 않은 것이 세 사이클을 태운 원인이다.

### 8.3 배치가 튀는 원인 후보 — 크기가 정확히 맞는다

`deduplicateCandidates`는 정규화 0.008 이내의 후보를 억제하고, 그 안에서는 `frameScore`만으로 승자를 정한다. 배포본 래스터에서 0.008은 **가로 약 7.1px, 세로 약 10.1px**다.

관측된 변위: **5.8, 6.6, 8.2, 8.4, 11.4, 12.6, 17** — **두 축 모두 같은 척도다.**

`match=1`이 6페이지 전부에서 나오므로 12개 정합 자체는 성공한다. 손상은 **성공한 정합 안의 개별 박스**에서 일어난다.

### 8.4 기각된 것

| 가설 | 결과 |
|---|---|
| 성별 창이 **계통적으로** ~5px 어긋난다 | **기각.** 실제 스캔에서 대부분의 `off`는 −0.3 ~ −2.8px. 계통 편향 없음 |
| 빈 양식의 성별 기준 박스가 잘려서(`22x20`) 생기는 문제다 | **기각.** 잘림은 실재하나 배치 오차와 상관되지 않음 |
| 판별식(무엇을 표시로 볼 것인가)이 원인이다 | **기각 3회** (G6, G6-b, 사이클 3). 원인은 **창의 위치**다 |

### 8.5 예측

다섯 칸이 배치 교정만으로 열린다: `p1 grade`, `p4 gender`, `p4 grade`, `p6 gender`, `p6 grade` → **`CORRECT 102 → 107`**.

## 9. 사이클 5 — 배치 교정 (병합 `981bc36` 이후, `CORRECT 103 → 105`)

### 9.1 방향 — dedup 반경이 아니라 **적합 결과를 강제**

2. 그 잔차들의 **중앙값 절대편차(MAD)**가 그 페이지 자신의 배치 정확도다 — 깨끗한 스캔이면 좁고 나쁜 스캔이면 넓다

### 11.1 규칙

지목된 칸이 잉크를 갖고, 다른 모든 칸을 **4배** 이상 앞서며, **다른 어떤 칸도 0.025를 넘지 않을 것.**

**두 곳에 표시된 용지를 여전히 거부하는 것은 비율이 아니라 절대 상한이다.** 진짜 표시가 둘이면 한쪽이 진한 순간 비율은 얼마든지 커지므로, 지배만으로는 이 게이트가 존재하는 이유인 바로 그 용지를 자동 입력한다. 두 번째 펜 자국은 **자기 힘으로** 0.025 아래여야 하는데, 이 프로젝트에서 측정된 표시는 전부 0.035 이상이다.

## 12. 사이클 8~9 — 점수기의 정렬 탐색 (병합, `CORRECT 106 → 107`)

### 12.1 계측이 찾은 것 — 정렬 탐색이 126개 중 87개에서 벽에 붙어 있었다

`BASELINE_ALIGNMENT_RADIUS = 1`은 **리샘플 표본** 단위다. 표본 간격은 셀 크기에 비례하므로 물리적 도달 범위가 셀이 작을수록 줄어든다.

| 셀 | 박스 크기 | 표본당 원본 px | 탐색 도달 |
|---|---|---|---|
| `basic.gender` | 22×20 | 0.61, 0.71 | **±0.6 px** |
| `cagi.q01` | 30×42 | 0.83, 1.50 | ±0.8 px |
| `satisfaction.q01` | 41×58 | 1.15, 2.09 | ±1.2 px |

**등록 오차를 흡수하라고 만든 탐색이 거의 아무것도 흡수하지 못했다.**

### 12.2 그래서 빈 칸에 점수가 붙는다 — 정류(rectification)가 어긋남을 신호로 바꾼다

p3 gender(정답표상 **무표시**):

```
2:scr=0.047 page=0.145 blank=0.204 shift=0 align=1,1!
1:scr=0.016 page=0.176 blank=0.252
```

**지목된 칸의 `page`가 `blank`보다 밝은데 점수가 양수다.** `max(0, page − blank − 0.08)`이 표본마다 적용되므로, 인쇄 테두리가 픽셀 일부만큼 어긋나면 어두워진 쪽만 남고 밝아진 쪽은 잘린다. 남는 것은 학생과 무관한 **잔여 고리**이며, 22×20 박스에서 2px 테두리는 면적의 **36%**다.

**두 결함은 대안이 아니라 곱해진다.** 정류가 어긋남을 점수로 바꾸고, 그 어긋남을 없앨 탐색이 닿지 못한다.

### 12.3 수정 — 반경을 셀 자신의 표본 간격에서 유도 (원본 픽셀 약 1개)

하한 1(이미 표본당 1px 이상인 셀은 불변), 상한 4(1px를 넘으면 흔들림이 아니라 등록 실패).

**왜 G5(빈 양식 팽창, `92→64`)와 다른가.** 탐색이 최소화하는 것은 `Σ|page − blank|` — **대칭** 절대차이지, 점수가 되는 일방향 잔여가 아니다. 빈 양식 잉크를 펜 획 위로 미끄러뜨리면 그 아래 차이는 줄지만, **원래 자리에서 사라지고 없던 자리에 생기므로 두 번 손해**다. 게다가 인쇄 잉크가 펜보다 훨씬 많다(`blank=0.251` vs `page=0.079`). 최소점은 인쇄 대 인쇄 정합에 그대로 있고, **반경을 넓히는 것은 그 최소점에 닿게 할 뿐 옮기지 않는다.**

팽창은 **감수(subtrahend)에 잉크를 더했다**. 평행이동은 잉크를 더하지 않고 **같은 잉크가 어디 놓일지만** 고른다. 구조적으로 반대다.

**숨은 지뢰**: 반경 > 1에서 기존 루프가 배열 끝을 넘어 읽어 `NaN`을 만들고, `NaN < best`는 항상 거짓이라 **변경 전체가 조용한 무동작**이 될 뻔했다. 비교 영역을 반경만큼 안쪽으로 물려 모든 오프셋이 같은 표본 수를 비교하도록 했다.

| basic | 12/12 | **7/12** |

만족도가 그대로인 것은 예측대로다 — 표본 간격이 이미 1px 이상이라 하한에 걸려 `reach=1,1`로 남는다.

### 12.5 다음 단서 — 만족도 44/60이 여전히 벽에 붙어 있다

`reach=1,1`인데도 벽에 붙는다는 것은 **±1 원본 픽셀보다 크게 두 이미지가 어긋나 있다**는 뜻이다. 셀 크기 문제가 아니라 등록 자체의 문제(D3: 빈 양식은 200dpi 스캔, 업로드는 그 절반 해상도)다.

만족도는 L2 17칸 중 8칸을 갖고 있다.

## 13. 사이클 10 — 평행이동으로는 안 되는 것이 절반이다 (계측, 병합)

### 13.1 반경 4까지 넓혔을 때 어디로 가고 싶어하는지 재봤다

벽에 붙은 만족도 승자 **44개**:

| | 개수 |
|---|---:|
| **`gain ≈ 0` — 4배 넓혀도 같은 자리, 얻는 것이 없다** | **23** |
| `gain` 0.0005~0.02 (미미) | 5 |
| `gain > 0.02` (진짜로 더 가고 싶어함) | 16 |
| `want` 자체가 반경 4에서 또 벽에 붙음 | 8 |

**절반 이상에서 평행이동은 빠진 연산이 아니다.** 하한을 올렸다면 헛수고였다.

그리고 `gain > 0`인 21개의 방향이 **일관된다.**

```
-1,-1  13개
-1, 0   4개
그 외    4개
```

**17/21이 같은 쪽으로 가고 싶어한다** — 셀별 흔들림이 아니라 **계통적 등록 오차**다.

### 13.2 상류를 직접 쟀다 — **그리고 내가 틀렸다 (§14에서 정정)**

```
satisfaction BLANK : 1654x2337 src=template  bounds=L0.0937 R0.9148 T0.0886 B0.9495
satisfaction p1    :  893x1262 src=paper     bounds=L0.0929 R0.9138 T0.0887 B0.9477
satisfaction p2    :  893x1262 src=paper     bounds=L0.0929 R0.9127 T0.0864 B0.9168
satisfaction p3    :  893x1262 src=paper     bounds=L0.0941 R0.9138 T0.0880 B0.9493

cagi BLANK : 1654x2337 src=template  bounds=L0.0931 R0.9788 T0.0813 B0.9495
cagi p1    :  893x1262 src=paper     bounds=L0.0907 R0.9149 T0.0816 B0.9453
cagi p2    :  893x1262 src=paper     bounds=L0.0907 R0.9429 T0.0800 B0.9469
cagi p3    :  893x1262 src=paper     bounds=L0.0907 R0.9149 T0.0808 B0.9485
```

**두 가지가 나왔다.**

**(a) 경계 판정 경로가 다르다.** 빈 양식 자산은 `src=template`, 업로드는 전부 `src=paper`다. 정규화의 기준이 서로 다른 방법으로 정해지므로 계통적 어긋남이 생긴다 — §13.1의 일관된 방향과 부합한다.

**(b) CAGI 빈 양식의 오른쪽 경계가 크게 어긋나 있다.** `R=0.9788` vs 실제 페이지 `0.9149`. 내용 폭이 빈 양식 **0.8857** 대 페이지 **0.8242** — **7.5% 가로 축척 오차**다. 893px 페이지에서 오른쪽 끝 기준 약 **55px**.

CAGI 셀 위치는 격자 검출(`src=grid`)로 정해지므로 이 오차가 좌표를 망치지는 않는다. 그러나 **빈 양식 차감은 이 정규화로 표본을 뜬다** — 즉 CAGI 오른쪽으로 갈수록 **엉뚱한 자리의 인쇄 잉크를 빼고 있다.**

만족도 쪽 전역 경계는 잘 맞는다(폭 0.8211 vs 0.8209, 0.1% 이내). 그러므로 만족도의 계통 어긋남은 축척이 아니라 **경로 차이(a)**에서 오는 1픽셀 수준의 것이다.

### 13.3 소거

| 가설 | 결과 |
|---|---|
| 만족도의 벽 붙음은 탐색 반경 하한(1) 때문이다 | **기각.** 44개 중 23개는 반경 4에서도 같은 자리, `gain=0` |
| 셀별 흔들림이다 | **기각.** `gain>0`인 21개 중 17개가 같은 방향 |

### 13.4 다음 표적

1. **`contentBoundsSource` 불일치** — 빈 양식은 `template`, 업로드는 `paper`. 같은 방법으로 잡아야 한다
2. **CAGI 빈 양식의 7.5% 가로 축척 오차** — 차감이 오른쪽으로 갈수록 엉뚱한 자리를 뺀다

## 14. 사이클 11 — §13.2의 두 가설이 모두 죽었다 (정정)

§13.2에서 내가 낸 두 진단은 **둘 다 틀렸다.** 실제 업로드에서 계측한 결과로 정정한다.

### 14.1 "빈 양식은 `template`, 업로드는 `paper`" — **틀렸다**

실제 스캔 132행 전부가 `bounds=template`이다.

```
72행  bounds=template/0.8858   (cagi)
60행  bounds=template/0.8208   (satisfaction)
```

빈 양식과 업로드가 **같은 경로, 같은 봉투**를 쓴다. 내가 잰 것은 `loadImageAnalysisData`의 출력이었고, 파이프라인은 그 뒤에 `applyTemplateRegistrationFrame`을 적용한다. **점수기가 보는 단계가 아니었다.** 계측기가 엉뚱한 단계를 재고 있던 사례로 세 번째다.

### 14.2 "CAGI 빈 양식의 7.5% 축척 오차가 차감을 망친다" — **틀렸다**

봉투가 두 이미지에 **동일하게** 적용되므로 불일치가 생기지 않는다.

이 가설이 함의하는 예측을 기존 계측기로 직접 시험했다 — 차감이 오른쪽으로 갈수록 엉뚱한 자리를 뜬다면 `fit`이 `atX`와 함께 올라가야 한다.

```
cagi          n=216   corr(atX, fit) = -0.590      ← 예측과 부호가 반대
satisfaction  n=204   corr(atX, fit) = +0.266
```

**반대 부호다.** 기각.

### 14.3 그러나 상수가 오염되어 있다는 것은 사실이다

작업자가 빈 양식의 오른쪽 여백을 열 단위로 프로파일했다.

```
cagi-blank          x=0.91: 9.3% 어두움   x=0.92~0.99: 0.1% 어두움, min=0
satisfaction-blank  x=0.91:10.9% 어두움   x=0.92~0.99: 0.0% 어두움, min=255
```

두 양식 모두 실제 내용은 x≈0.91에서 끝난다(표의 오른쪽 괘선). 그 너머로 만족도 빈 양식은 순백인데, **CAGI 빈 양식에는 x=0.99까지 거의 검은 점이 흩뿌려져 있다.**

그리고 결정적으로, CAGI 템플릿의 `registrationFrame` 상수가 그 얼룩 기준 측정과 **소수 네 자리까지 일치한다.**

```
registrationFrame  x=0.0931  w=0.8857  ->  right 0.9788
얼룩 낀 빈 양식의 paper 검출        L0.0931 R0.9788 W0.8857
```

**상수가 스캔 얼룩에서 유도되었다.** 봉투가 실제 내용보다 6% 넓은 빈 여백을 포함한다. 두 이미지에 똑같이 적용되므로 지금은 무해하지만, `roiTemplates.ts`에 잘못된 값이 박혀 있다는 사실은 기록해둔다(소유 파일이 달라 이번에 손대지 않음).

### 14.4 남은 것

| 사실 | 상태 |
|---|---|
| `gain>0`인 21개 중 17개가 같은 방향(`-1,-1`) | **원인 미상.** 경계·봉투는 아니다 |
| 벽에 붙은 44개 중 23개는 평행이동으로 아무것도 못 얻는다 | **미해결.** 리샘플링/해상도(D3)가 남은 후보 |
| `form-boundary-unverified` 6칸 | **미착수.** 한 페이지의 만족도 전체가 전제 조건에서 막힌다 |

**`form-boundary-unverified` 6칸이 남은 최대 단일 덩어리다.** 이 칸들은 증거가 약해서가 아니라 **전제 조건**에서 막힌다 — 점수는 오히려 좋다(하한 7.8~8.8배, 간격 6.75~10.75배).

## 15. 사이클 12 — 그 6칸은 "나쁜 스캔"이 아니었다 (진단 라벨 정정)

### 15.1 라벨 하나가 6칸을 하루 종일 잘못 읽게 했다

호출부는 두 조건의 **논리곱**을 넘긴다.

```
allowAutoValue = hasUsableFormBounds(satisfactionImage) && Boolean(verifiedGridCells)
```

`analyzeChoiceGroup`은 합쳐진 값만 받는데, 사이클 7에서 그 분기를 `form-boundary-unverified`로 이름 붙였다 — **한쪽 절반을 전체인 것처럼.** 그 결과 6칸이 "페이지가 나빠 위치를 못 잡는다"로 읽혔다.

### 15.2 나쁜 페이지일 수 없다는 것이 스캔 없이 증명된다

- `contentBoundsSource === 'template'`은 `applyTemplateRegistrationFrame`의 **성공 반환에서만** 설정된다. 그러려면 `pageBounds`가 존재하고 `isPlausiblePaperBounds`와 `isPlausibleTemplateContentBounds`가 모두 통과해야 한다
- `hasUsableFormBounds`는 **같은 값에 같은 순수 술어 둘을 다시** 돌린다 — 동의할 수밖에 없다
- 호출부는 **같은 이미지 객체**를 양쪽에 넘긴다

실측 132행이 전부 `bounds=template`이다. 따라서 `hasUsableFormBounds`는 **참을 반환했고**, 거부한 것은 **`verifiedGridCells`** — 격자 검증이다.

### 15.3 수정

`hasUsableFormBounds`가 `resolveFormBoundsStatus`의 한 줄 포장이 되어, **판정과 그 판정을 내린 절을 한 번의 평가에서 함께** 반환한다. 보고되는 이유가 적용된 이유와 어긋날 수 없다 — 이번 라운드를 만든 실패 방식 자체를 구조적으로 막았다.

구성한 도형 **10,025개**를 이전 로직과 대조: **불일치 0.** 실측 `CORRECT 107, WRONG 0` 무변화, 라벨만 `grid-unverified`로 바뀜.

### 15.4 정정된 결론

| 이전 | 정정 |
|---|---|
| 6칸은 스캔이 나빠 정당하게 수기 | **틀림.** 페이지는 멀쩡하다 |
| `hasUsableFormBounds`를 완화해야 한다 | **틀림.** 이 함수는 거부 방향으로 호출된 적이 없다 |
| — | **6칸은 격자 검증에서 막힌다.** `tableGridDetection.ts` 소관 |

**엉뚱한 단계를 잰 사례로 네 번째다.** 이번엔 계측기가 아니라 **계측기가 붙인 이름**이 틀렸다. 그리고 그것을 잡아낸 것도 같은 계측기다.

## 16. 사이클 13 — D3 확정: **해상도 불일치이고, 제거 가능하다**

### 16.1 측정 설계 — 착수 전에 판정표를 고정했다

| 읽힘 | 결론 |
|---|---|
| `edge ≫ fraction`, `bal ≈ 0`, `soft < fit` | 해상도 불일치, **제거 가능** |
| `edge ≫ fraction`, `bal ≈ 0`, `soft ≈ fit` | 선명도 문제이나 3×3 평활로는 안 닿음 |
| `bal ≈ 1` | 잔차가 진짜 잉크다 — **D3 기각** |
| `edge ≈ fraction` | 고르게 퍼짐 — **D3 기각** |
| `sharp`가 양쪽 비슷 | 전제 자체가 거짓 — **D3 뿌리부터 기각** |

**다섯 중 셋이 이 축을 닫는 결론이다.** 부호 규약도 미리 검증했다 — 진짜 표시가 있는 칸은 평활하면 `fit`이 **올라간다**(`0.2227 → 0.2493`). 즉 **잔차가 진짜 잉크인 칸이 거짓 양성을 낼 수 없다.**

### 16.2 실측

| 집단 | n | `fit` | edge share / fraction | `bal` | soft(blank) | soft(both) | 개선 |
|---|---:|---|---|---|---|---|---|
| 전체 | 132 | 0.1296 | **0.577 / 0.215** (2.7배) | **0.211** | 0.1297 | **0.0978** | 125/132 |
| 만족도 벽·`gain≈0` | 23 | 0.0918 | **0.557 / 0.146** (3.8배) | **0.174** | 0.0997 | **0.0658** | **23/23** |
| 만족도 벽·`gain>0` | 21 | 0.1089 | 0.489 / 0.135 (3.6배) | 0.205 | 0.1011 | 0.0767 | 21/21 |
| CAGI | 54 | 0.1492 | 0.717 / 0.317 (2.3배) | 0.134 | 0.1483 | 0.1044 | 54/54 |

**판정표의 첫 줄이다.** 잔차는 인쇄 경계에 몰려 있고(2.3~3.8배), 경계에 대해 **반대칭**이며(`bal` 0.13~0.21), **두 이미지를 공통 선명도로 맞추면 4분의 1이 사라진다.**

### 16.3 예상과 달랐던 것 — "빈 양식이 더 선명하다"가 아니다

```
CAGI    page 0.2931 / blank 0.3171   빈 양식이 더 선명
만족도  page 0.1942 / blank 0.1468   페이지가 더 선명
```

방향이 양식마다 반대다. 그리고 **빈 양식만 평활하면 아무 효과가 없다**(0.1297 vs `fit` 0.1296). 효과는 **둘을 같은 유효 해상도로 맞출 때만** 나온다 — 두 이미지가 애초에 가져본 적 없는 조건이다.

### 16.4 확정된 사실

| # | 사실 |
|---|---|
| D3-1 | 평행이동으로 닿지 않던 잔차는 **해상도 불일치**다 |
| D3-2 | 인쇄 경계에 2.3~3.8배 농축돼 있고 경계에 대해 반대칭이다 — 실체가 아니라 선명도다 |
| D3-3 | 공통 해상도로 맞추면 잔차의 **약 25%**가 사라진다. 132칸 중 125칸, 벽에 붙은 만족도 44칸은 **44/44 전부** |
| D3-4 | 어느 한쪽만 평활하는 것으로는 **아무 효과가 없다** |

### 16.5 다음 라운드의 위험

평활은 **진짜 표시도 흐린다.** 고정 시험에서 표시 있는 칸은 평활 시 `fit`이 올라갔다(정상 — 그 불일치는 실체다). 그러나 점수 경로에 평활을 그대로 넣으면 약한 표시가 눌릴 수 있고, 이는 G5(빈 양식 팽창, `92→64`)와 같은 계열의 실패다.

**따라서 구현은 "전부 흐린다"가 아니라 "두 이미지를 같은 유효 해상도로 맞춘다"여야 한다.** 그리고 합격 조건은 그대로다 — `p3 basic.gender`와 `p3 satisfaction.q01`이 빈칸으로 남고 `WRONG = 0`.

## 17. 사이클 14 — 격자 검증: 행은 고쳤고, 막는 것은 **열**이었다

### 17.1 진단 — 빈 양식만으로 재현된다

템플릿은 각 행의 **선택지 위치**를 단언한다. `deriveCellBoundaries`는 이웃 중심 사이 거리를 반으로 갈라 인쇄 괘선을 **역산**하는데, 이는 이웃 행의 높이가 같을 때만 정확하다. **2줄짜리 문항이 그 전제를 깬다.**

빈 양식에서 이진 표의 실제 인쇄 띠는 **39, 66, 38, 39, 38 px**인데 역산은 **52, 52, 45, 38, 38**을 함의한다. 그래서 표가 **페이지가 기여하기도 전에 8% 허용치의 6.94%를 써버린다.**

행 간격이 불균등한 두 표가 정확히 허용치를 태우는 두 표다.

```
cagi.primary         5.63/8.0    칸별 4.1,5.6,2.3,0.8,0.8,0.2,0.6
satisfaction.binary  6.94/8.0    칸별 5.6,6.9,2.7,0.9,0.4
cagi.late            0.65/8.0
satisfaction.scale   0.67/8.0
```

### 17.2 수정 — 템플릿이 실제로 단언하는 양(띠의 중심)으로 비교

`6.94% → 0.23%`, `5.63% → 1.28%`. 행만 고친다(이 양식들의 열은 균등 간격이라 역산이 정확하다). 중심이 3개 미만이면 기존 비교를 유지한다 — 중심 2개는 간격 1개이고 자기 자신에 대한 비율은 항상 1이라 정보가 없다.

### 17.3 실측 — `CORRECT 107` 무변화. 그런데 실패 페이지를 직접 찔러보니

```
p1  refused=gapCols 17.5>8.0, resCols 9.0>6.0   rowGaps=0.1,0.3,0.1,0.3
p2~p6  (거부 없음)
```

**행은 0.1~0.3%로 내려왔다 — 수정이 실제 실패 페이지에서 작동한다.** 그리고 **막는 것은 열이다**: 열 간격 17.5(한계 8.0), 열 잔차 9.0(한계 6.0).

작업자는 "이 양식들의 열은 균등하므로 고칠 것이 없다"며 열을 의도적으로 건드리지 않았다. 그 판단이 **틀린 것이 아니라, 열에는 다른 문제가 있다.**

### 17.4 병합 판정 — 이득 0인데 병합했다

프로젝트 규칙은 "측정된 이득이 없으면 병합하지 않는다"이다. 이번은 예외로 하고 근거를 남긴다.

1. **실제 실패 페이지에서 작동함이 직접 측정됐다** — 합성이 아니라 그 페이지의 `rowGaps`가 6.94%대에서 0.1~0.3%로 내려왔다
2. **다음 단계의 선행 조건이다** — 열을 고쳐도 행이 다시 막으면 아무것도 안 된다
3. **CAGI까지 넓어지는 변경인데 `WRONG 0`, 정답 수 무변화로 확인됐다**

### 17.5 남은 것 — 열

| 사실 | 값 |
|---|---|
| p1 열 간격 비율 | **17.5%** (한계 8.0) |
| p1 열 잔차 | **9.0%** (한계 6.0) |
| p1 행 간격 | 0.1~0.3% (한계 8.0) |
| p2~p6 | 거부 없음 |

p1의 여섯 칸은 격자가 거부되어 `src=fixed`로 떨어지고, 고정 셀이 실제 셀보다 3.5배 작아(`pitch page=0.44` vs 정상 `1.53`) 인쇄물 위에만 앉는다. 점수가 0.168로 높은 것은 표시가 아니라 **인쇄 잉크**를 재고 있기 때문이다.

## 18. 사이클 15 — 평활은 틀렸다. **부분 표본 정렬**이 답이었다 (`CORRECT 107 → 108`)

### 18.1 명백해 보이던 수정이 측정에서 틀렸다

§16의 데이터를 그대로 읽으면 "비교를 평활한다"가 자연스럽다. 작업자가 그것을 **먼저 만들어 재봤다.**

```
평활 끄기   align=1,0   blank=0.180   fit=0.0012   scr=0.001  -> low
평활 켜기   align=0,0   blank=0.155   fit=0.0264   scr=0.024  -> medium
```

(1,0)에 `fit=0.0012`의 뚜렷한 최적점이 있었는데 **평활된 목적함수가 그것을 못 보고** 22배 나쁜 이웃을 골랐다. 그 결과 **표시가 없는 페이지의 빈 칸이 중간 신뢰도 판독이 됐다.** 평활된 목적함수로 오프셋을 고르고 평활하지 않은 이미지에 적용하면 **선택이 표류한다.**

### 18.2 진짜 원인 — 부분 표본 어긋남

기하학상 빈 양식은 **어디서나** 더 고해상도다(200dpi 대 절반 렌더). 선명도 불일치였다면 빈 양식만 평활해도 사라졌어야 하는데 그것은 효과가 0이었다(§16.3).

양쪽 평활이 제거하던 것은 **부분 표본(sub-sample) 어긋남**이다. 탐색이 **정수 표본 단위로만** 움직였으므로 소수점 오프셋은 **어떤 반경에서도 보이지 않았다.** 그래서 23칸이 4배 반경에서도 아무것도 못 얻었다.

**소수 오프셋을 없애는 연산은 소수 이동이다.** 빈 양식을 이중선형으로 읽고 오프셋을 표본의 분수로 해석한다. 단계 수는 페이지 자신의 표본 간격에서 유도한다.

**목적함수는 그대로이므로 점수 대상은 아무것도 평활되지 않는다.** 약한 표시는 잉크를 전부 유지하고 형태 검사는 원해상도로 본다.

설계된 두 성질: **적합은 나빠질 수 없고**(정수 오프셋이 후보로 남아 상위집합에서 최소화), **비용이 유한하다**(성김→촘촘, 9.3s → 9.7s).

### 18.3 실측

`CORRECT 107 → 108, WRONG 0`. **적대적 칸 두 개 모두 `blank (unmarked, correct)` 유지.**

### 18.4 다음 결정을 위한 숫자 하나

`mscore` — 차감 자체를 공통 대역에서 했다면 점수가 얼마였을지(측정만, 적용 안 함). 고정 시험의 표시 있는 칸에서 **0.1865 대 실제 0.205** — 차감을 맞추면 **진짜 표시를 9% 잃고** 옆 빈 칸에서는 아무것도 못 얻는다. **차감을 건드리자는 제안이 나오면 이 숫자를 먼저 보라. 현재로서는 반대한다.**

## 19. 사이클 16 — p1의 열은 **진짜로 잘못 검출됐다**

### 19.1 판정

작업자의 답은 "첫 번째 모양" — 페이지 1의 열이 실제로 잘못 검출됐고 **거부가 옳다.** 근거는 전부 빈 양식에서 얻었다(스캔 미사용).

- 이진 표는 세 경계에 대해 **정확히 세 개의 세로선**을 검출한다. 하나가 없으면 **대안이 없어 거부가 강제된다.** 양식 통틀어 가장 약한 열 구성이고, 실패한 것이 바로 그 표다
- 행에서 발견한 역산 결함이 열에도 있으나 **너무 작다** — 오른쪽 경계가 실제 공유 테두리보다 12px 안쪽으로 외삽된다. 8% 중 **3.09%**. 행이 태우던 87%와 다르다. 고쳐도 p1은 안 열리므로 고치지 않았다
- 기준 페이지에 어떤 교란을 줘도 17.5%에 못 미친다: 회전 0.6°에서 오히려 **감소**(3.09→2.73), 0.9°에서 선 하나가 빠져도 아핀 재구성이 받아 여전히 통과, 1.0°부터는 품질 게이트가 아니라 **아예 실패**. 답 표시 한 열을 통째로 칠해도 검출 집합 **바이트 동일**. 잡선 7위치에서 최대 4.18

### 19.2 계측이 한 번에 갈랐다

거부가 이제 **어떤 선을 찾았는지**까지 보고한다.

```
p1  cols sel=-1,1,-30   det=-1,63,94
```

기대 경계는 첫 경계 기준 **0, 63, 125**. 검출된 것은 **−1, 63, 94**.

**125 근처에는 아무것도 검출되지 않았다.** 세 번째 경계 — 만족도 세 표가 공유하는 오른쪽 테두리 — 가 p1에서 **검출되지 않았고**, 매처는 대안이 없어 31px 떨어진 것을 집었다.

### 19.3 남은 후보 — 선행 사례가 있다

이 모양은 처음이 아니다. [[15_FAILURE_ELIMINATION_TABLE]] §6: 만족도 척도 표의 기대선 `y=943`이 **검출 목록에서 아예 빠져 있었고**, 감도(`horizontalLineDarkRatio`) 0.3→0.2로 **+10칸**을 회복했다. 선택 실패가 아니라 **검출 감도** 문제였다.

지금은 세로선 쪽에서 같은 모양이다. 종이에는 분명히 있는 공유 테두리가 p1에서만 검출되지 않는다.

**단 한 페이지 표본이므로 감도를 그 페이지에 맞추는 것은 금지다.** `darkThreshold` 180→200이 두 페이지를 살리고 두 페이지를 잃은 전례가 있다([[15_FAILURE_ELIMINATION_TABLE]] §6).

## 20. 사이클 17 — 격자 열 문제 **종결**: 선이 없다

### 20.1 경계별 신호를 재는 계측을 넣었다

거부가 "간격 비율이 한계를 넘었다"까지만 말하고, **선이 흐린 것인지 밀린 것인지 아예 없는 것인지**는 구분하지 못했다. 셋은 서로 다른 답을 요구한다.

### 20.2 실측 — p1, 최소 요구 32%

```
signal(t=200, min=32.0%, radius=7px)
  offset   0   최대 81.7%  @ -1px
  offset  62   최대 81.7%  @ +2px
  offset 125   최대  3.6%  @ -6px
```

**앞의 두 경계는 요구치의 2.5배로 1~2px 안에 정확히 있다. 세 번째는 요구치의 10분의 1이다.**

3.6과 81.7 사이를 가르는 문턱 중 잡음을 받아들이지 않는 것은 없다. **감도 문제가 아니라 선이 없다.**

### 20.3 종결 — 6칸은 정당하게 수기 입력

| 사실 | 값 |
|---|---|
| p1 열 경계 1·2 | 검출 강도 81.7%, 위치 오차 1~2px |
| p1 열 경계 3 (기대 +125) | **검출 강도 3.6%. 그 자리에 선이 없다** |
| 가장 가까운 검출선 | +94 — 31px 안쪽, 탐색 반경(±7px) 밖 |
| 행 | 0.1~0.3% (한계 8.0) — 정상 |
| p2~p6 | 거부 없음 |

행은 정확한데 셋째 열 경계만 31px 안쪽이다. 표 전체가 좁아진 것이라면 둘째 경계도 밀렸어야 하는데 그것은 1px 안에 있다. **p1의 표는 오른쪽만 31px 좁다.**

**격자 검증은 옳게 거부하고 있다.** 위치를 확정할 수 없는 페이지에서 좌표를 읽지 않는 것이 이 게이트의 존재 이유다. 이 6칸(실질 3칸)을 **정당한 수기 입력으로 기록하고 예산을 옮긴다.**

### 20.4 기각 기록

| 가설 | 결과 |
|---|---|
| p1 6칸은 나쁜 스캔이라 폼 경계에서 막힌다 | **기각**(§15). 폼 경계는 통과, 격자가 거부 |
| 격자 거부는 행 역산 결함 때문이다 | **부분.** 행은 고쳐졌으나(6.94%→0.1%) p1은 여전히 거부 |
| 세로선 검출 감도가 낮아 놓친다 | **기각.** 있는 선은 81.7%, 없는 자리는 3.6%. 감도로 가를 수 없다 |
| 이 6칸은 회복 가능하다 | **기각.** 표 자체가 다르다 |
