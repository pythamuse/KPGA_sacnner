# 작업 A — 약한 표시의 마킹 판별 (2026-08-20~)

기본정보·만족도 문항1·CAGI 8·9의 빈칸이 **하나의 뿌리**를 공유한다. 좌표는 검증됐고(`src=grid`) 표시도 실제로 있는데, **신호가 약할 때 인쇄 잔여와 구분하지 못해** 자동 입력이 막힌다.

상위 문서: [Docs/00_PRD.md §10-1](../Docs/00_PRD.md) — 자동 입력률이 제품 성립 조건이다.
선행 스레드: [[MEASUREMENT_RENDER_PARITY_2026-08-19]]

## 1. 배경 — 반드시 먼저 읽을 것

### 1.1 이미 네 번 실패했다

잉크 경로를 건드린 시도가 모두 배포본 해상도에서 악화됐다. **같은 방식을 반복하지 마라.**

| 시도 | 결과 |
|---|---|
| 면적 평균 리샘플링 (상대 대비 없이) | WRONG 1 → 4 |
| 빈 양식 3×3 팽창 차감 | CORRECT 92 → 64 |
| 인셋 대칭화 (양쪽 20%) | 기본정보 13 → **0** |
| 면적 평균 리샘플링 (상대 대비 있이) | scale 1.5에서 WRONG 0 → 4 |

**임계값·인셋·리샘플링 방식 조정은 이 작업의 대상이 아니다.** 판별에 쓰는 **특징(feature) 자체**를 바꾸는 것이 이번 과제다.

### 1.2 현재 판별 방식

두 개의 게이트가 순서대로 걸린다.

1. **`analyzeChoiceGroup`** (`markDensity.ts`) — 빈 양식 차분 후 잉크 총량으로 점수를 매기고, 절대 하한(`HIGH_ABSOLUTE_SIGNAL = 0.021`) + 상대 대비(`HIGH_RELATIVE_CONTRAST = 1.25`) + 형태 게이트(`hasStructuredTemplateMark`)를 통과해야 `high`.
2. **`hasUniqueDirectCheckboxEvidence`** (`detectCheckmarks.ts:649`) — 기본정보 전용. 후보 박스 내부에 잉크가 있는 칸이 **정확히 하나**여야 자동 확정.

### 1.3 확정된 실패 메커니즘

**(a) 기본정보 — 게이트 2가 막는다.** 실사용 6명 전원 보류이며, 다음이 결정적이다.

```
학생 4 성별: 여 21% / 남 4%  (5.25배)  →  보류
학생 6 성별: 여 15% / 남 3%  (5.00배)  →  보류
```

배수가 5배인데도 막힌다. 상대 대비(1.25)는 여유롭게 통과하므로 **`hasUniqueDirectCheckboxEvidence` 하나가 원인**이다. 인쇄된 체크박스 테두리 잔여 때문에 **두 칸 모두 "잉크 있음"**이 되어 모호로 떨어진다.

**(b) 만족도 q01·CAGI 8·9 — 게이트 1이 막는다.** 좌표는 `src=grid`인데 `conf=low`다.

**(c) 약한 표시는 노이즈와 구분되지 않는다.** 한 페이지에서 실측한 값:

```
정상 페이지 정답:  0.067
약한 페이지 정답:  0.011   ← 6배 흐림
같은 칸 인쇄 잔여: 0.020   ← 정답보다 높음
```

절대 하한 0.021은 이 오답을 막지만, 동시에 약한 진짜 표시도 함께 막는다.

## 2. 목표와 합격 기준 (착수 전 확정)

`REAL_SCAN_RENDER_SCALE` 기본값(배포본 래스터)에서 6페이지를 측정한다.

| # | 기준 |
|---|---|
| **필수** | **`WRONG = 0`.** 하나라도 늘면 즉시 기각. 예외 없음 |
| **필수** | 전체 `CORRECT ≥ 102` (현재 기준선) |
| **목표** | 기본정보 자동 입력 증가 (현재 성별 3/5·학년 3/6·학교유형 5/6) |
| **목표** | `satisfaction.q01` 2칸, `cagi.q08`·`cagi.q09` 2칸 회복 |
| 상한 | 넷을 다 회복하면 `CORRECT 112` |

**빈칸과 오답을 맞바꾸지 않는다.** 빈칸은 검수자의 키 입력 한 번이지만, 오답은 사람이 확인한 것처럼 중앙 시스템에 저장된다.

## 3. 방향 제안 (하나를 고르고 이유를 문서에 남길 것)

### 방향 1 — 인쇄 요소와 연결되지 않은 성분으로 판정 (권장)

지금은 "칸 안에 잉크가 있는가"를 본다. 대신 **"빈 양식에 잉크가 없던 자리에 새 성분이 있는가"**를 본다.

- 빈 양식 셀을 이진화해 인쇄 마스크를 만든다
- 실제 셀의 잉크 중 **인쇄 마스크에 닿지 않는 연결 성분**만 남긴다
- 그 성분의 크기·개수로 판정한다

손으로 그린 동그라미·체크는 인쇄 원/박스를 **가로지르거나 벗어나므로** 반드시 마스크 밖 성분을 남긴다. 반면 정렬 오차로 생기는 테두리 잔여는 인쇄 획에 **붙어 있다**.

### 방향 2 — 잉크 무게중심의 편향

인쇄 요소는 셀 중앙에 대칭으로 놓인다. 손 표시는 한쪽으로 치우친다. 차분 잉크의 무게중심이 셀 중심에서 얼마나 벗어났는지를 특징으로 쓴다.

### 방향 3 — 게이트 2를 완화하되 근거를 강화

`hasUniqueDirectCheckboxEvidence`가 "잉크 있는 칸 == 1"을 요구하는 것을 "**방향 1의 마스크 밖 성분이 있는 칸 == 1**"로 바꾼다. 게이트를 없애는 것이 아니라 판정 근거를 교체하는 것이다.

## 4. 제약 (위반 시 되돌림)

1. **`WRONG`을 늘리지 마라.** 유일한 절대 조건이다.
2. **필드명·후보 인덱스로 분기하지 마라.** `field === 'basic.gender'` 같은 예외는 표본에 코드를 맞추는 것이며 금지다. 수정은 판별 방식의 일반적 성질이어야 한다.
3. **소유 파일**: `src/lib/recognition/basicCheckboxDetection.ts`, `src/lib/recognition/detectCheckmarks.ts`, `src/lib/recognition/markDensity.ts`. **이 셋 외의 소스 파일을 수정하지 마라** — 다른 작업이 `src/lib/recognition/ocrTextLines.ts`에서 동시에 진행 중이다.
4. **`tests/real-scan-measure.test.ts`, `local-scans/`, `templates/`, `src/lib/recognition/assets/`를 수정하지 마라.** 계측기와 정답표를 고쳐 숫자를 맞추는 것은 금지다.
5. **병렬 판별 경로를 추가하지 마라.** 기존 경로를 고치되, 두 번째 판별기를 나란히 두면 어느 쪽이 판정했는지 알 수 없게 된다.
6. `npm test`·`npm run build` 통과. 버전 마커는 갱신하지 마라(병합은 지휘자가 한다).
