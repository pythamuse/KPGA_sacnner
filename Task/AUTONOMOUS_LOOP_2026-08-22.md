## 사이클 1 — 만족도 콘텐츠 상자가 페이지마다 다르다

### 1.1 계측

19페이지 × 2폼의 페이지 기하와 표별 등록 상태를 노드에서 뽑고, 브라우저 결과와 대조했다.

먼저 상위 가설부터 정리했다 ([[FIELD_TEST_2026-08-21]] §18): 페이지 위치는 `r=-0.550`으로 주범이 아니고, **좌표 붕괴(+0.590)와 2순위 상승(+0.614)** 이 더 잘 설명한다. 둘은 서로 `+0.631`로 붙어 있어 **표 등록 정확도** 하나의 두 얼굴로 보인다.

그 다음 페이지 기하를 봤다. 콘텐츠 상자 폭·좌변·높이·기울기는 브라우저 실패와 **상관이 약하다**(|r| ≤ 0.47). 그런데 표를 하나로 좁히자 완전히 갈렸다.

```
satisfaction.scale   verified   콘텐츠 폭  732 733 733 736 736 736 736 737 761  (11페이지)
                     candidate  콘텐츠 폭  778 790 790 797 804 807 808 812      (8페이지)
                                            ↑ 761과 778 사이에 빈 구간
```

**연속적 흔들림이 아니라 이봉분포다.**

### 1.2 빈 양식이 어느 쪽이 맞는지 결정한다

```
satisfaction-blank.png   1654x2337,  콘텐츠 폭 1358  →  893px 환산 733.1
```

**정상군 732~737이 기준과 일치하고, 이상군 778~812가 최대 11% 넓다.** 넓은 쪽은 상자가 페이지 전폭에 가깝게 벌어진다(예: p13 L=59 W=812 → 59~871 / 893). 스캔 가장자리 잡음을 물고 있다는 뜻이다.

콘텐츠 상자는 **정규화 좌표계의 분모**다. 11% 넓어지면 모든 ROI가 그만큼 밀리고, 그래서 표 등록이 검증을 통과하지 못한다.

### 1.3 원인 추정

`loadImageAnalysisData` → `detectPaperContentBounds(image, pageBounds)`가 19페이지 중 8페이지에서 **인쇄 영역이 아니라 스캔 가장자리까지** 포함한다. 19페이지 전부 `src=paper`이므로 프레임/다크 폴백이 아니라 이 함수 자체다.

CAGI 쪽은 폭으로 갈리지 않는다(겹침) — 사이클 1의 범위는 만족도로 한정한다.

### 1.4 계획

- Codex에 위임: `detectPaperContentBounds`가 페이지마다 일관된 인쇄 영역을 내도록 한다
- **빈 양식이 같은 함수를 통과한다.** `cagi-blank` 1465, `satisfaction-blank` 1358이 흔들리면 템플릿 좌표계 전체가 어긋난다 — 불변이어야 한다
- 임계값을 템플릿 폭에 맞춰 깎는 것은 금지. 원인(가장자리 잡음 포함)을 제거해야 한다

### 1.5 위임 결과 (Codex, 5분)

원인: `detectDarkPixelBounds`가 **인쇄선의 반복성을 보지 않고 어두운 픽셀 하나까지 외곽점으로 채택**했다. JPEG 스캔의 급지 그림자·가장자리 잡음이 좌우 경계를 벌렸다.

수정: 가로 외곽을 **시트 높이의 0.5% 이상 반복되는 어두운 열**에서만 잡는다. 이 경로는 **중간 명암값이 있는(=압축된) 이미지에만** 적용하고, 1비트 자산은 기존 경로를 유지한다. 템플릿 폭·페이지 번호·사후 클램프 없음.

### 1.7 ★ 판정이 막혔다 — 그리고 그게 다음 작업이 됐다

규칙 2대로 브랜치를 밀어 프리뷰 배포를 받았다. 배포는 성공했으나 **URL이 Vercel SSO로 보호돼 있다.** 로그인은 할 수 없다(자격증명 입력 금지).

프로덕션에 올려 재면 되지만 그건 규칙 2를 버리는 것이다. 그래서 **배포 자체를 없애는 쪽**을 봤다.

`uploadStore.ts`의 `usesLocalMemoryStore()`는 `!process.env.VERCEL`이므로 **로컬에서는 이미 메모리 스토어를 쓰게 되어 있다.** 그런데 로컬 dev에서 `/api/recognize`가 `409 UPLOAD_INTEGRITY_ERROR`를 낸다 — 업로드는 200인데 읽기가 빈다.

의심: `LOCAL_MEMORY_UPLOADS`가 모듈 수준 `Map`이라 **Next.js dev에서 두 라우트가 인스턴스를 공유하지 못한다.**

이것이 풀리면 **배포 없이 매 사이클을 로컬에서 측정**할 수 있다. 사이클 1b로 위임했다.
