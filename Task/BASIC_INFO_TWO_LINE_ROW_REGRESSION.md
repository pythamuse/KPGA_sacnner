또한 CAGI 응답 열 x가 검출값 `[0.6898, 0.7468, 0.8092, 0.8805]`로, 내가 빈 양식에서 독립 측정한 `[0.690, 0.747, 0.809, 0.877]`과 일치한다. 참고로 템플릿의 `cagiOptionXs = [0.742, 0.805, 0.871, 0.944]`는 약 0.05 어긋나 있는데, 격자 검출이 이를 올바르게 덮어쓰고 있다(검출 실패 시 폴백은 여전히 부정확하다는 뜻이므로 별도 과제로 남김).

## 2. 회귀: 2줄짜리 기본정보 항목이 한 줄로 뭉개졌다

`학교유형`과 `학년`은 양식에서 **두 줄에 걸쳐 인쇄**돼 있다:

```
학교유형 | 초등학교□(4학년부터 해당)  중학교□        ← 1줄
         | 고등학교□        학교 외 기관□          ← 2줄
학  년   | 1학년□  2학년□  3학년□                  ← 1줄
         | 4학년□  5학년□  6학년□                  ← 2줄
```

그런데 행 앵커링이 그룹 전체에 **단일 y**를 적용해, 두 줄이 하나로 붕괴됐다:

| 항목 | 템플릿 y | 검출 y | 검출 x |
|---|---|---|---|
| elementary | 0.174 | **0.1787** | 0.3474 |
| middle | 0.174 | 0.1787 | 0.5246 |
| **high** | **0.193** | **0.1787** | **0.3474** ← elementary와 y·x 모두 동일 |
| outside | 0.174 | 0.1787 | 0.6345 |
| grade1 / **grade4** | 0.208 / **0.228** | **0.2186 / 0.2186** | **0.257 / 0.257** ← 동일 |
| grade2 / grade5 | 0.208 / 0.228 | 0.2186 / 0.2186 | 0.402 / 0.402 ← 동일 |
| grade3 / grade6 | 0.208 / 0.228 | 0.2186 / 0.2186 | 0.5471 / 0.5471 ← 동일 |

**즉 `초등학교`와 `고등학교`, `1학년`과 `4학년`, `2학년`과 `5학년`, `3학년`과 `6학년`이 각각 문자 그대로 같은 픽셀을 읽는다.** 두 후보의 점수가 항상 같아지므로 원리적으로 구분이 불가능하다.

## 3. 왜 테스트가 못 잡았나 (q01 때와 같은 구조)

신규 `tests/blank-form-detection.test.ts`는 그룹의 **합집합 중심 y 하나**를 기준값과 대조한다. 두 줄이 한 줄로 붕괴돼도 합집합 중심은 여전히 기준값 근처이므로 **통과한다.** 후보끼리 좌표가 중복되는지는 아무도 확인하지 않는다.

[[REMAINING_FIELD_FIXES_AFTER_BLANK_FORM]] §2에서 지적한 것과 정확히 같은 함정이다 — 수치 허용오차는 "정밀하지만 의미가 틀린" 상태를 표현하지 못한다.

## 4. 실제 피해 범위 (과장하지 않기)

두 후보 점수가 **동일**해지면 `analyzeChoiceGroup`의 `gap`이 0이 되어 medium 임계값(0.025)에 미달하므로, **잘못된 값이 자동 확정되지는 않는다 — 항상 낮은 신뢰도로 남는다.** 즉 "위험한 오확정"이 아니라 "이 두 필드는 영원히 자동 인식 불가"에 가깝다. 안전 쪽으로 실패하고는 있지만, 배지가 `격자 검출`로 표시되어 **사용자에게는 정상 동작처럼 보인다**는 점이 문제다.

## 5. 작업지시서 (Codex, Luna-Max)

1. **그룹 내 후보별로 서로 다른 행을 허용하도록 수정한다.** 기본정보 행 앵커링이 그룹 전체에 단일 y를 적용하는 대신, 각 후보의 **템플릿 y가 어느 인쇄 줄에 속하는지**를 보고 해당 줄의 검출 y를 적용해야 한다. 구현 방향 예시(어느 쪽이든 무방):
   - 템플릿 y 값을 클러스터링해 줄 수를 구하고(학교유형·학년은 2줄), 검출된 행 경계와 순서대로 대응시킨다.
   - 또는 후보를 템플릿 y 기준으로 그룹핑한 뒤 각 서브그룹에 개별적으로 행 보정을 적용한다.
2. **`basic.gender`는 1줄이므로 현재 동작이 맞다** — 건드리지 말 것.
3. **회귀 테스트를 강화한다(필수).** `tests/blank-form-detection.test.ts`에 **한 그룹 안의 두 후보가 동일하거나 거의 동일한 사각형을 갖지 못하도록** 하는 검사를 추가한다. 예: 같은 그룹 내 임의의 두 후보 사각형의 중심 거리가 최소값(예: 셀 폭·높이의 절반) 이상일 것. 이 검사는 **모든 그룹**(CAGI·만족도 포함)에 적용해, 앞으로 어떤 필드에서든 같은 붕괴가 재발하면 즉시 잡히게 한다.
4. 후보별 검출 y가 템플릿의 줄 구분을 보존하는지도 확인한다(예: `high`의 검출 y가 `elementary`보다 확실히 아래일 것, `grade4~6`이 `grade1~3`보다 아래일 것).
5. 자동 확정 안전장치(`allowAutoValue`, `requiresHighVisualConfidence`)는 **이번에도 변경 금지**.
6. `npm test`, `npm run build` 통과, `git status`에 `templates/` 변경 없음 확인, 버전 마커 갱신(현재 `v2026-08-10.5`) 후 커밋·푸시.

보고 시: (a) 파일별 변경, (b) 테스트/빌드 결과, (c) **`학교유형` 4개·`학년` 6개 각각의 검출 x/y 목록** — 두 줄이 실제로 분리됐는지 눈으로 확인 가능하게, (d) 3번 중복 검사가 실제로 실패를 잡을 수 있는지(일부러 붕괴시킨 입력에서 실패하는지) 확인 결과.
