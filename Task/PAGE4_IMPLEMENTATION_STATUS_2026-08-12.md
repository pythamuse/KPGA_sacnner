# 페이지 4 골든 케이스 구현 상태 (2026-08-12)

## 목적

이 문서는 `PAGE4_GOLDEN_CASE_ROOT_CAUSE_AND_REMEDIATION_PLAN_2026-08-12.md`의 사실, 가설, 구현 범위를 분리해 기록한다. 자동 인식 결과와 검수 단계에서 사람이 입력한 값을 혼동하지 않으며, 검증되지 않은 좌표를 자동 입력으로 승격하지 않는 것이 이번 변경의 기준이다.

## 이번에 구현한 범위

### P0. 필드별 판정 이력

- 모든 인식 필드에 `auto`, `manual`, `unresolved` 출처를 기록한다.
- 검수 화면에서 값을 변경하면 해당 필드는 `manual`로 기록하고 수기 수정 시각을 저장한다.
- 자동 인식이 보류된 경우에는 보류 사유와 사용한 좌표 판정 근거를 함께 보존한다.
- API 응답도 이 출처와 판정 근거를 유지해 화면 전환 과정에서 자동값과 수기값이 섞이지 않게 한다.

### P3. 연령 OCR 실패 상태

- 연령 OCR은 단순한 빈값 대신 `invalid_input`, `worker_pending`, `deadline_exhausted`, `invalid_crop`, `timeout_or_error`, `parse_or_confidence_rejected` 상태를 남긴다.
- 학생별 시간 예산이 이미 끝난 경우에는 워커 준비 상태와 혼동하지 않고 `deadline_exhausted`로 기록한다.
- OCR 값은 템플릿 좌표 영역, 숫자 파싱, 신뢰도 검증을 모두 통과했을 때만 `auto`로 기록한다.

### P5. 파일명 기반 예외 제거

- 파일명에 의존하던 보정 또는 판정 예외를 제거했다.
- 같은 입력이면 파일명과 무관하게 같은 검증 경로를 사용한다.

## 이번에 의도적으로 하지 않은 범위

- 기본정보 전용 정합 등록기(P1)는 아직 구현하지 않았다.
- 만족도 문항 7-10 전용 정합 등록기(P2)는 아직 구현하지 않았다.
- 따라서 이 영역은 현재 자동 입력하지 않고, 검수 화면에서 보류 사유를 보여 준다.
- 응답 빈도 기반 사전확률은 후보 순위 또는 검수 우선순위에만 사용할 수 있으며, 자동 저장 근거로 사용하지 않았다.
- 기존 신뢰도 임계값을 낮추거나, 격자 검증 실패를 통과시키는 변경은 하지 않았다.

## 테스트로 확인된 사실과 해석

### 확인된 사실

- 골든 PDF의 페이지마다 미세한 스캔 차이가 있으며, 기본정보와 일부 만족도 영역에서 행 또는 열 격자 독립 검증이 실패한다.
- 실패한 영역은 `Grid candidate rejected` 또는 `insufficient_lines` 진단을 남기며 자동 입력되지 않는다.
- 검수 화면에 보이는 연령, 성별, 학교유형, 학년 값 중 사용자가 다음 학생으로 넘어가기 위해 직접 입력한 값은 자동 인식 성공의 증거가 아니다.
- CAGI 1-7과 일부 만족도 문항은 기존 검증을 통과한 경우에만 자동값으로 남는다. CAGI 8-9 및 만족도 일부는 보류되는 사례가 반복된다.

### 현재 해석

- 주된 문제는 마크 판독 이전의 좌표 정합 신뢰도 부족이다.
- OCR 또는 사전확률만 강화해도 정합되지 않은 좌표에서 잘못된 답을 자동 저장하는 위험은 해결되지 않는다.
- 다음 기능 개발은 실패한 필드군별 전용 등록기를 만들고, 골든 PDF 전체에서 등록 오차와 답안 판독을 분리해 측정하는 순서여야 한다.

## 다음 테스트에서 확인할 항목

1. 검수에서 수기로 수정한 필드에 `수기 수정` 출처와 수정 시각이 남는지 확인한다.
2. 자동 인식이 보류된 필드가 자동값처럼 저장되지 않는지 확인한다.
3. 연령 OCR이 빈값일 때 카드의 판정 근거가 `deadline_exhausted` 등 실제 종료 사유를 보여 주는지 확인한다.
4. 기존 자동 인식 성공 영역(CAGI 1-7 및 검증된 만족도 문항)의 자동 입력이 회귀하지 않았는지 확인한다.
5. P1/P2 구현 전에는 기본정보 및 만족도 7-10의 보류 결과를 정확도 향상으로 해석하지 않는다.
