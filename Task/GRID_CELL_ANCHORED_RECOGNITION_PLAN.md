# 표 셀 앵커 기반 응답 인식 구현 계획

## 배경

실제 촬영 샘플에서 문서 양식 분류와 업로드 흐름은 통과했지만, 검수 화면의 선택지 ROI가 문항 셀과 어긋나 대부분 낮은 신뢰도로 표시됐다. 기존 구현은 표의 가로선을 찾아 문항 행 높이만 보정하고 선택지 열 X좌표는 고정 템플릿을 사용한다. 사진의 원근, 여백, 미세한 회전 때문에 열 위치가 달라지면 체크 표시와 후보 셀이 분리된다.

## 목표

고정된 CAGI·만족도조사 양식에서 표의 가로선과 세로선을 함께 검출하고, 교차점으로 만들어진 셀을 문항 행과 선택지 열에 직접 연결한다. 답안 매칭은 질문 본문 OCR이 아니라 `표 블록 → 행 → 열 → 셀 중앙의 체크 흔적` 순서로 수행한다.

## 1차 구현 범위

1. 각 응답 표 블록의 예상 위치를 양식 템플릿에서 계산한다.
2. 예상 위치 근처에서 가로선과 세로선의 긴 어두운 픽셀 구간을 검출하고, 템플릿의 행·열 개수 및 간격과 일치하는 선 집합만 채택한다.
3. 인접한 가로선·세로선 사이의 실제 셀 중앙 영역을 선택지 ROI로 사용한다.
4. 격자 검출에 성공한 문항은 실제 셀 범위로 채점하고, 검수 화면의 crop도 같은 범위를 사용한다.
5. 격자를 신뢰할 수 없으면 기존 행 보정 및 낮은 신뢰도 검수 흐름으로 폴백한다. 자동값을 강제로 확정하지 않는다.

## 양식별 표 블록

| 양식 | 문항 | 행 수 | 선택지 열 수 |
|---|---:|---:|---:|
| CAGI | 1~7 | 7 | 4 |
| CAGI | 8~9 | 2 | 4 |
| 만족도조사 | 1 | 1 | 4 |
| 만족도조사 | 2~6 | 5 | 2 |
| 만족도조사 | 7~10 | 4 | 5 |

## 점수와 안전장치

- 셀 테두리와 인쇄된 동그라미는 모든 선택지에 공통으로 존재하므로 절대 어두운 픽셀 비율만 사용하지 않는다. 같은 행의 최고 후보와 차순위 후보의 밀도 차이를 함께 본다.
- 격자 앵커가 있는 경우에만 셀 중심의 상대 점수 기준을 적용한다.
- 문서 외곽 프레임 또는 표선 패턴이 불확실하면 자동 선택을 하지 않고 검수 화면에서 사용자가 결정한다.

## OCR 및 오픈소스 모델 적용 원칙

- 답안 셀 매칭의 1차 해법은 모델이 아닌 표선·교차점 기반 기하 보정이다. 고정 양식에서는 더 빠르고 설명 가능하다.
- OCR은 제목·기본정보·표 블록 검증 같은 보조 앵커로 제한한다. 현재 Tesseract 경로는 요청 지연 방지를 위해 예산이 제한돼 있다.
- 후속 벤치마크 후보는 PaddleOCR의 한국어 인식 모델과 wired table structure 모델(SLANeXt)이다. 무거운 Python/모델 추론은 Vercel 함수에 직접 넣지 않고 별도 서비스에서 정확도·지연을 측정한 뒤 채택한다.

## 검증 계획

1. 합성 표에서 행·열선으로 선택지 셀 ROI가 생성되는지 단위 테스트한다.
2. 고정 템플릿 좌표가 틀려도 실제 셀 ROI에서 더 진한 체크 후보를 선택하는지 검증한다.
3. 기존 회귀 테스트와 프로덕션 빌드를 통과시킨다.
4. 운영 배포 후 동일 샘플로 CAGI 9개와 만족도 10개의 crop이 각 문항 행과 선택지 열을 포함하는지 확인한다.

## 후속 단계

- 실제 샘플 30쌍 이상으로 표 블록별 검출 성공률, 정답률, 처리 시간을 기록한다.
- 표선이 흐리거나 양식이 달라지는 입력에 대해서만 PaddleOCR SLANeXt_wired 또는 Table Transformer를 별도 서비스에서 비교한다.
- 손글씨 성명·연령은 별도 OCR 정확도 기준을 세운 뒤 선택적으로 자동화한다.
