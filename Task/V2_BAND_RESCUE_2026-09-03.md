# V2 선 대응 — 기대 행 밴드 + 밴드 안 되찾기 (2026-09-03)

**표적**: 브라우저 래스터에서 척도표의 2·3번째 행 경계(942·975px)가 문턱 0.2 아래로 떨어져 V2가 실패하는 사례
([FIELD_TEST](FIELD_TEST_2026-08-21.md) §34.3–§34.5: p4·p5·p10 척도표, p9 빈도표). 노드 렌더는 같은 선을 0.2에서 잡는다.
**작성**: 오퍼스 서브에이전트(코덱스 중단 중, CLAUDE.md §0), 워크트리 `wt-band`, 브랜치 `codex-v2-band`, 커밋 `0a64eb6`(기준 `ad5f959`).
**판정**: 메인 에이전트, 실제 자료로만. 서브에이전트는 학생 파일을 열지 않았고 합성 시험만 돌렸다.

## 1. 구현 (플래그 `GRID_BAND_V2=1`, 행에만 적용)

1. 밴드 = 0.75 × 최소 기대 행 간격. 검출 선 중 어느 기대 행의 밴드 안에 드는 것만 V2 후보(`outOfBand=<n>`으로 제외 수 기록).
2. 밴드 후보로 V2 → 실패하면 전체 후보로 한 번(현재 동작) → 그래도 실패하면 **되찾기**: 같은 탐색 창(표의 열 폭)에서
   `max(0.12, ratio×0.6)`으로 재검출한 선 중 **아무 선도 안 들어온 기대 행의 밴드 안** 것만 취해(1px 중복 제거) 밴드 후보 ∪ 되찾은 선으로
   V2를 다시 돈다. V2 규칙(배율·잔차·절대 위치·결손 ≤ floor(E/3))은 그대로. `rescued=[idx@ratio]` 기록.
3. 플래그 off는 기존 `matchTemplateLinePattern(horizontalLines, expectedY)` 한 번 호출과 동일 경로.

주문과 다른 점(서브에이전트 보고): 되찾기 재검출을 결손 밴드마다가 아니라 탐색 창 전체에 한 번 돌린 뒤 결손 밴드로 거른다(선 묶음이
밴드 경계에서 갈라지는 것을 피함, §34.4 계측과 같은 방식); 재검출 x 범위는 페이지 폭이 아니라 표의 열 폭(주 검출과 같은 비율 의미).
